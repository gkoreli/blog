## Original proposal — historical, superseded where it conflicts above

Around 2026-09-17, when two full weeks of evidence-era rows exist, compare the first-party Browsers filter with Cloudflare Web Analytics (bots excluded) over the same 7-day and 14-day UTC windows. Cloudflare Web Analytics is script-based: it counts only browsers that ran JavaScript on the page, so it is the one independent measurement available and the check the stats page's honesty rests on (ADR-0016.3 tenet 5).

Method: record four numbers per window: D1 Browsers page views and daily clients (`/api/stats?traffic=browser&range=7d`), Cloudflare Web Analytics page views and visits (dash.cloudflare.com, Web Analytics, gkoreli.com, "Exclude bots" on). Compare views with views and clients with visits; the units differ (an HMAC daily client is not a visit), so report both ratios and say which is which. Baseline before the fix, 7 days to 2026-09-02: D1 1,209 views / 578 clients against 113 views / 52 visits, a ratio of about 11 to 1, which is what exposed the browser-UA scrapers (artifact 02). Expected after the fix: the evidence-era Browsers rows (reason `navigation-shaped`) should sit within roughly 1 to 2 times the script count, because the script also misses readers with JavaScript off or blocked. Decision rule: if Browsers still exceed the script count by more than about three times, something the evidence cannot see is still counted, and the next ADR considers a client-side confirmation signal; if the ratio is within range, state it on the stats page methodology as the external check. Either way, record the numbers in research artifact 02 as a dated section. This is continuation evidence for the article, not a reason to delay it. Nothing to build until the date.
