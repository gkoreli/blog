Decisions:
- Replaced beacon ingestion with observePageResponse, which composes response eligibility, request metadata, AI-first traffic classification, daily HMAC identity, and the page_observations repository; eligible writes are scheduled through ExecutionContext.waitUntil.
- Kept policies as pure functions and composition rather than classes. The only persisted identity is a 128-bit lowercase HMAC result derived from a master secret, UTC-date daily key, and length-prefixed host/date/IP/User-Agent fields. Raw IP and User-Agent are transient only.
- Classified traffic as browser, bot, or ai; named AI rules run before bot rules, and unmatched generic automation has a null agent name.
- Preserved page_views exclusively as a legacy table while creating a separately constrained page_observations table and indexes in both fresh schema and migration. Active analytics reads and writes use only page_observations.
- Defined range=7d|30d|90d|all, traffic=browser|bot|ai|all, and optional exact path query semantics. All public SQL predicates use raw half-open UTC timestamp bounds and is_owner = 0. D1 batch queries return cards and all dimensions from one snapshot.
- Defined camelCase StatsResponse rows, exact UTC calendar ranges, hourly 7d buckets, daily longer/all buckets, and complete zero-filled time domains through the current UTC hour/date.
- Added dependency-free Node test contracts compiled with the package's existing TypeScript toolchain.

Risks:
- UA classification remains heuristic and sender-asserted; named matches are not verified identities.
- waitUntil persistence is best effort, so a successfully served response can be absent after a D1 failure.
- The all-time query returns complete path aggregates and may grow in cost as the new dataset grows.
- Production deployment requires ANALYTICS_HASH_KEY before the first observed response.
