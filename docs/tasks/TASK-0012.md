# TASK-0003 — End-to-end analytics data semantics audit

**Scope:** read-only trace of `packages/analytics` and the stats/API/dashboard paths in `packages/blog`.

**Source baseline:** repository revision `c85a629d1074db54d5f9e5c171abbd798be85945`.

## Compressed conclusion

**Observation:** the stored fact is not an original page request. Static HTML bypasses the Worker; the event is a best-effort row created by a later browser-side `POST /api/event`. Non-JavaScript crawlers that fetch an article never enter D1. The public surface then calls rows “Views,” daily rotating pseudonymous identities “Visitors,” and all `visitor_type = 2` beacon rows “AI Reads” / `ai_fetches`.

**Inference:** the dashboard is internally useful as a rough count of successfully written client events, but several labels imply stronger or differently bounded facts than the implementation provides. The highest-impact semantic risks are: (1) Bot/AI totals include only beacon-capable matching clients, not bot/AI traffic or article fetches; (2) period “Visitors” are distinct rotating IP+UA hashes, not unique people; (3) `7d/30d/90d` include N+1 local calendar dates; (4) timezone grouping uses one fixed current offset across historical data while identity rotates at UTC midnight; (5) owner exclusion and the AI total use inconsistent populations; and (6) the privacy copy omits fields actually persisted.

This is diagnostic input only. It makes no ADR or repair recommendation.

## Compact data-flow diagram

```text
GET /some-page
  └─ Cloudflare static asset path (Worker-first is only /api/*)
      └─ generated pageShell runs inline browser script unless
         localStorage.analytics_ignore === "true"
          └─ POST /api/event, text/plain JSON
             { path: location.pathname, referrer: document.referrer }
              ├─ sanitize client-supplied path; clean referrer
              ├─ classify POST User-Agent -> Human(0) | Bot(1) | AI(2)
              ├─ classify device from POST User-Agent
              ├─ read POST cf-connecting-ip + request.cf geo
              ├─ visitor_hash = first 64 bits of SHA-256(
              │    UTC-date + IP + UA)
              ├─ is_owner = exact IP membership in OWNER_IPS
              └─ INSERT page_views (...); created_at = D1 datetime('now')
                  └─ waitUntil(write); HTTP 204 can precede/fail after response

GET /api/stats?days=N&tz=getTimezoneOffset()&visitor=...
  ├─ fixed-offset local DATE(created_at); lower bound only, inclusive
  ├─ one visitor population predicate + optional path LIKE 'prefix%'
  ├─ D1 batch: totals/path/country/time/referrer/AI/device
  └─ JSON, Cache-Control: public, max-age=300
      └─ /stats browser client
          ├─ cards: Views | Visitors | AI Reads
          ├─ chart called "Daily" even when N <= 7 returns hourly buckets
          └─ top pages/referrers/countries + device percentages
```

**Evidence:** static assets bypass the Worker except `/api/*` in [`wrangler.jsonc:21-28`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/wrangler.jsonc#L21-L28); the beacon is emitted by `pageShell` in [`packages/blog/src/templates/page.ts:155-157`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/blog/src/templates/page.ts#L155-L157); routing is in `worker.fetch` at [`packages/blog/src/worker/index.ts:28-39`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/blog/src/worker/index.ts#L28-L39); event construction and asynchronous write are in `handleEvent` at [`packages/analytics/src/index.ts:43-90`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/analytics/src/index.ts#L43-L90).

## Explicit UTC-hash versus local-bucket trace

Take a viewer at UTC−08:00 (`getTimezoneOffset() = 480`) and one unchanged IP+UA:

1. **One displayed local day spans two salts.** Events at `2026-01-01 23:59Z` and `2026-01-02 00:01Z` both display on local `2026-01-01`, but `dailySalt()` produces `2026-01-01` and `2026-01-02`. The hashes differ. `by_day[2026-01-01].visitors` counts the same client twice; `totals.visitors` also counts two hashes.
2. **One UTC hash spans two displayed local dates.** Events at `2026-01-02 07:59Z` and `2026-01-02 08:01Z` use the same `2026-01-02` salt, but display on local `2026-01-01` and `2026-01-02`. Each `by_day` row reports one visitor, so summing the two rows gives two, while `totals.visitors` across both dates is one.
3. For `days <= 7`, `by_day` is hourly. Even away from UTC midnight, the same hash appearing in two hours is distinct once in each hourly row but once in period totals.

**Consequence:** `totals.visitors` and the sum of `by_day.visitors` have no stable additive relationship outside the exact UTC/daily case, and neither can truthfully mean unique people. The narrow, source-true description is “distinct daily-rotating IP+UA hash values within this query/bucket,” with known collapse/split behavior. Evidence: UTC salt in [`hash.ts:21-23`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/analytics/src/hash.ts#L21-L23); fixed-offset local bucketing and distinct counts in [`stats.ts:53-79`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/analytics/src/stats.ts#L53-L79).

## Privacy and persistence observations

1. **Observation:** the public privacy page says analytics records “path and referrer only.” **Evidence:** the D1 insert also persists country, city, continent, a rotating IP+UA hash, visitor type, device type, owner flag, and timestamp: [`privacy.ts:11-13`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/blog/src/pages/privacy.ts#L11-L13) versus [`db.ts:10-35`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/analytics/src/db.ts#L10-L35) and [`schema.sql:4-16`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/analytics/schema.sql#L4-L16).

## Schema and API contract assumptions

- `created_at` is D1 insertion time, not browser navigation time; event body/insert carry no client timestamp.
- API `days`: absent means 30; invalid, empty, negative, and zero become all-time; values over 365 clamp; fractions are accepted. Dashboard URL parsing can retain `NaN`, negatives, or 999 while server answers a different normalized period. [`index.ts:101-111`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/analytics/src/index.ts#L101-L111), [`client/stats.ts:61-73`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/blog/src/client/stats.ts#L61-L73).
- API JSON has a hand-copied client interface, not a shared runtime/schema contract: [`analytics/stats.ts:18-26`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/analytics/src/stats.ts#L18-L26) versus [`blog/client/stats.ts:10-18`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/blog/src/client/stats.ts#L10-L18).
- `OWNER_IPS` is optional and absent from checked-in Wrangler variables/secrets; deployment-dashboard configuration is not visible. Client opt-out depends on manually set localStorage and suppresses the row. [`db.ts:3-8`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/packages/analytics/src/db.ts#L3-L8), [`wrangler.jsonc:12-14,30-35`](https://github.com/gkoreli/blog/blob/c85a629d1074db54d5f9e5c171abbd798be85945/wrangler.jsonc#L12-L14).

## Open questions

1. Is `OWNER_IPS` configured outside the repository, and is `localStorage.analytics_ignore` set on every author device/browser?
2. What is the deployed D1 schema and distribution of legacy/null/defaulted rows?
3. Is “Visitors” intended to mean daily unique client identities, period-unique people, or visitor-days? Current data can only report distinct rotating hash values, with UTC/local split/collapse behavior.
4. Should `7d` mean seven calendar labels including today, today plus seven prior dates, or the last 168 hours?
5. Is the five-minute cache observed only in browsers, or does a deployed edge/cache rule honor it too? Source proves the directive, not cache topology.
6. Is unbounded `page_views` retention intentional, and does privacy text intend to disclose geo and the rotating pseudonymous identifier?
7. Are Bot/AI owner inclusion and filter-independent AI totals intentional standalone populations or denominator drift?
