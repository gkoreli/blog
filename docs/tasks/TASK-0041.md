# TASK-0030 — code-backed analytics architecture before and after

**Checked:** 2026-08-26. Repository facts below are code-inspected at immutable commits; deployment facts come from the checked-in production record; conclusions are marked as inference where code cannot prove outcome or cost. The immediate article's living center is the active wrong-event failure and cutover tension, but that does not ban earned past-tense lessons. It can braid proven architecture lessons, present uncertainty, and future intent. The clean 30-day outcome remains a separate continuation, which can use the same freedom rather than becoming a rigid retrospective.

## Compressed finding

The old system did not miscount its own event. It correctly counted browser beacon POSTs, then the dashboard called those rows page views, visitors, and AI reads. That event could never observe an ordinary crawler's original HTML request, much less a direct `llms.txt` or Markdown request. The failure was semantic and architectural: the desired claim sat outside the instrument's boundary.

The replacement moves observation to the served HTML-response boundary, preserves the meaningful 2,564-row beacon history as a source-marked read-model copy, and gives ingestion, storage, queries, UI, and privacy one vocabulary. It is a stronger instrument, but not a finished empirical result: writes remain best effort, identity and bot classes remain estimates, non-HTML resources remain outside `PageObservation`, the public timeline mixes two methods, and Worker-first cost/benefit has not been measured over a clean window.

The owned center should be: **I built a correct counter for the wrong event.** The new value beyond `does-llms-txt-work` is how to repair an observation boundary and migrate useful history without laundering one method into another.

## Before: browser beacon flow

```text
Browser GET /article
  -> Cloudflare static asset router
       -> dist/article.html                    (Worker not invoked)
       -> inline JavaScript runs, if allowed
            -> client chooses path/referrer
            -> POST /api/event                 (Worker invoked)
                 -> parse/sanitize JSON
                 -> classify POST User-Agent
                 -> SHA-256(UTC date:IP:UA), first 64 bits
                 -> INSERT page_views

/stats -> GET /api/stats?days=30&tz=<viewer offset>&visitor=human
       -> batched page_views queries
       -> duplicated snake_case JSON contract
       -> Views / Visitors / AI Reads

Direct crawler GET /article, /llms.txt, or /post.md
  -> static asset router -> no JS beacon -> no page_views row
```

### Evidence and consequences

1. `run_worker_first` matched only `/api/*`; ordinary static files bypassed application code ([legacy `wrangler.jsonc` L21-L29](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/wrangler.jsonc#L21-L29)).
2. Every generated HTML page included a one-line `fetch('/api/event')` guarded by `localStorage.analytics_ignore` ([legacy template L150-L152](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/packages/blog/src/templates/page.ts#L150-L152)). The client supplied `location.pathname` and `document.referrer`.
3. The Worker routed that POST to `handleEvent` ([legacy Worker L28-L40](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/packages/blog/src/worker/index.ts#L28-L40)).
4. `handleEvent` classified the beacon request's UA, derived the daily hash, and inserted a client-supplied event ([legacy handler L43-L90](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/packages/analytics/src/index.ts#L43-L90)). Sanitization limited path shape, not provenance; a caller could forge/replay it.
5. `page_views` stored path, host/path referrer, country, city, continent, a nullable 16-hex daily hash, numeric `visitor_type`, owner bit, device class, and UTC timestamp, with few checks ([legacy schema L4-L20](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/packages/analytics/schema.sql#L4-L20)).
6. Identity was the first 64 bits of unkeyed SHA-256 over delimiter-concatenated `YYYY-MM-DD:IP:UA` ([legacy hash L12-L23](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/packages/analytics/src/hash.ts#L12-L23)). The public date rotated equality at UTC midnight but did not prevent candidate enumeration over low-entropy IP/UA inputs.
7. Stats counted `visitor_type = 2` rows and returned the count as `ai_fetches`, independently of the selected visitor filter ([legacy stats L72-L97](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/packages/analytics/src/stats.ts#L72-L97)). It meant “beacon rows whose beacon POST UA matched the AI regex,” not crawler fetches.
8. The client sent its current numeric UTC offset; the server shifted historical UTC timestamps by that one offset before grouping ([legacy client L77-L80](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/packages/blog/src/client/stats.ts#L77-L80); [legacy stats L53-L70](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/packages/analytics/src/stats.ts#L53-L70)). Inclusive `DATE >= daysAgo(today,N)` yielded N+1 dates, while identity rotated at UTC midnight. A fixed current offset could not reconstruct historical DST.
9. The blog client hand-copied the API interface ([legacy client L8-L18](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/packages/blog/src/client/stats.ts#L8-L18)).
10. Public labels completed the overreach: Humans, Views, Visitors, AI Reads, and “without … fingerprinting” ([legacy stats page L11-L30, L61-L64](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/packages/blog/src/pages/stats.ts#L11-L30); [legacy privacy L11-L14](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/packages/blog/src/pages/privacy.ts#L11-L14)). Privacy said path/referrer only although the INSERT stored geography, pseudonymous identity, classes, owner status, and time.

### What the old system was still better at

It was cheap and isolated. Static pages stayed on Cloudflare's asset path; application code ran only for APIs. `document.referrer` captured browser navigation attribution. `localStorage.analytics_ignore` could suppress a beacon before spending a Worker request or D1 write. The package already had a sound `blog -> analytics` dependency direction, native crypto, raw D1, and a thin Worker. These strengths explain why it looked reasonable and why the wrong event survived.

## After: edge observation plus source-aware continuity

```text
GET /article, /post.md, /llms.txt, asset, or API
  -> Worker runs first
       -> known API? return API response
       -> otherwise env.ASSETS.fetch(request) exactly once
            -> actual status + Content-Type
            -> eligibility: GET + 2xx + text/html; not prefetch,/stats,/api
            -> metadata: pathname, external referrer host, country, transient IP/UA
            -> classifier: browser | bot | ai + nullable matched rule
            -> daily HMAC: secret -> UTC daily key -> structured host/date/IP/UA
            -> waitUntil(INSERT page_observations)
       -> return asset response unchanged

GET /api/stats?range=30d&traffic=browser[&path=/...]
  -> exact UTC window + one predicate
  -> D1 batch totals/paths/countries/buckets/referrers/devices/agents
  -> zero-fill missing buckets
  -> shared camelCase StatsResponse

Legacy page_views (untouched archive)
  -> idempotent minimized copy
  -> page_observations(source='beacon', source_event_id=old.id)
New rows -> page_observations(source='edge', source_event_id=NULL)
```

### Evidence and consequences

1. `run_worker_first: true` makes the blog Worker the composition root for static traffic; `ANALYTICS_HASH_KEY` is required ([current config L12-L32](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/wrangler.jsonc#L12-L32)). [Cloudflare's Worker-first docs](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/) name logging/middleware as the use case.
2. Known APIs return first. Every other request fetches the asset once, passes the actual request/response to analytics, and returns that response ([current Worker L21-L35, L76-L78](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/blog/src/worker/index.ts#L21-L35)). `/api/event` is gone.
3. Eligibility defines the event: successful HTML GET, excluding prefetch/prerender, `/stats`, and APIs ([eligibility L1-L20](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/src/eligibility.ts#L1-L20)). The Worker now sees non-HTML requests, but deliberately does not persist `llms.txt`, Markdown, feeds, assets, redirects, errors, or HEAD. This is edge analytics for HTML responses, not a universal request log or RUM.
4. The observer composes metadata, classification, identity, and repository functions; `waitUntil` makes persistence best effort ([composition L15-L53](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/src/index.ts#L15-L53)).
5. Referrers become external hostnames; query strings, full paths, city, and continent are dropped. IP/UA exist only long enough to classify and derive identity ([metadata L11-L39](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/src/metadata.ts#L11-L39); [repository L9-L44](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/src/db.ts#L9-L44)).
6. Traffic is `browser|bot|ai`; named AI rules run before bot rules, generic automation is bot/null-agent, and Browser is not called human ([classifier L13-L68](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/src/classify.ts#L13-L68)). UA remains sender-asserted, never verified identity.
7. HMAC-SHA-256 derives a daily key from a required master key, length-prefixes host/date/IP/UA, and stores 128 bits as 32 lowercase hex ([HMAC L3-L48](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/src/hash.ts#L3-L48)). It blocks outsider enumeration without the key; it remains pseudonymous daily-client estimation, not anonymity or people measurement.
8. Schema checks constrain path, ID, traffic/device enum, owner boolean, source vocabulary, and source ID uniqueness; indexes match time/class/path predicates ([schema L1-L30](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/schema.sql#L1-L30)).
9. One raw half-open UTC predicate scopes every aggregate. Presets are exact UTC calendar windows; 7d is hourly, longer ranges daily; absent buckets are server-created zeros ([dates L40-L78](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/src/dates.ts#L40-L78); [query L42-L53, L129-L195](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/src/stats.ts#L42-L53)).
10. `StatsResponse` is exported once and imported by the blog ([contracts L1-L28](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/src/contracts.ts#L1-L28); [client L1-L4, L77-L83](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/blog/src/client/stats.ts#L1-L4)).
11. The public page now defines Page views, Daily clients, Browsers, Bots, AI UAs, both eras, and limits beside the dashboard ([methodology L90-L96](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/blog/src/pages/stats.ts#L90-L96)). Privacy discloses transient/persisted fields, HMAC, legacy archive, indefinite retention, and separate Cloudflare Web Analytics ([privacy L11-L23](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/blog/src/pages/privacy.ts#L11-L23); [live privacy](https://gkoreli.com/privacy)).

## Bounded contexts and DDD/composition choice

| Boundary | Owns | Does not own |
|---|---|---|
| Blog Worker | HTTP route precedence, `ASSETS`, package composition, returned response | Metric semantics or UI |
| `@gkoreli/analytics` | Vocabulary, eligibility, minimization, classification, HMAC, D1 repository/query service, UTC, shared contracts | Asset serving, presentation, newsletter/errors |
| D1 read/write model | Source-aware observations and aggregate predicates | Verified provider identity, reading, RUM, cross-day people |
| Stats client/page | URL state, accessible rendering, adjacent methodology | Reclassification or client aggregation |
| Cloudflare Web Analytics/client observability | RUM-like performance and selected browser errors | Public D1 stats |

The Worker-local `Env` intersects package bindings and adds `ASSETS`; analytics `Env` owns only DB, hash key, and owner IPs ([Worker L21-L22](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/blog/src/worker/index.ts#L21-L22); [analytics env L3-L7](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/src/db.ts#L3-L7)). The package exports runtime composition and a contracts-only path ([package L1-L18](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/package.json#L1-L18)).

This is DDD in vocabulary and boundaries, not ceremony. Eligibility, classification, identity, persistence, time, and bucket completion vary independently, so functions with explicit dependencies fit better than inheritance. Raw SQL and platform crypto remain the boring choice; no ORM, analytics vendor, event bus, or class hierarchy was introduced. ADR-0016.1 also separates edge analytics from RUM ([ADR-0016.1 L176-L196](https://github.com/gkoreli/blog/blob/0df8c5936b2cfa6a1d9f77218262aacbd489100c/docs/adr/0016.1-analytics-purpose-and-decision-loop.md#L176-L196)).

## Migration, source continuity, and production

The first cutover instinct favored purity: create `page_observations`, leave `page_views` untouched, and start stats at the edge era. Production inspection changed the decision. The 2,564 old rows contained meaningful history. The amended model keeps `page_views` as lossless archive and copies a minimized representation into the public read model.

Migration 0002 adds `observation_source`, nullable old ID, and a partial unique index, then uses `INSERT OR IGNORE` ([migration L1-L51](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/migrations/0002_backfill_legacy_page_views.sql#L1-L51)):

- `0/1/2 -> browser/bot/ai`;
- host/path referrer -> hostname;
- 16-hex old daily ID duplicated to 32 characters, preserving equality/distinct counts without adding entropy;
- `agent_name=NULL`, because raw historical UA was never stored;
- `source='beacon'`, `source_event_id=old.id`; new rows default to `source='edge'`.

Production held 2,564 legacy rows from 2026-03-07 through 2026-08-26: 2,120 Browser, 347 Bot, 97 AI-UA; 39 paths, 32 referrers, 69 countries. Copy proof was 2,564 source rows, 2,564 copied, zero missing; archive untouched ([TASK-0020 L32-L45](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/docs/tasks/TASK-0020.md#L32-L45)). The two methods are not comparable; continuity is retained with source and prose rather than an artificial reset.

**Deployment dead end:** Wrangler's bulk import endpoint failed with Cloudflare authentication code 10000 despite valid D1 write scope; executing the same four schema statements through D1's query API succeeded. The hash secret was installed; first Worker version was `60a8a07b-204d-4704-8abb-0bc1b966b167`; source-aware final version was `30b44b36-61c5-42e9-8f55-55bdec6a71ef` ([TASK-0020 L23-L30, L47-L58](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/docs/tasks/TASK-0020.md#L23-L30)). Frozen verification: 2,126 Browser page events, 1,245 daily clients, 173 daily buckets, time-series sum equal to total. The [live all-time Browser API](https://gkoreli.com/api/stats?range=all) is volatile and had already moved after that snapshot.

## Cost and tradeoffs

**Before:** page GETs did not execute application code. Each successful beacon cost one Worker request and one D1 insert. With three indexes, the historical estimate was four row writes/event; at 94 events/day, 376 rows/day (0.376% of 100,000 free writes) ([ADR-0004 L85-L93](https://github.com/gkoreli/blog/blob/d6980874e9bf4422ea1b49225825cfc3aec265d6/docs/adr/0004-analytics.md#L85-L93)). Low cost came from excluding blocked JS and non-browser clients.

**After:** code runs before every static request, but D1 writes only eligible HTML. One table row plus three always-applicable indexes means likely four writes/edge event; the partial source index should exclude null edge IDs **[INFERENCE; verify with `meta.rows_written`]**. Backfilled non-null source IDs likely populate the fourth index **[INFERENCE]**. Current Cloudflare pricing lists 100,000 Worker requests/day free, 100,000 D1 writes/day free, and static assets free/unlimited ([official pricing, updated 2026-08-25](https://developers.cloudflare.com/workers/platform/pricing/)). Do not infer a dollar charge from `run_worker_first` without account metrics. The certain cost is a larger application-code, CPU, latency, and failure surface, plus potentially more rows. Complete all-time path aggregates may also grow in read cost.

|---|---|---|

## Dead ends and decisions that changed

1. **Add more crawler names:** a larger regex on `/api/event` still classifies the wrong request. Move the source first.
2. **Relabel and keep the beacon:** better copy cannot make non-JS HTML clients visible.
3. **Hide legacy history:** rejected after 2,564 valid rows proved meaningful. Source-aware continuity replaced semantic purity.
4. **Upgrade old identities during backfill:** impossible. Equality can be preserved; entropy, agent identity, and HMAC provenance cannot be invented.
5. **Keep viewer-local time:** a current offset cannot reconstruct historical DST and disagreed with UTC identity rotation.
6. **Call unkeyed SHA-256 anonymous:** public-date/low-entropy inputs remain enumerable and pseudonymous. HMAC improves secrecy, not personhood.
7. **Assume migration tooling is routine:** bulk import failed; query API was the real production path.
8. **Add architectural ceremony:** no class hierarchy/framework was warranted; policies vary independently.
9. **Assume the source marker is public filterability:** `StatsResponse` does not expose/filter source. Source awareness lives in D1 and methodology; that is a deliberate simplicity tradeoff.

## Observations, inferences, unknowns

### Observed / code-inspected

- Current analytics can record non-JS HTML clients. It still excludes non-HTML `llms.txt`/Markdown. Keep resource-request experiments distinct from HTML page observations.
- Source archive and edge rows have no automatic expiration; privacy says retention is indefinite.
- Writes are best effort. A served page can be absent after D1 failure.
- UA matches are requester claims. They do not establish verified provider, read, index, training, citation, or model use.
- Historical `/stats` beacon rows remain in All-time data although new `/stats` responses are excluded.

### Documentation contradiction

ADR-0016 says the public timeline includes both eras and production All-time begins 2026-03-07, but one time bullet still says “All starts at the first edge observation” ([ADR L153-L165](https://github.com/gkoreli/blog/blob/0df8c5936b2cfa6a1d9f77218262aacbd489100c/docs/adr/0016-analytics-observation-semantics.md#L153-L165)). Code uses the earliest non-owner row from either source ([query L145-L152](https://github.com/gkoreli/blog/blob/f9d65ae9618c00c464c4ed274fc52534f352513b/packages/analytics/src/stats.ts#L145-L152)). Treat implementation, amendment, and production as current; flag the stale sentence rather than repeating both.

### Inferences

- Edge routing should capture more HTML automation/configurations than the beacon, but the clean window has not quantified it.
- Worker-first increases operational surface; latency/billing effect at this site's scale is unmeasured.
- Combined history is useful for broad path/referrer trends, but method bias is unknown without parallel evidence.

### Unknowns to keep open

- Post-cutover 30-day class mix and write-loss rate; continuation material, not a reason to delay this piece.
- Classifier false positives/negatives and unnamed automation left in Browser.

## Reusable architecture advice

1. Write the event sentence before the schema: method, source boundary, status, content type, exclusions, failure.
2. Name metrics from evidence, not desire. Exact count plus inflated label is still wrong.
3. Instrument the boundary that can see the fact: client for RUM/interactions; edge for served responses/non-JS. Neither proves attention.
4. Separate visibility from inclusion. The Worker sees Markdown; eligibility excludes it.
5. Put source semantics and source IDs in the model before combining eras.
6. Migrate only facts that survive; never synthesize stronger identity or historical classification.
7. Use one time contract across identity, SQL, buckets, UI, and URLs. Raw half-open UTC bounds remain indexable.
8. Derive privacy copy from the whole flow, including transient inputs, parallel third parties, and retention.
9. Keep bounded contexts boring: Worker composes, analytics defines, D1 stores/queries, page presents. Share contracts.
10. Turn semantics into reconciliation invariants: class sums, client<=views, path/time sums, owner exclusion everywhere.
11. Price the denominator change with platform metrics, not diagrams. Upstream observation changes execution and volume.
12. Keep analytics non-fatal and disclose “best effort” beside the count.

## Article implications

- **Form:** evidence-led engineering investigation braided with earned architecture lessons. The cutover is real; its empirical payoff is unresolved. Do not manufacture exposure or erase competence to preserve tension.
- **Opening:** pair the old beacon with `ai_fetches`. Both code fragments are technically correct. The lie enters at the semantic join.
- **Middle:** before/after diagrams, then the 2,564-row continuity decision. This is more valuable than “move analytics server-side”: real history made the clean model impure, so migration records that impurity.
- **Praise the loser:** beacon routing was simpler, cheaper in execution, browser-referrer-aware, and locally suppressible. Edge evidence adds routing surface.
- **Present tension:** the counter now has an honest meaning, but it is not yet known whether the data changes publishing decisions or just builds a better dashboard. That question is live now.
- **Novelty boundary:** do not repeat provider crawler lists, GEO claims, or `llms.txt` verdicts. Use those resources only as the request class that exposed the boundary, then generalize to instrumentation semantics.
- **Bounded verdict:** if a claim concerns an original resource request, a browser beacon is the wrong source. Edge observation fixes eligibility/provenance/naming; it does not turn UA into identity or a response into a read.
- **What could change it:** measured Worker-first overhead outweighing decision value; a lower-cost edge dataset meeting the exact/source-aware contract; or evidence that only browser/RUM questions matter.
- **Continuation:** the 30-day piece may state past-tense lessons from this cutover and stay vulnerable about whatever new ambiguity exists then. It need not conform to a retrospective template.
