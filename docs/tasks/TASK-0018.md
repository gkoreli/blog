## Findings

### Blocker

None.

### High

None.

### Medium

1. **`All` does not have the ADR's stable first-observation start; its start changes with traffic and path filters.** ADR-0016 says `All` starts at the first edge observation (`docs/adr/0016-analytics-observation-semantics.md:160`). `predicateFor` adds the selected `traffic_class` and exact `path` (`packages/analytics/src/stats.ts:42-53`), and the `MIN(observed_at)` query uses that predicate (`packages/analytics/src/stats.ts:129-148`). Thus an AI filter whose first match is August 20 reports a later `period.start` than a browser filter whose first match is August 1; a filter with no rows collapses `All` to today via `createStatsWindow` (`packages/analytics/src/dates.ts:40-55`). The `MIN` query also runs needlessly for 7d/30d/90d even though `createStatsWindow` ignores `allStart` outside `all`. **Fix:** for `range === 'all'` only, obtain the first non-owner `page_observations.observed_at` without traffic/path predicates (or include owners only if the accepted ADR is explicitly changed to define that), use it for the shared reporting window, and retain the selected predicate for every displayed aggregate. Do not issue `MIN` for preset ranges. **Test:** seed an early browser/path row, a later AI/different-path row, and no-match filters; assert every `all` response has the same first public-observation `period.start`, including empty segments, while totals and dimensions remain selected-filter scoped.

2. **The tests do not defend the persistence, D1 aggregation, metadata, or Worker-routing contracts that carry most cutover risk.** `packages/analytics/test/contracts.test.mjs:18-80` covers eligibility samples, four classifier samples, HMAC input separation, preset dates, and bucket completion only. It never imports or exercises `metadata.ts`, `db.ts`, `index.ts`, `stats.ts`, the migration/schema, or `packages/blog/src/worker/index.ts`. Consequently no behavioral test proves owner exclusion across every aggregate, half-open SQL bounds, class/path consistency, all-time behavior, complete path totals, legacy-table isolation, write scheduling/error behavior, or removal of `/api/event`. **Fix/tests:** add a disposable-D1 or faithful D1 integration test that seeds all three classes, owners, two paths, duplicate daily IDs, and rows immediately before/at both timestamp bounds; assert `all = browser + bot + ai`, `dailyClients <= views`, `sum(timeSeries.views) = totals.views`, complete `byPath` sums to totals, every dimension applies owner/class/path predicates, and a sentinel `page_views` row is never read. Add an observation/Worker test with fake `ASSETS`, `ExecutionContext.waitUntil`, and D1 bindings: eligible HTML GET schedules exactly one write after the asset response; API/stats/prefetch/HEAD/redirect/error/non-HTML paths schedule none; `/api/stats` routes to query handling; `/api/event` cannot ingest; a D1 rejection does not replace the already-served asset response. Add metadata cases for same-site/external/malformed referrers, absent UA, and owner matching.

### Low

3. **The analytics binding type owns the static-assets transport boundary and gives handlers broader dependencies than they use.** `packages/analytics/src/db.ts:3-8` places `ASSETS` on analytics `Env`, although no analytics function fetches assets; the blog Worker is the composition root and is the actual consumer at `packages/blog/src/worker/index.ts:21-22,76-77`. This contradicts the ADR boundary that the blog Worker owns HTTP/static routing while analytics owns observation semantics (`docs/adr/0016-analytics-observation-semantics.md:63-87`). `handleStats` consequently accepts secret, owner, and asset bindings while using only D1 (`packages/analytics/src/stats.ts:177-190`). **Fix:** remove `ASSETS` from the analytics bindings, declare the asset binding in a Worker-local `Env`, and narrow analytics entry points to their explicit dependencies (for example, stats gets `D1Database`; observation gets DB/hash-key/owner inputs). Keep function composition; no inheritance or class hierarchy is warranted.

4. **A missing hash binding fails closed but produces an accidental TypeError rather than the required-secret diagnostic.** `persistObservation` dereferences `env.ANALYTICS_HASH_KEY.length` before checking runtime presence (`packages/analytics/src/index.ts:15-17`). The binding is type-required and listed in `wrangler.jsonc:12-14`, but Wrangler's local schema describes `secrets.required` as local-dev warning/type-generation support rather than a production deployment guarantee (`node_modules/wrangler/config-schema.json:348-360`). If production is misconfigured, every eligible background write rejects with an undefined-property TypeError. No weak/unkeyed identifier is written, which is the correct security posture, but the operational failure is needlessly opaque and untested. **Fix:** guard `typeof key === 'string' && key.length > 0` and throw the explicit `ANALYTICS_HASH_KEY must not be empty` error for absent or empty bindings before metadata/HMAC/D1 work. Add a focused observer test asserting missing and empty keys reject the `waitUntil` promise with that message and never call D1; retain deployment verification that the secret exists.

## Contracts correctly defended

- `wrangler.jsonc:21-26` runs the Worker before assets; the Worker routes known APIs first, fetches assets once, calls observation only on the served response, and returns that response (`packages/blog/src/worker/index.ts:28-78`). `/api/event` is absent.
- Eligibility enforces GET, `response.ok`, HTML content type, all three prefetch-purpose headers, and stats/API exclusion (`packages/analytics/src/eligibility.ts:1-19`). Redirects, failures, HEAD, feeds/Markdown/non-HTML, `/stats`, and API routes are therefore outside the metric.
- HMAC identity uses a date-derived HMAC key, length-prefixed structured host/date/IP/User-Agent fields, and the first 128 bits as lowercase hex (`packages/analytics/src/hash.ts:3-48`). Raw IP and User-Agent are transient metadata only; the insert persists neither (`packages/analytics/src/metadata.ts:24-39`; `packages/analytics/src/db.ts:22-45`).
- AI named rules run before general bot rules; generic automation is bot/null-agent and unmatched UAs are browser (`packages/analytics/src/classify.ts:13-56`). Schema checks constrain identity shape, traffic class, browser-agent nullness, device type, and owner booleans consistently in fresh schema and migration (`packages/analytics/schema.sql:3-24`; `packages/analytics/migrations/0001_create_page_observations.sql:1-22`).
- Referrers are reduced to normalized external hostnames; same-site and malformed values become null (`packages/analytics/src/metadata.ts:11-21`). Country is Cloudflare-derived; path is pathname only.
- Preset windows use exact UTC calendar arithmetic, raw half-open SQL timestamp predicates, hourly 7d/day longer granularity, and zero-fill through the current UTC bucket (`packages/analytics/src/dates.ts:40-78`; `packages/analytics/src/stats.ts:42-53,129-169`). All displayed SQL aggregates use one selected predicate and one `db.batch`; owner exclusion is present in every statement via that predicate.
- The API response contract is shared and camelCase (`packages/analytics/src/contracts.ts:1-28`), accepts only 7d/30d/90d/all and browser/bot/ai/all, and no viewer timezone offset affects computation (`packages/analytics/src/stats.ts:177-190`).
- Active SQL reads/writes mention only `page_observations`; `page_views` appears only in the fresh-schema preservation comment, so legacy beacon rows cannot contaminate the edge series. Raw timestamp indexes and owner/traffic/path composite indexes match the query predicates (`packages/analytics/schema.sql:19-24`; `packages/analytics/src/stats.ts:42-53`).
- The implementation correctly uses small policy functions and composition. There is no inheritance hierarchy; the only architectural correction needed is narrowing the binding boundary described above.
