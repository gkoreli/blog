# TASK-0024 — preregistered 30-day sequel evidence window

## Publication and form boundary

This protocol governs a **separate continuation**. It is not a gate for the immediate analytics-rebuild article, which publishes from the active pain and evidence already owned: the old implementation correctly counted browser beacon events while its labels made stronger claims about page requests and AI reads. Waiting 30 days would falsely make that current work look resolved before publication.

The continuation may later braid earned, past-tense lessons from the cutover with whatever tension, failure, or confidence is alive then. It should choose its governing form from that future material. This protocol does not impose an open-wound quota, force a field-note structure, erase growth, or manufacture vulnerability. It only prevents later data from laundering the immediate mistake into an inevitable success story. If the data add no new value, publish no sequel.

## Frozen clocks

All ranges are UTC and half-open.

| Final restatement | `2026-09-28T06:00:00Z` | — | D+2 | Lock late provider aggregates and ledger |

Aug 26 is excluded because `TASK-0020` records two deployments, six verification edge Browser rows, and the source-aware backfill that day. The original 2,564-row `page_views` archive remains the lossless history; its 2,564 source-marked copies remain meaningful. The 30-day comparator is a lens, not a reason to delete history, blend sources, retroactively name legacy agents, or imply identical event universes.

### Frozen comparison cohorts

Before the edge window starts, freeze paths that (1) have at least one non-owner beacon row in the comparator, (2) serve eligible HTML at T0, and (3) existed before cutover. Never select paths based on post-window performance. Analyze:

1. **Whole site:** operational totals, including new posts and traffic shocks.
2. **Frozen stable paths:** the least-bad time-separated source comparison.
3. **Unchanged stable paths:** sensitivity view excluding a frozen path whose body, canonical URL, title, discoverability metadata, or distribution materially changed during the edge window.

New posts, including the immediate analytics article, stay in whole-site totals and the intervention ledger but cannot enter the matched comparator.

## Evidence ledger at freeze

### Observed / code-inspected

- `TASK-0020` records the exact 2,564-row backfill and final cutover deployment `30b44b36-61c5-42e9-8f55-55bdec6a71ef`.
- `page_observations` admits only `beacon|edge` and `browser|bot|ai`, preserves `source_event_id`, and indexes time/public predicates (`packages/analytics/schema.sql:3-29`).
- Public queries use half-open UTC timestamps and `is_owner=0`; one predicate scopes cards, paths, time series, referrers, countries, devices, and agents (`packages/analytics/src/stats.ts:42-53,129-174`).
- The Worker returns the asset response and schedules D1 persistence with `waitUntil`; the response may succeed while the row is lost (`packages/analytics/src/index.ts:15-53`).
- AI rules precede named/general bot rules; unmatched UA is Browser, not verified human (`packages/analytics/src/classify.ts:13-59`).
- D1 intentionally excludes Markdown, `llms.txt`, assets, feeds, redirects, failures, `HEAD`, prefetches, APIs, and `/stats`.

### Primary documented

- Cloudflare Web Analytics is a browser beacon. It can be blocked and lose payloads. Unsampled data lasts seven days; longer-lived data is aggregated to roughly 10%, and dashboard/API queries may be dynamically sampled. It is a RUM layer, not the first-party edge dataset.
- `httpRequestsAdaptiveGroups` can filter exact/path-like URL, successful status, `requestSource: "eyeball"`, and UA-like patterns on all plans. Adaptive counts may be estimates; request `sampleInterval` and 95% confidence intervals.
- D1 exposes query volume, rows read/written, latency, response bytes, and database size for 31 days. Billing uses rows and storage; index updates add row writes.
- Workers metrics expose request/error statuses, CPU, wall time, and subrequests. Invocation success does not prove a background D1 write succeeded.

### Inferences to test

- Persistent edge Bot/AI rows across dates and paths would show that the new counter observes declared automation in the eligible HTML-response universe that the beacon could not comprehensively cover. It cannot prove provider identity, reading, indexing, citation, training, or use.
- Beacon/edge count differences mix method change with real calendar-time traffic change. They are not causal uplift.
- Successful `/llms.txt`, `/llms-full.txt`, or `*.md` requests prove requests only, not discovery, selection, comprehension, answer influence, or citation.
- Stable Web Analytics/D1 divergence would make the layer boundary visible, not identify one universally correct counter.

### Unknowns

- Post-window volume/class mix and traffic shocks.
- Web Analytics owner contribution, per-vital sample counts, sampling, and late-beacon magnitude.
- Exact eligible HTML responses lost after `waitUntil`; there is no independent exact denominator.
- Whether the account exposes all desired GraphQL dimensions. Introspect before T0. If unavailable, cancel that branch rather than changing production.

## Analysis queries

### Source/class comparison

```sql
WITH windows(label, source, start_at, end_at) AS (
  VALUES
    ('legacy_beacon','beacon','2026-07-27 00:00:00','2026-08-26 00:00:00'),
    ('edge_30d','edge','2026-08-27 00:00:00','2026-09-26 00:00:00')
)
SELECT w.label, p.observation_source, p.traffic_class,
       COUNT(*) views, COUNT(DISTINCT p.daily_client_id) daily_clients,
       COUNT(DISTINCT date(p.observed_at)) active_days,
       COUNT(DISTINCT p.path) paths
FROM windows w JOIN page_observations p
  ON p.observation_source=w.source
 AND p.observed_at>=w.start_at AND p.observed_at<w.end_at
WHERE p.is_owner=0
GROUP BY w.label,p.observation_source,p.traffic_class
ORDER BY w.label,p.traffic_class;
```

Repeat with the frozen path list and unchanged-path list. Compare exact totals, per-day rates, median/IQR, weekday strata, automation share, max-day share, and max-path share. Ratios remain descriptive method-and-time differences.

### Daily partitions

```sql
SELECT date(observed_at) day_utc, traffic_class,
       COUNT(*) views, COUNT(DISTINCT daily_client_id) daily_clients,
       COUNT(DISTINCT path) paths
FROM page_observations
WHERE observation_source='edge' AND is_owner=0
  AND observed_at>='2026-08-27 00:00:00'
  AND observed_at<'2026-09-26 00:00:00'
GROUP BY day_utc,traffic_class
ORDER BY day_utc,traffic_class;
```

Every day/window: `all views = browser + bot + ai`; each class `daily_clients <= views`; named agents do not exceed their class; no source/class lies outside schema. Do not require distinct clients to add across classes/dates.

### Archive/source integrity

```sql
SELECT observation_source, COUNT(*) rows,
       SUM(source_event_id IS NULL) null_source_ids,
       SUM(source_event_id IS NOT NULL) retained_source_ids,
       MIN(observed_at) first_at, MAX(observed_at) last_at
FROM page_observations GROUP BY observation_source;

SELECT COUNT(*) post_cutover_beacons FROM page_observations
WHERE observation_source='beacon' AND observed_at>='2026-08-27 00:00:00';

SELECT
 (SELECT COUNT(*) FROM page_views) archive_rows,
 (SELECT COUNT(*) FROM page_observations WHERE observation_source='beacon') copied_rows,
 (SELECT COUNT(*) FROM page_views v LEFT JOIN page_observations o
   ON o.observation_source='beacon' AND o.source_event_id=v.id
   WHERE o.id IS NULL) missing_copies;
```

Expected T0: 2,564/2,564/0. Edge `source_event_id` is null; copied beacon IDs are retained. Any later beacon insert is a protocol break.

### Path/agent evidence

```sql
SELECT path,traffic_class,agent_name,COUNT(*) views,
       COUNT(DISTINCT date(observed_at)) active_days,

FROM page_observations
WHERE observation_source='edge' AND is_owner=0

  AND observed_at<'2026-09-26 00:00:00'
GROUP BY path,traffic_class,agent_name
ORDER BY views DESC,path,traffic_class,agent_name;
```

Legacy `agent_name` is null by design; never infer historical named agents.

### Exact non-HTML resources

Run one daily `httpRequestsAdaptiveGroups` query with `requestSource: "eyeball"`, 2xx status, and path OR: `/llms.txt`, `/llms-full.txt`, `%.md`. Request path, count, sample interval, and 95% CI.

```graphql
query ResourceRequests($zone:string!,$start:Time!,$end:Time!){
 viewer{zones(filter:{zoneTag:$zone}){
  httpRequestsAdaptiveGroups(limit:5000,orderBy:[count_DESC],filter:{
   datetime_geq:$start,datetime_lt:$end,requestSource:"eyeball",
   edgeResponseStatus_geq:200,edgeResponseStatus_lt:300,
   OR:[{clientRequestPath:"/llms.txt"},{clientRequestPath:"/llms-full.txt"},{clientRequestPath_like:"%.md"}]
  }){
   count avg{sampleInterval}
   confidence(level:0.95){count{estimate lower upper sampleSize}}
   dimensions{clientRequestPath}
  }
 }}
}
```

For named automation, rerun with one frozen `userAgent_like` rule at a time, or verified `botDetectionIds` only when entitled. Rule counts are nonadditive evidence per rule; UA is spoofable and patterns may overlap. Store aggregates only. Never infer resource requests from D1 or Web Analytics: both omit them.

### Web Analytics/RUM

At T0, capture/freeze the exact dashboard GraphQL and variables for daily page views, visits, sample interval, and path-filtered P75 LCP/INP/CLS with sample counts/ratings. Run daily inside raw retention.

For dates where each source has >=5 observations, compute `cfwa_pageviews / d1_edge_browser_views`, median/IQR, daily-gap sign, and rank correlation across >=15 dates. This diagnoses layers only: Web Analytics can be blocked, includes owner traffic, observes executing browsers, loses/samples beacons; D1 excludes owners, includes non-JS HTML clients, and can lose background writes.

No Core Web Vitals verdict unless a per-vital count exists, `n>=100` across >=10 dates, and sampling/coverage is reported. Otherwise call it sparse/insufficient. RUM never validates automation or resources.

## Contamination/confounder rules

1. No measurement changes or new probes during observation.
2. No result-based exclusions; retain raw and adjusted aggregate plus evidence for every predefined exclusion.
3. D1 always uses `is_owner=0`. CF sources may include owner activity; never subtract guessed rows. Remove a known probe only with uniquely identifying time/path/UA evidence and report both totals.
4. Publishing continues. New posts/actions stay in whole-site totals/ledger, not the stable comparator. Material stable-path changes enter sensitivity exclusions.
5. If one day is >=25% of window views or one referrer >=35%, label volume shock-dominated; preserve it and report daily median/IQR plus leave-one-shock-day sensitivity.
6. Nonconcurrent sources confound method with calendar time, seasonality, recrawl, content mix, and distribution.
7. Historical owner exclusion was imperfect; legacy Browser volume/clients are approximate, not an exact external-reader denominator.
8. UA rules are sender-provided, frozen, incomplete. Browser is not human. New UA strings remain Browser until a post-window decision; no manual in-window reclassification.
9. Missing referrer is unattributed, not direct.
10. D1, RUM, Workers, and HTTP analytics differ in eligibility, failure, sampling, retention, and owner scope; none is a perfect denominator.
11. Resource requests include caches/retries and are not clients/uses.
12. RUM varies with blockers, support, visibility/navigation behavior, late beacons, interactions, and sampling.
13. Worker/D1 metrics include newsletter/client-error work; attribute only with query/script evidence.

## Stop rules

No early success stop. Complete the fixed window unless integrity breaks.

**Hard stop/restart:** any frozen semantic change; missing hash secret; schema/source-marker/owner failure; post-T0 beacon write; independent HTML evidence nonzero while edge rows vanish >24h; attributable persistence failures exceed 1% of estimated attempts; or >24h of non-owner synthetic traffic cannot be separated. Do not mutate production merely to save the study; handle health separately, then register a new window.

**Cancel only a branch:** exact path HTTP data unavailable at T0 or >=3 consecutive captures lost beyond retention cancels resources; missing WAE sampling/per-vital counts cancels quantitative RUM; unavailable query attribution cancels marginal cost but permits platform-wide context.

**Cancel standalone sequel:** no branch below clears; only result repeats the code-proven beacon blind spot; or evidence is dominated by one test/owner/day/path/UA or unrecoverable sampling. Thirty elapsed days are not a finding.

## Sequel claim branches and thresholds

These are editorial anti-noise gates, not statistical causality. Use exact D1 counts and 95% lower bounds for adaptive CF counts. Clearing permits investigation, not compulsory publication.

### A. Event boundary mattered in field data

**Justifies:** edge `bot+ai >=30`, across `>=10` dates and `>=5` frozen paths, plus either automation share `>=2x` beacon comparator or named-AI edge `>=10` across `>=3` dates and `>=3` paths. Require no day >50% and no path/agent >60% after sensitivity.

Allowed: persistent declared automation appeared in the edge HTML universe the beacon could not comprehensively cover. Forbidden: causal traffic lift, verified identity, reads, indexing, citation, training, use.

**Weakens:** `<20`, `<7` dates, or concentration breach. **Cancels branch:** `<10` or only test/owner evidence.

### B. HTML repair leaves a resource boundary

**Justifies:** 95% lower bound for 2xx `/llms.txt` + `/llms-full.txt` + `*.md` is `>=20`, across `>=7` dates and `>=3` paths. An AI-specific sentence additionally requires `>=5` named-AI-UA/verified-ID requests across `>=2` agents and `>=2` dates. Without it, say resources were requested, not AI-requested.

Allowed: HTML analytics and non-HTML request evidence answer different stages. Forbidden: discovery, selection, use, answer influence, citation.

**Weakens:** CI relative width >25%, one resource/day >60%, or only probes. **Cancels:** exact path unavailable or lower bound `<10`.

### C. Edge and RUM visibly differ

**Justifies a layer section, not a winner:** `>=15` dates each with at least five D1 Browser and five WAE page views, median absolute daily ratio gap `>=25%`, same sign on `>=12` dates. Carry owner/blocking/late/sampling/best-effort caveats.

**Weakens/cancels:** fewer comparable dates, unknown sampling, or one shock determines result. RUM performance may stand only if its sample gate clears.

### D. Cost/failure changes the verdict

**Justifies:** attributable persistence errors `>=1%` of attempts or `>=5` on each of two dates; isolated analytics queries consume `>10%` of plan’s included D1 daily allowance on `>=3` dates; or attributable modeled paid overage exceeds `$1` over 30 days. Preserve exact logs/query evidence and distinguish table rows, index writes, shared DB, and Worker costs.

No observed errors and trivial included usage strengthen the implementation account but do not earn a sequel alone.

### E. No clean result

If no branch clears, preserve the ledger and publish no 30-day article. Issue a short correction only if a fact in the immediate article changed; do not manufacture closure.

## Implications for the continuation

If a branch clears, choose the future piece’s form from the evidence and author’s actual state. It may contain resolved lessons, current uncertainty, or both. Regardless of form, preserve these evidence boundaries:

1. name the preregistered dates and 2,564-row continuity;
2. show source-separated counts before combined totals;
3. name each event: beacon event, served HTML response, browser RUM, or resource request;
4. keep contamination, counterevidence, cost/errors, and non-proofs beside the claim;
5. state the bounded decision and what would change it.

Do not repeat `does-llms-txt-work`, which already separates discovery, retrieval, navigation, use, citation, referral, and outcome. New value must be source-aware measurement behavior in this owned production system.
