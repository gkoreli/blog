Decisions:
- Made the Worker the composition root: API routes are handled first, all remaining requests are served through env.ASSETS.fetch, and the served Response is passed to observePageResponse without delaying the response on persistence. Enabled Worker-first assets globally and declared ANALYTICS_HASH_KEY as required.
- Removed the legacy /api/event route and inline page beacon completely.
- Consumed TrafficFilter and StatsResponse directly from @gkoreli/analytics. URL state now uses range and traffic parameters from the shared contract. Every selection aborts the prior request, clears current data, hides the dashboard, and exposes a whole-dashboard loading/error/empty state before new values can appear.
- Reframed the public UI around Browsers, Bots, AI UAs, and All; Page views and Daily clients; grouped aria-pressed controls; explicit UTC bounds, bucket granularity, partial-period state, and updated time. Added UTC-aware hourly/daily plotting plus an accessible table, view-labeled dimension rows, safe page links, named-agent rows, and Browser-only device mix.
- Placed the observation boundary and metric methodology inline, including heuristic sender-provided UA classes, best-effort recording, owner exclusion, daily pseudonymous HMAC client IDs, and the non-additivity of hourly daily-client counts.
- Updated privacy disclosure with the exact first-party stored fields, transient IP/User-Agent processing, 128-bit HMAC construction and linkage limits, and a separate Cloudflare Web Analytics beacon disclosure.

Risks:
- Cloudflare Web Analytics is an operational Cloudflare setting; repository code can disclose it but cannot disable it.
- Worker-first execution applies to every asset request and changes the request path through Cloudflare even though ineligible responses are rejected by the analytics eligibility policy.
- The chart depends on uPlot sizing after the hidden loading state becomes visible; the renderer measures after revealing the dashboard and the ResizeObserver keeps it synchronized.

Evidence and remaining checks:
- Targeted stats-page render smoke confirmed accessible selected controls, Daily clients copy, and absence of the legacy beacon/forbidden terms.
- Targeted Worker smoke served an HTML asset through ASSETS and observed exactly one persisted page observation.
- Static audit found no /api/event, handleEvent, analytics_ignore, Humans, Visitors, AI Reads, or fingerprint-free wording in owned files.
- Parent integration must run the repository-wide formatter, typecheck/build/tests once both analytics and blog slices are present, then browser-check the generated /stats surface and Cloudflare deployment bindings/migration.
