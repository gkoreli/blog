# TASK-0025 — Worker-first routing and non-HTML ResourceObservation boundary

## Bounded verdict (2026-08-26)

The production Worker is not blind to `llms.txt`, `llms-full.txt`, page Markdown, `posts.json`, or RSS. `run_worker_first: true` sends those requests through the Worker before the static asset binding. The application deliberately persists only successful, non-prefetch HTML GETs as `PageObservation`. That is the right page-view boundary, but it leaves a separate non-HTML resource-request question unanswered by D1.

Do **not** widen `page_observations` or rename non-HTML requests as views. A separate `ResourceObservation` bounded context is conceptually justified; engineering it is **not earned yet** because current request volume and a decision that needs durable first-party history have not been established. Cloudflare's no-code surfaces can establish that baseline now. This is an open architecture boundary for the immediate article, not a reason to delay publication for a 30-day result. The article may braid earned lessons from the cutover, the unresolved boundary now, and future intent; the evidence does not prescribe a rigid narrative form or manufacture exposure.

## Observed request path

```text
request
  -> gkoreli-com Worker (all domain traffic; Worker-first)
      -> explicit /api/* handlers return early
      -> otherwise ASSETS.fetch(request)
          -> observePageResponse(request, response, ...)
              -> only eligible successful HTML GETs
                  -> asynchronous D1 page_observations insert
              -> every non-HTML representation exits without D1 persistence
```

**Code evidence**

- `wrangler.jsonc:5-9,21-32` names `packages/blog/src/worker/index.ts` as the Worker, routes the `gkoreli.com` custom domain, binds static assets, sets `run_worker_first: true`, and binds D1 as `DB`.
- `packages/blog/src/worker/index.ts::fetch` (lines 28-79) returns explicit API responses before the asset path; every other request calls `env.ASSETS.fetch`, then `observePageResponse`.
- `packages/analytics/src/eligibility.ts::isEligiblePageResponse` (lines 9-20) requires `GET`, `response.ok`, no `/stats` or `/api` path, no prefetch/prerender purpose header, and `Content-Type: text/html`.
- `packages/analytics/src/index.ts::observePageResponse` and `persistObservation` (lines 15-53) classify the UA, build a daily pseudonym, and persist asynchronously with `ctx.waitUntil`.

## Current observability map

### First-party D1: durable page semantics only

`packages/analytics/schema.sql` and its migrations define only `page_observations`. A production read-only query on 2026-08-26 found:

| Source | Rows | First observation | Latest at query | Meaning |
|---|---:|---|---|---|
| `beacon` | **2,564** | 2026-03-07 01:10:23 UTC | 2026-08-26 05:05:01 UTC | Historical browser-beacon page events |
| `edge` | **15** | 2026-08-26 15:26:15 UTC | 2026-08-26 16:15:22 UTC | Eligible HTML page responses after cutover, at query time |

The 2,564 rows remain meaningful page-event history. They cannot be backfilled into ResourceObservation because the browser beacon never saw server-side requests for non-HTML resources. `packages/analytics/migrations/0002_backfill_legacy_page_views.sql:12-50` preserves `beacon` versus `edge` provenance rather than pretending the methods are identical.

The public `/api/stats` reads only `page_observations` and reports `views` and daily pseudonymous clients (`packages/analytics/src/stats.ts::queryStats`, lines 129-174). It therefore cannot answer how often any non-HTML representation was requested. That is correct and must stay separate.

### Workers Logs: precise, sensitive, short-lived request evidence

The deployed config enables logs and invocation logs (`wrangler.jsonc:15-19`). Live tail exposed full request URL, method, request headers including raw IP and UA, detailed Cloudflare request metadata, and response status for all six marked resources. Cloudflare documents request/response metadata and fetch messages containing method and URL. Stored logs retain 3 days on Workers Free or 7 days on Workers Paid; the unspecified sampling rate defaults to 1, while live tail may sample at high volume.

**Answers now:** whether an exact path reached the Worker, method/UA/status, inside the available window.

**Does not answer durably:** 30/90-day first-party history, a stable taxonomy across UA changes, or public aggregate provenance. Copying raw headers into D1 would make privacy worse.

Sources: [Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/) (updated 2026-08-11); [Real-time logs](https://developers.cloudflare.com/workers/observability/logs/real-time-logs/) (updated 2026-06-25).

### Cloudflare AI Crawl Control: best no-code baseline

For recognized AI crawlers, AI Crawl Control provides allowed/all requests, crawler, category (purpose/type), operator, hostname, status distribution, requested versus served format, edge response bytes, most popular paths, path filters, and CSV export. Free-plan detection is UA-based and Metrics covers only the past 24 hours; Enterprise Bot Management adds detection IDs and configurable timeframes.

**Answers now:** which recognized crawler/operator requested each exact resource or paired HTML path, whether it succeeded, format, and bytes within the plan window.

**Cannot prove:** genuine identity on free, model reading/use/indexing/citation, or the intent of unrecognized/generic automation.

Sources: [Analyze AI traffic](https://developers.cloudflare.com/ai-crawl-control/features/analyze-ai-traffic/) (updated 2026-04-23); [plan limits](https://developers.cloudflare.com/ai-crawl-control/get-started/) (updated 2026-04-23).

### Cloudflare Web Analytics: browser RUM, separate again

Cloudflare describes Web Analytics as page performance experienced by site visitors. The privacy page says its JavaScript beacon supplies Cloudflare's performance dashboard and does not feed public stats (`packages/blog/src/pages/privacy.ts:21-23`). It does not establish Worker receipt of machine-readable resources. Source: [Cloudflare Web Analytics](https://developers.cloudflare.com/web-analytics/) (updated 2026-04-16).

## No-code baseline — start now; do not delay the article

1. In **Cloudflare → AI Crawl Control → Metrics**, select the exact 24-hour window. Export CSV at one fixed UTC time daily so free-plan windows do not overlap or leave gaps.
2. Capture separately: `/llms.txt`, `/llms-full.txt`, `/*.md`, `/posts.json`, `/feed.xml`, and paired canonical HTML paths. Never add HTML and resource requests into one “views” number.
3. Preserve UTC coverage, path, crawler, operator, category, allowed/all requests, status class, response content type, and edge bytes. Label identity UA-declared unless Cloudflare supplies a detection ID.
4. Use **Workers → gkoreli-com → Observability** as a short-window audit for exact URLs/status/UAs and unknowns. Record aggregates only; do not copy raw IP, full headers, city, TLS fingerprints, or full UA strings.
5. Compare D1 PageObservations only in a separate table/chart. The valid comparison is representation requests under named boundaries, not a combined total and not a read claim.
6. Exclude the TASK-0025 synthetic audit UA and owner traffic. Treat sampling, outages, missed exports, or plan-window gaps as unknown coverage, not zero.

Suggested ledger columns: `window_start`, `window_end`, `surface`, `resource_kind`, `path`, `agent_family`, `declared_purpose`, `identity_basis`, `status_class`, `response_type`, `requests`, `bytes`, `coverage_note`. This baseline is continuation evidence and an engineering gate, never a prerequisite for publishing the immediate piece.

## Purpose-aware UA taxonomy

The current page classifier collapses distinct declared purposes and misses current fetchers (`packages/analytics/src/classify.ts:13-29,42-59`):

- GPTBot and ChatGPT-User both become `ai`, though OpenAI documents potential training versus user-triggered visit. OAI-SearchBot is omitted and falls into unnamed generic `bot`, though OpenAI documents search surfacing.
- `Claude-Web` is present, while Anthropic currently documents ClaudeBot (potential training), Claude-User (user retrieval), and Claude-SearchBot (search quality); the latter two are absent.
- PerplexityBot is present while Perplexity-User is absent; Perplexity documents search-result crawl versus user-triggered retrieval.
- CCBot and broad crawlers are labeled `ai` even though UA alone cannot establish a particular downstream purpose.

Primary sources: [OpenAI crawlers](https://developers.openai.com/api/docs/bots); [Anthropic crawler policy](https://privacy.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler); [Perplexity crawlers](https://docs.perplexity.ai/docs/resources/perplexity-crawlers).

ResourceObservation should keep two axes:

- `agent_family`: documented normalized token, or `generic_automation`/`unknown`.
- `declared_purpose`: `training`, `search_index`, `user_fetch`, or `unspecified`.

Purpose is **declared**, never verified or observed. UA is sender-controlled. Unknown stays unknown; do not infer “AI read” from organization, browser-shaped UA, IP owner, or path. Version the taxonomy so old aggregates retain meaning.

## Engineering gate

Implement ResourceObservation only when all are true:

1. **Decision need:** a named product/editorial decision requires durable resource-by-purpose history, and 24-hour exports/short logs cannot answer it reliably.
2. **Repeated signal:** either (a) at least 100 successful non-HTML GETs from at least two documented families across seven distinct days in a rolling 30-day period, excluding owner/synthetic/generic traffic, or (b) one reproduced real-client workflow requests these resources and needs durable measurement. This filters isolated probes/bursts; it is not statistical significance.
3. **Semantic stability:** every named family has a primary-source purpose; all else remains `unspecified`.
4. **Privacy/retention:** daily aggregates answer the decision without IP, raw UA, referrer, country, device, client pseudonym, or event rows, and 90 days is enough.
5. **Public need before public API:** add an endpoint only when readers/automation need reproducible aggregates; otherwise query privately.

**Current disposition: gate not met.** Routing and eligibility are proven, but exact AI Crawl Control volume and a decision that exports fail to support are unknown. Begin the baseline while publishing the architecture story now.

## Conditional minimal schema/API if the gate fires

Keep a separate table; never add nullable resource fields to `page_observations`.

```sql
CREATE TABLE resource_observation_daily (
  day TEXT NOT NULL,
  resource_kind TEXT NOT NULL CHECK (resource_kind IN (
    'llms_index', 'llms_full', 'page_markdown', 'posts_index', 'rss'
  )),
  path TEXT NOT NULL CHECK (path LIKE '/%'),
  method TEXT NOT NULL CHECK (method IN ('GET', 'HEAD')),
  status INTEGER NOT NULL CHECK (status BETWEEN 100 AND 599),
  agent_family TEXT NOT NULL,
  declared_purpose TEXT NOT NULL CHECK (declared_purpose IN (
    'training', 'search_index', 'user_fetch', 'unspecified'
  )),
  taxonomy_version INTEGER NOT NULL,
  requests INTEGER NOT NULL CHECK (requests > 0),
  PRIMARY KEY (day, resource_kind, path, method, status, agent_family, declared_purpose, taxonomy_version)
);
```

Classify only the five families, skip owner/synthetic traffic, and atomically upsert `requests + 1`. Do not hash a client. Purge after 90 days in the nightly handler. Do not clone/read response bodies merely to count bytes; Cloudflare already supplies transfer bytes and that allocation is unjustified.

Conditional public contract:

```text
GET /api/resource-stats?range=7d|30d|90d&kind=<optional>&purpose=<optional>
```

Return `requests`, never `views`/`clients`, with UTC period/coverage, time series, by-kind, by-path, by-agent-family, and by-declared-purpose. Never join/sum it into `/api/stats`; comparisons belong in an analysis layer with both method labels visible.

## Privacy, volume, retention

- Current PageObservation processes IP/UA transiently but stores a daily HMAC and reduced metadata (`packages/analytics/src/metadata.ts:24-39`; `packages/analytics/src/hash.ts:24-48`). Resource questions need no pseudonym.
- Live logs contain raw IP, full UA, detailed geo/network/TLS data. Their short retention is safer than copying them into D1, but exports still require minimization.
- Restrict to five resource families; exclude CSS, JS, images, APIs, sitemap, and arbitrary HTML. Daily upsert cardinality follows meaningful dimensions, not request count. Keep path because page-Markdown choice is the question.
- Existing first-party page rows have no automatic expiry (`packages/blog/src/pages/privacy.ts:11-19`). Do not silently extend that precedent. Ninety days is the bounded resource decision window; longer needs a named question and privacy-policy change.
- Writes remain best effort. Expose coverage and method limits instead of promising exhaustive logs.

## Explicit non-goals

- Calling resource requests page views, visits, people, or clients.
- Combining ResourceObservation with PageObservation or rewriting the 2,564 beacon rows.
- Claiming request = model read, index, use, citation, answer influence, referral, or outcome.
- General access logging for assets/APIs/sitemap/arbitrary files.
- Replacing Web Analytics/RUM or Cloudflare AI/security analytics.
- Persisting IP, raw UA, referrer, query, city, TLS fingerprint, Accept, or event rows.
- Verifying bots or syncing vendor IP lists before spoofing changes a decision.
- Measuring representation answer quality; TASK-0025 owns the architecture boundary only.
- Delaying the immediate article for the 30-day continuation.

## Article implications

1. The old beacon counted a browser-side event correctly but it was the wrong event for claims about served pages and AI requests. The edge cutover now counts eligible HTML responses correctly.
2. The Worker can see agent resources and refuses to call them page views. That is stronger than “we forgot Markdown logging.” The repaired boundary also exposes a live question: which representations matter enough for their own context?
3. Preserve 2,564 historical rows with `beacon` provenance. They remain useful under the old method and never become access-log history.
4. This does not repeat `does-llms-txt-work`. That piece asks about downstream efficacy. This case teaches a measurement rule: define event and bounded context before naming the metric; a machine-readable request is neither page view nor proof of use.
5. The governing form remains editorial judgment. The material can braid retrospective lessons the cutover genuinely earned, present ambiguity or cost that remains alive, and future intent. Do not force a tutorial, a vulnerability quota, or an artificially unresolved ending.
6. Publish the immediate evidence-led piece now. The no-code baseline and 30-day resource result are a separate continuation, which may itself combine past-tense learning with whatever new wound is alive then.
