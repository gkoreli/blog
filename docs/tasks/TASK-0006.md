# Observed live state
- Initial load selected Humans / 30d and rendered 209 Views, 121 Visitors, 17 AI Reads. Request: /api/stats?days=30&tz=420&visitor=human from America/Los_Angeles.

# High-confidence anomalies
1. Period labels are off by one calendar day: 7d returned Aug 18–25 inclusive (8 dates); 30d returned Jul 26–Aug 25 inclusive (31); 90d returned 91.
2. AI Reads ignores the active visitor filter. `ai_fetches: 17` appeared for Human, Bot, AI, and All. Human-only views/visitors are paired with global AI reads. AI makes all three cards 17 and redundant.
3. All is not exactly the union of named classes. 30d Human/Bot/AI views were 209/68/17 (294), while All was 295. Visitors did sum: 121+65+17=203. At least one unclassified/null view, overlap, or inconsistent filter needs tracing.
4. Device type is questionable for crawler traffic. AI / 30d reports 76% Mobile; all-time AI reports 90 mobile vs 7 desktop. This may reflect UA parsing but reads as human device behavior without qualification.
5. Daily chart labeling is noisy. Each 30d tick repeats 12am plus a date; legend remains Time: -- Views: -- Visitors: -- until hover. Mobile labels are small/low contrast.

# Additional chart correctness finding

The time series omits zero buckets and the client charts only returned rows. On AI / 30d the API period was 2026-07-26 through 2026-08-25, but nonzero rows existed only on Jul 26, 28, 30, and 31. The rendered x-axis therefore stopped at Jul 31 and connected those four points, visually turning a 30-day selection into a six-day chart and hiding the following 25 zero days. For count data, absent date/hour buckets must be zero-filled across the requested period (or rendered as explicit gaps); the domain must remain the selected period.

# Fundamental collection blind spot

`AI Reads` and `Bots` are not counts of AI/bot requests to the site. Static HTML bypasses the Worker (`run_worker_first` is `/api/*` only), and classification happens only when the client-side JavaScript beacon posts to `/api/event`. Well-behaved crawlers that fetch HTML but do not execute the beacon are invisible. The dashboard can count only beacon-capable clients whose POST user-agent matches a bot/AI pattern. Calling this metric AI reads/fetches materially overstates its coverage; the future agent-traffic design needs server-side request visibility or a deliberately narrower label.
