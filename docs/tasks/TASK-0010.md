# TASK-0002 — Live `/stats` surface and API audit

**Scope:** Black-box exercise of `https://gkoreli.com/stats`, its rendered controls/chart/rankings, and live `/api/stats` responses. I did not inspect repository implementation.

**Observation window:** approximately 2026-08-26 04:57–05:05 UTC. Browser locale `en-US`, IANA timezone `America/Los_Angeles`, `Date#getTimezoneOffset() = 420`. Values are live and changed during the audit; the same Human/30d query moved from 209 views / 121 visitors to 216 / 122. The API advertised `Cache-Control: public, max-age=300`, so the numbers below are evidence snapshots, not an immutable fixture.

## What was exercised

- Desktop Chromium at 1440×1000: every cross-product of visitor control (`Humans`, `Bots`, `AI`, `All`) and period control (`7d`, `30d`, `90d`, `All`) — 16 states.
- Narrow viewport at 375×812: control layout, Human/30d populated state, AI/7d empty state, cards, device summary, chart, and all three ranked sections.
- Chart hover at multiple x positions for 7d and 30d.
- URL state and reload/deep-link behavior.
- Immediate UI state before the fetch resolves.
- Out-of-order request defense by deliberately holding the older Human/All request while allowing the newer Human/7d request to resolve.
- Direct API probes for timezone offsets `0`, `420`, `-330`, `840`, and `-840`.

## Live control and routing behavior

**Observations / evidence**

- Initial state is `Humans` + `30d`; observed request: `GET https://gkoreli.com/api/stats?days=30&tz=420&visitor=human`.
- Period and visitor state are encoded in the page URL. Examples observed after clicks: `/stats?days=7`, `/stats?days=7&visitor=bot`, `/stats?days=90&visitor=bot`, `/stats?days=90&visitor=ai`, `/stats?days=0&visitor=ai`. Default Human is omitted from the URL.
- Reloading `/stats?days=0&visitor=ai` restored active `AI` + `All`, rendered 97 views / 94 visitors / 97 AI Reads, and requested `/api/stats?days=0&tz=420&visitor=ai`.
- Selection styling updates immediately, before data does. Reproduction: from AI/All (97 views, 94 visitors, 97 AI Reads), click Human then 7d quickly. Immediate state: pills say Human/7d, but cards still read 97/94/97 and chart aria-label still describes the old all-time AI result. After the request resolved, cards became 112/46/0 and the chart label described 7d Human. There is no visible loading/busy state.
- A forced out-of-order response did **not** overwrite the newer result: delayed `/api/stats?days=0&tz=420&visitor=human` arrived after `/api/stats?days=7&tz=420&visitor=human`; UI remained Human/7d at 112/46/0. This is useful negative evidence: the transient mismatch exists, but stale late responses appear guarded.

## Timezone and window probes

The browser sends numeric `Date#getTimezoneOffset()`; timezone identity is not sent. Direct all-visitors probes near the same observation time produced:

| Request | Period | Totals (views / visitors / AI reads) | `by_day` points |
|---|---|---:|---:|
| `days=7&tz=0&visitor=all` | 2026-08-19 → 2026-08-26 | 134 / 65 / 0 | 38 hourly points |
| `days=7&tz=420&visitor=all` | 2026-08-18 → 2026-08-25 | 132 / 68 / 0 | 41 hourly points |
| `days=7&tz=-330&visitor=all` | 2026-08-19 → 2026-08-26 | 136 / 67 / 0 | 39 hourly points |
| `days=30&tz=0&visitor=all` | 2026-07-27 → 2026-08-26 | 281 / 185 / 5 | 31 daily points |
| `days=30&tz=420&visitor=all` | 2026-07-26 → 2026-08-25 | 295 / 203 / 17 | 31 daily points |
| `days=30&tz=-330&visitor=all` | 2026-07-27 → 2026-08-26 | 285 / 188 / 5 | 31 daily points |

Whether this is correct local-day behavior or a reproducibility problem is a product decision input, not resolved by live inspection.

## Ranked anomalies / misleading states

### 1. Labels imply bot/AI coverage that the collection path cannot provide — **high confidence, high severity**

**Live observation:** The public controls and cards are labeled `Bots`, `AI`, and `AI Reads` without a coverage qualifier.

**Cross-layer evidence supplied from TASK-0003 (not independently re-inspected here):** static HTML bypasses the Worker (`run_worker_first` applies only to `/api/*`); classification occurs on the client-side JS beacon POST to `/api/event`; non-JS crawlers that fetch articles never enter D1.

**Inference:** `Bots` and `AI Reads` cover only beacon-capable matching clients. They cannot support the ordinary reading that the dashboard measures bot/AI traffic or article fetches in general. This is the most consequential misleading state because the missing population is structurally invisible, not merely delayed.

**Falsifiable question:** What exact population is promised by each label, and what fraction of known AI/bot fetches can execute and complete the beacon?

### 2. `AI Reads` ignores the active visitor filter while adjacent metrics and rankings obey it — **high confidence, medium-high severity**

At 30d the card showed 17 under Humans, 17 under Bots, 17 under AI, and 17 under All. At 90d it showed 57 in every visitor state; all-time it showed 97 in every visitor state. Meanwhile Views, Visitors, chart, pages, countries, referrers, and devices changed with the visitor pill. Under AI specifically, AI Reads equals AI Views; under Humans/Bots it remains the same global-looking number.

**Inference:** Either `AI Reads` is intentionally period-global and needs explicit scope, or it is incorrectly unfiltered. In the current layout it appears scoped by the active pill, so Human and Bot states are misleading.

### 3. 7d is hourly but exposed as `by_day` and announced as `Daily views` — **high confidence, medium severity**

API timestamps, hover tooltips, and point counts all prove hourly resolution in 7d. The accessible label is factually wrong for that state.

### 4. `7d`, `30d`, and `90d` period metadata spans N+1 calendar dates — **high confidence observation, medium severity if labels mean calendar days**

Observed periods were Aug 18→25 (8 dates), Jul 26→Aug 25 (31 dates), and May 27→Aug 25 (91 dates). This may encode rolling elapsed-duration boundaries with inclusive date labels, but the UI says only `7d/30d/90d` and the chart aria-label says `last N days`.

**Falsifiable question:** Is the contract a rolling N×24-hour interval, N local calendar dates including today, or an inclusive start/end date range? The current metadata and wording do not agree on one unambiguous reading.

### 5. Active filters can temporarily describe stale cards/chart with no loading indication — **high confidence, medium severity under slow networks**

Reproduction above showed Human/7d active while the AI/All numbers and aria-label remained rendered until the fetch returned. Out-of-order completion was safely ignored, but the in-flight state is still internally inconsistent.

### 6. Same deep link is not numerically reproducible across timezones — **high confidence, medium/decision-dependent severity**

The page URL stores period and visitor, but not `tz`; client offset materially changes period dates and totals. This may be desired localization, but screenshots or shared URLs cannot be expected to match without recording offset and observation time.

### 7. Countries section is visibly partial without saying so — **high confidence, low-medium severity**

The UI shows at most ten rows and is titled `Countries`, unlike `Top Pages`. Even the API country array can omit views: all-visitors/all-time totals were 2,556 views while the 30 returned country rows summed to 2,463 (93 absent); Human/all-time was 2,112 versus 2,022 (90 absent). Missing/unknown/truncated geography is not surfaced as an `Unknown` or `Other` row.

### 8. One 30d all-visitors snapshot did not equal the sum of visitor categories — **medium confidence, low severity pending atomic check**

Captured views: Human 209 + Bot 68 + AI 17 = 294, while All = 295. Other tested periods reconciled exactly. Because the site is live and cached for five minutes, this may be non-atomic snapshot drift rather than an unrepresented classification. Re-test against one atomic data snapshot before treating it as a defect.

## Unknowns requiring code/data inspection

1. Formal window boundary contract and whether the displayed `period` is intended to be inclusive.
2. Whether 7d hourly granularity is deliberate and, if so, why the field/accessibility copy says daily.
3. Whether `totals.ai_fetches` is designed to ignore visitor filtering or the query omits a filter.
4. Exact bot/AI classifier population, false-positive/false-negative behavior, and beacon completion rate.
5. Cause of uncategorized country views and whether the API applies a top-30 limit, drops null geography, or both.
6. Whether cache keys vary by all query parameters and whether the five-minute public cache can mix snapshot ages across the 16-state matrix.
7. Whether long clipped labels have an intended touch-accessible disclosure beyond their full DOM text.
