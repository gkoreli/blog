## Governing evidence boundary

The owned claim is supported now: **the old system correctly counted a later browser-beacon event, then the dashboard used that count to make stronger claims about page requests, visitors, bots, and AI reads.** Static page requests bypassed the old Worker path; non-JavaScript crawlers did not create rows. The repair moves the event to an eligible HTML response at the edge and narrows the public language. This establishes a measurement-boundary correction. It does not establish a traffic improvement, readership result, or AI-discovery result.

## Schema and migration ledger

### Legacy source archive (`page_views`)

Production has 11 columns: `id`, `path`, `referrer`, `country`, `city`, `continent`, `visitor_hash`, `visitor_type`, `is_owner`, `created_at`, `device_type`; indexes `idx_path`, `idx_created`, `idx_visitor`. Most legacy columns are nullable/defaulted. It contains all 2,564 source rows, 39 paths, 32 distinct non-null referrer values, and 69 countries. Every `visitor_hash` passed the 16-lowercase-hex eligibility check.

### Public read model (`page_observations`)

Production has 12 columns and four indexes listed in S5. Constraints enforce leading-slash path, 32-lowercase-hex daily ID, `browser|bot|ai`, agent name only for automation classes, three device values, Boolean owner value, and `beacon|edge` source. The partial unique `(observation_source, source_event_id)` index makes legacy copying idempotent.

### Exact preservation proof

The backfill maps type `0/1/2` to `browser/bot/ai`, duplicates the original 16-hex daily identifier to 32 hex characters, sets agent name null, copies path/country/device/owner/timestamp, minimizes referrer to the hostname-like prefix used by the migration, sets source `beacon`, and stores the old ID. Production audit: 2,564 source rows, 2,564 unique copies, 0 missing, 0 extra, 0 mismatched. Equality and distinct-count behavior are preserved; no new historical identity or UA rule is invented.

## Privacy boundaries

1. **Edge D1 storage:** path only (no query), external referrer hostname, country, 32-hex daily client ID, traffic class, nullable named rule, device class, owner flag, source/time. No raw IP or raw UA in D1.
2. **Transient edge processing:** IP and UA are still processed to classify and derive the HMAC. This is pseudonymous, linkable within a UTC day, and not anonymous.
3. **Legacy archive:** retains city, continent, the older cleaned referrer value, 16-hex daily hash, class/device/owner/time. The minimized public copy omits city and continent and reduces referrer further.
4. **Retention:** both first-party datasets currently have no automatic expiration; live privacy says rows remain until deleted.
5. **Separate surfaces:** Cloudflare Web Analytics remains an active browser beacon and is disclosed. Turnstile and browser error diagnostics are separate again. Edge analytics is not RUM.
6. **Owner boundary unresolved:** query code excludes flagged owners, but every one of the 2,564 legacy rows and every inspected edge row had `is_owner=0`. Active version output listed no `OWNER_IPS` binding. The operational statement “my own requests are excluded” is therefore not supported by current production evidence.

## Prohibited claims

Do not publish any of these without new, stage-specific evidence:

- “The old system counted page requests,” “all page views,” or non-JavaScript crawler traffic. It counted recorded beacon events.
- “AI reads,” “AI visitors,” “AI indexing,” “AI citations,” “training,” “model use,” or verified provider requests. A UA match is sender-asserted classification only.
- “Browser means human,” “daily clients are people,” “unique visitors,” “returning readers,” or cross-day/client identity.
- “The edge metric captures `llms.txt`, `.md`, feeds, or other non-HTML resources.” It explicitly rejects them.
- “The edge metric is RUM” or “Cloudflare Web Analytics feeds public stats.” Neither is true.
- “Every eligible response is recorded” or “the totals are exact.” `waitUntil` persistence is best effort.
- “Anonymous,” “no fingerprinting,” or “no personal-data processing.” IP and UA are transient HMAC inputs.
- “The historical and edge eras are directly comparable,” or any cross-cutover increase framed as growth.
- “My own traffic is excluded” as a production fact until owner classification is configured and evidenced.
- “`30b44b36…` is active.” It was superseded.
- “The current numbers are the result of the rebuild,” “traffic improved,” or any 30-day outcome. Current values are a few live hours and a preserved five-month archive.
- A falsely totalized “the rebuild solved analytics” claim. Earned past-tense lessons are valid, but owner classification, non-HTML visibility, mixed-method interpretation, and live-value volatility must not be erased when they are material to this piece.

## Source rationale

1. **Production D1 read-only aggregates and schema introspection** are strongest for current row counts, schema, partitions, and one-to-one backfill proof. They cannot explain user intent or prove requests that failed before insertion.
2. **Pinned repository code** is strongest for event definitions, stored fields, eligibility, HMAC construction, aggregation predicates, and historical implementation. Use `f9d65ae…` for the cutover and `c85a629…` for the old path; do not cite moving `main` when the line matters.
3. **Live endpoints** are strongest for what readers are told now and the served API contract. Values are volatile/cached; retain `period.updatedAt`.
4. **Wrangler deployment/version metadata** is strongest for version chronology, traffic assignment, bindings, and secret presence without exposing values. It does not prove which Git commit produced an untagged upload.
5. **`FLDR-0001` artifacts** preserve dated reproductions and commands: `TASK-0010` old live behavior, `TASK-0012` old semantics trace, `TASK-0013` primary-source integrity limits, `TASK-0019` pre-production verification, and `TASK-0020` migration/deploy proof.
