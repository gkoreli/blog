# ADR-0016.20: Provider method updates and receipt display provenance

## Status

Accepted November 5, 2026. Implementation, activation and production acceptance are recorded separately in the [provider investigation](../../packages/blog/drafts/research/ai-bot-analytics-grilling/05-provider-expansion-and-hardening.md). Extends [declared roles and signer evidence](0016.8-declared-client-roles-and-signer-evidence.md) and [network policy](0016.4-owner-exclusion-and-network-evidence.md).

## Context

Controlled Grok, Claude, Gemini, Context.dev and ChatGPT Dot trials tested the analytics as well as retrieval. Twenty-seven exact page requests have full acknowledgement-to-D1 receipt equality under the previous collection/classifier profiles. That establishes stored behavior for those requests, not complete identification of all automated clients.

Verified Dot browser and curl requests named `https://chatgpt.com`, while the public display catalogue returned Other. The earlier ExaUser trials named `https://exauser.crawler.exa.ai`, also Other. Exa's current documentation separates that user-fetcher origin from its indexing crawler. The old per-client method registry still expected the indexing origin for ExaUser.

Receipt projection also used the mutable current display catalogue. The old database evidence did not retain its display-profile version. Adding names without addressing that would change a historical reconstruction.

Claude-User was recognized as an assistant declaration but had no configured address method. Anthropic now publishes a classic-bot JSON feed and separately documents hosted-browser `Claude-Agent` traffic with a SAIL publication. The captured Claude-User address did not match the reviewed JSON snapshot. That negative membership result does not authenticate another operator or establish impersonation.

One Grok request used AS7979. [RIPEstat](https://stat.ripe.net/data/as-overview/data.json?resource=AS7979) names Servers.com; the [operator's network description](https://www.servers.com/about/network) describes dedicated-server infrastructure. This meets the existing hosting-list criterion. Several other observed networks are transit, VPN or mixed consumer networks and do not.

## Decision

- Approve the exact ChatGPT and ExaUser publisher origins for display. This grants no verification trust and implies no human trigger, delegated identity or signed User-Agent.
- Version the ordered display catalogues. Locally verified, non-injected observations retain `signerDisplayProfile` in their signature evidence. Other outcomes display no verified publisher name and omit that field, preserving the existing 2 KiB storage limit even for the complete closed failure set.
- Replay retained profiles independently of today's catalogue. Legacy rows use a frozen last-unretained baseline (`2026-10-28.1`) or an explicit externally recorded historical profile; the latter's provenance remains external to D1. Reject unknown profiles and conflicts with a retained profile. No old row gains metadata retrospectively.
- Move ExaUser's current documented signing origin and reviewed directory to its dedicated subdomain. Preserve old stored method outcomes and recognize their historical profiles in reports.
- Add Anthropic's [classic-bot feed](https://claude.com/crawling/bots.json) only for ClaudeBot, Claude-User and Claude-SearchBot. Keep normal fetch deadlines, body bounds, cache policy, address provenance and four-source fanout unchanged.
- Recognize the documented Claude-Agent product token as a declared assistant role. Do not assign the classic robots' IP feed to it. Its [separate SAIL method](https://claude.com/.well-known/sail) remains unimplemented and explicitly unmapped.
- Add Servers.com AS7979 for future collection and provider display. Keep the September registry frozen for migrations 0006/0008. Do not rewrite their SQL or existing row classifications. A future historical correction would need its own disclosed migration and revision audit.
- Bump collection, classifier, network-method, signing-method, directory-publication and report-cache profiles as appropriate. Keep the cryptographic verifier profile unchanged.

## Consequences and limits

Current reports can show newly approved signer names for old verified origins; historical receipts retain their earlier Other result. These are different views with different purposes. Browser remains a request-shape classification, and network list nonmembership remains inconclusive. Bare `Google` from AS15169 does not become a documented Gemini declaration. A controlled provider label is experimental evidence and never a rule for unrelated production traffic.

Tests cover historical names and receipts, declared roles, new/old network-method scopes, unavailable feeds, storage budgets and preserved mixed-network exclusions. Independent local replay of the three Dot proofs demonstrates covered versus unsigned mutation behavior. Fresh production acceptance must establish deployment behavior separately.
