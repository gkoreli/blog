# ADR-0016.17: Report classification and signature evidence together

## Status

Active October 27, 2026 UTC. Source `2d900fb`, 100% activation, live API/table, local cache reuse and article publication are accepted in [research 23](../../packages/blog/drafts/research/analytics-retrospective/23-classification-and-signature-basis.md). Native D1/baseline comparison, scoped direct SQL and local UI fixtures remain separate evidence; no new collection or historical proof is inferred. Extends [identity and role](0016.8-declared-client-roles-and-signer-evidence.md), [verification evidence](0016.11-signature-verification-evidence.md) and [classification uncertainty](0016.12-explicit-classification-uncertainty.md).

## Decision

Add `byKindSignature`, a disjoint projection of included observations by stored classification and nine closed signature bases. Distinguish actual UA coverage from absent coverage, unsigned from unverified, outcome-only history from detailed records, injected verdicts and unrecognized/inconsistent facts. Do not infer a real-world operator, purpose, authorization or human trigger from these combinations.

Use the existing materialized included population and one report statement, preserving every selection/exclusion and historical observation. Require the projection's sum to equal the selected total, reject malformed/duplicate/nonpositive groups and preserve unknown kind as null. Emit no source URL, header, signature, nonce or arbitrary diagnostic string. No schema or collection change.

Expose the intersection as a native accessible table with full labels and kind links. Those links apply the same kind selection to existing vendor/network panels. Use honest headings for request classifications and stored signing outcomes. Version the API/report cache as `2026-10-27.6`; ingestion profiles remain unchanged.

## Basis and consequences

Two native stored-record fixtures have identical old classification and signature marginals but different intersections. The new projection exposes the difference. All common output remains identical; old reports gain no retrospective proof.

The extra group scan costs 1,028 additional local row reads on each 512-record fixture (21,132 → 22,160). Record actual production acceptance cost separately; do not claim this is a query optimization or a general accuracy improvement. The scoped pre-release SELECT uses 42,512 reads and zero writes within 50,000, revealing 225 outcome-only records. Public fills and observation work are additional.

Keep native-provider assessments, documented signer relations and published-IP checks independent. The table neither joins a native log sample to D1 nor establishes independent human/device labels. Source checks, delivery, activation, API/cache/UI and article publication require separate acceptance.
