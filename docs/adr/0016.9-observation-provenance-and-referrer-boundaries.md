# ADR-0016.9: Version observations and preserve ambiguous referrer evidence

## Status

Accepted — October 25 Pacific / October 26 UTC, 2026. Extends [ADR-0016.8](0016.8-declared-client-roles-and-signer-evidence.md) and the referrer history in [ADR-0016.6](0016.6-versioned-referral-policy-and-matomo-source.md). [Full-interval findings and release evidence](../../packages/blog/drafts/research/analytics-retrospective/10-full-interval-and-field-hardening.md).

## Basis

The complete release-to-cutoff aggregate contains 14,835 included events, with 1,540 root-source records among 2,365 internal-referrer events. An origin-only Referer and an actual homepage source serialize identically. The previous finite-number ASN check also accepted constructed negative/fractional inputs; the production aggregate found zero invalid non-null ASNs. These observations support a prospective precision repair and a preventive validation boundary, not a historical accuracy percentage.

## Decision

- Retain internal as normalized publication-host grouping, including the www alias. It is not the browser origin test; explicitly disclose scheme/port differences. This is analytics interpretation, not an authentication or same-origin security boundary.
- Keep absolute HTTP(S)/android-app hostname parsing. Target-relative and about:blank inputs remain unsupported and appear as unusable; that word must not mean all values were malformed. The aggregate finds one included unusable event, which does not justify guessing missing raw inputs or expanding the parser silently.
- Stop storing `/` as a source path on new internal-referrer events. Retain the internal category and null source path. Label old `/` source records as homepage or origin-only. Destination `/` remains a known requested page. Root omission trades some genuine homepage-transition detail for an honest unknown; historical rows are unchanged.
- Accept ASN only when it is an integer strictly between 0 and 4,294,967,295. These endpoints are reserved in the [IANA registry](https://www.iana.org/assignments/as-numbers). This validates a numeric boundary; it does not validate assignment, network ownership or identity. Missing/invalid values become null, without a request-source marker.
- Migration 0010 adds nullable collection_version and classifier_version. No backfill/default guesses. New writes use `2026-10-26.2` for both; normalization is part of the classifier's evidence inputs. Bump the appropriate constants when those semantics change. They identify implementation method, not verification of values. Report cache version becomes `2026-10-26.2`.
- Add `/owner`, an unindexed, non-counted setup page using the existing authenticated owner endpoint. Send the credential only in its same-origin Authorization header, clear the field after submission, and use no persistent browser storage. Marking remains browser/network/UA/UTC-day scoped. Existing cached reports may remain stale for up to an hour.

## Acceptance and limits

Test the migration and actual collector through local D1 before applying the additive migration in production. Verify future writes separately after activation. Old version nulls, referrer paths, classifications and raw outcomes remain intact. A setup page returning 200 or a successful scripted owner mark does not complete the actual owner's browser acceptance; the human must authenticate the intended browser and make the labelled verification navigation. Record persistence and public exclusion after that step, accounting for cache freshness.
