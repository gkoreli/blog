# ADR-0016.14: Retain documented public-range verification methods

## Status

Active implementation decision, October 27, 2026 UTC. Source `6124fab` has separate local checks, migration-before-push, integration/build, 100% activation, actual Worker negative controls, public exclusion and served API/UI/article/privacy/cache acceptance. Listed-vendor and genuine relay production acceptance remain open. [Research 21](../../packages/blog/drafts/research/analytics-retrospective/21-published-vendor-ip-methods.md) owns those receipts. Extends [signature methods](0016.13-verification-outcomes-and-vendor-methods.md) without changing their proof boundary.

## Decision

Compare eligible named declarations with fixed, reviewed vendor IP-feed endpoints. Initially eight feeds cover nine declarations: AhrefsBot/SiteAudit share a feed; Googlebot uses the common-crawler feed; OpenAI's GPTBot, SearchBot, ChatGPT-User and AdsBot use separate feeds; Perplexity Bot/User use separate feeds. Exa's documented signature method remains separate. Unmapped declarations stay explicit, and unknown strings never supply a fetch URL. OAI-AdsBot becomes an exact named other-bot declaration for documented ad validation, not an AI-training inference.

Use exact-pinned MIT `ipaddr.js` 2.5.0 for address parsing/matching, with a strict wrapper rejecting legacy numeric IPv4 and scoped/list/address-port forms. Verify its registry integrity and byte agreement with the recorded upstream commit. Check IPv4/IPv6 family and whole-feed CIDR validity, reject malformed entries instead of silently narrowing the list, and require network rather than host-bit prefixes. The feed registry is the source-to-document cross-reference; general ASN or cloud-provider membership supplies no vendor proof.

Use edge-supplied address fields only when provider context exists. Missing/invalid addresses and non-default parser ranges, Worker relay/subrequest addresses and unavailable provider context abstain. For documented pseudo-IPv4 overwrite cases, use the original IPv6 field accepted by the profile and retain the selected header/family. Same-zone Worker forwarding limits and shared relay addresses prevent an unconditional original-client claim. Process addresses in memory; do not add raw IP/UA, matched CIDR, arbitrary source URL or per-address cache keys to stored evidence. Public-feed requests contain no reader address.

Bound work to four applicable sources per request, fixed eight-source per-isolate caches, 256 KiB/4,096 prefixes per response and a 1.5-second deadline. Coalesce source fetches. Respect max-age/Age/no-cache/no-store, default reusable data to five minutes and cap reuse at one hour. Revalidate stale reusable bodies with bounded validators; preserve original fetch time, last validation time and digest separately. No stale result is used after failure. A 30-second per-source refresh cooldown returns not-assessed, rather than bypassing no-cache or calling the request a nonmatch. These are per-isolate controls, not a global vendor-request budget.

Persist a nullable 4,096-byte `vendor_ip_evidence` JSON column through additive migration 0014. Store method/profile, normalized address provenance/state/family, declaration coverage, per-source listed/nonlisted/unavailable/not-assessed results and successful feed digest/version/prefix-count/fetch/validation/freshness times. Keep summary flags for bounded report aggregation without per-row JSON-array expansion. Counts overlap across applicable methods; they are not extra page events. Collection/classifier/report versions become `2026-10-27.4`; the signature verifier/evidence remain `.3` and the new IP method has its own `.1` profile.

Classification remains independent. Range membership supports attribution to a published network snapshot, not authentication of a particular product, operator, user, intent, physical device or readership. Nonmembership does not prove spoofing. Preserve history as unrecorded, never rerun current feeds as historical-time proof. Derived evidence remains linked pseudonymous data under the existing observation lifecycle; this does not activate optional raw diagnostics or establish full EU/US compliance. Update the privacy disclosure alongside collection.

## October 30 cache provenance refinement

Vendor-IP profile `2026-10-30.1` records the access path and closed policy facts for future source checks. Keep accepted-response time, lifetime source and overlapping reuse blockers separate from the membership outcome. An empty blocker list describes the reuse interval at validation, not freshness at an arbitrary later request. Guards have no cache assessment. A cooldown may carry the last accepted policy in that isolate's current attempt context, but supplies no membership snapshot. Clear this context at the next attempt; a failure must not inherit a prior success's explanation. For no-store/private responses, retain only these derived processing facts for diagnostics, never the forbidden feed body, validators or raw publisher headers. Copy outward evidence so mutation cannot rewrite cached or earlier facts.

The 4,096-byte schema bound, cooldown, deadlines, fanout, classification and stale-data policy remain unchanged. Collection and full-stats cache versions advance; signature/classifier and article-readership report versions do not. Historical profiles keep their original scope without manufactured cache facts. New-profile stored-record consistency validates the cache facts; do that work conditionally for the new profile. [Research 103](../../packages/blog/drafts/research/analytics-retrospective/103-vendor-cache-policy-provenance.md) records paired workerd/Node, storage/receipt/report and cost evidence. Source delivery, production activation and measured acceptance remain separate. This fixed-feed cache implements a bounded policy subset; this refinement does not certify full RFC 9111 conformance.

## October 30 public cache explanations

Report cache version `2026-10-30.2` adds a strict `vendorCache` summary and a native disclosure on `/stats`. Partition every included event into recognized cache-era records, missing historical/unreported facts or unsupported/inconsistent records. Separate no applicable feed, guards only and recorded access; keep known/unknown policy overlap explicit. Paths, reuse contexts and blockers are event-presence counts across sources, not extra page events or upstream-request totals. Last accepted context on a cooldown is not a fresh membership result or a claim of freshness now. Reuse the existing stored network validator and group identical facts before bounded source/blocker expansion. Reject missing/inconsistent cohorts and preserve exact overlap conservation with safe-integer checks and BigInt intermediates. The client hides incompatible reports instead of filling plausible zeros.

The same iteration repairs the Fetch Metadata report's collection allowlist: collection `2026-10-30.1` preserves the parser/record and classifier used by `2026-10-29.6`; future/unrelated stamps remain unsupported. Verify this through the actual current collector, not only hand-built historical fixtures. No collection, classifier, verifier, schema, exclusion or article-readership semantics change.
