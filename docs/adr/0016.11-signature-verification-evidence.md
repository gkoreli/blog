Active October 27, 2026 UTC. Migration 0012, source `d723a88`, 100% activation, live public reporting and an excluded unsigned prospective-write control are accepted; organic signed collection remains open. Separate local, replay and production evidence is recorded in the [protocol audit](../../packages/blog/drafts/research/analytics-retrospective/18-webbotauth-verification.md). Public reports expose aggregate availability/coverage through the same population, exclusions and materialized single SELECT. Counts overlap and unavailable history is explicit. Version public report caches when activating the new semantics. Native agreement is not presumed.

## Why

The [real retained sample](../../packages/blog/drafts/research/analytics-retrospective/exa-native-verification.json) verifies 19 Exa-declaring records but authenticates neither UA nor requested path. A result saying only verified would discard this consequential limit. Two records share one provider ID, so neither signature validity nor a provider identifier proves unique events.

The [primary standards and pinned reference review](../../packages/blog/drafts/research/analytics-retrospective/18-webbotauth-verification.md#standards-vendor-claims-and-local-policy) also shows native Cloudflare and later draft/reference wire formats differ. Local and native verdicts must remain independently inspectable.

## Consequences and acceptance

No nonce database or active fingerprinting is added. Replay prevention, unsupported algorithms/discovery/components, invalid-versus-unavailable summary, complete cache/SSRF handling and classifier ambiguity remain explicit follow-ups. New booleans are linked to existing pseudonymous observations; privacy disclosure must not call them anonymous or claim legal applicability is settled. Existing retention/basis/rights issues remain open.

Apply migration 0012 before code writes the new column. Tests cover actual signed mutations, key cache/rotation/expiry, protocol input limits, native unknown/false, injection separation, migration preservation, report selection/exclusions and public privacy canaries. Use native local D1 before a bounded metered production SELECT. Verify source delivery, deployment, public API/UI and future organic writes separately; do not backfill historical proof.
