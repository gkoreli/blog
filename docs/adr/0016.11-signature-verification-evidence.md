# ADR-0016.11: Preserve what signature verification proves

## Status

Implemented and locally accepted October 27, 2026 UTC; production migration, activation and measured acceptance are recorded separately in the [protocol audit](../../packages/blog/drafts/research/analytics-retrospective/18-webbotauth-verification.md). Extends [identity and role](0016.8-declared-client-roles-and-signer-evidence.md) and [private diagnostics](0016.10-private-request-evidence.md).

## Decision

Keep the dedicated local Ed25519/directory verifier. Preserve its cryptographic outcome separately from native-provider assessment and declared client role. Successful verification must retain the covered components, wire form, validity, age, profile version and explicit expiry-only replay policy. Verification does not prove an unsigned role, human trigger, unique request, citation or authorization.

Add nullable, valid JSON `signature_evidence` with a 2,048-byte ceiling. Store closed derived fields and existing bounded local failure reasons; no raw signature, nonce, keys, headers, URLs or arbitrary native object. Missing native booleans remain null; false remains false. Injection is labelled and cannot supply claimed coverage. Historical rows remain null. This routine fact layer does not activate the optional raw diagnostic profile.

The production collector opts into evidence and a 24-hour maximum age/lifetime policy with existing 60-second skew. It retains its two-second abort deadline. Enforce protocol MIME/HTTP 200/no redirects, bounded directory body/key counts, key activation/expiry, publisher max-age/Age and no-store/no-cache, bounded cache maps and pending fetches, coalescing and a rate-limited forced refresh for key rotation. Evict imported keys when a newer fetched directory removes them. Direct HTTPS discovery remains distinct from redistributed key proof; neither full RFC/draft conformance nor full HTTP caching is asserted.

Collection/verifier profiles become `2026-10-27.1`; classifier remains `2026-10-26.3`. Public reports expose aggregate availability/coverage through the same population, exclusions and materialized single SELECT. Counts overlap and unavailable history is explicit. Version public report caches when activating the new semantics. Native agreement is not presumed.

## Why

The [real retained sample](../../packages/blog/drafts/research/analytics-retrospective/exa-native-verification.json) verifies 19 Exa-declaring records but authenticates neither UA nor requested path. A result saying only verified would discard this consequential limit. Two records share one provider ID, so neither signature validity nor a provider identifier proves unique events.

The [primary standards and pinned reference review](../../packages/blog/drafts/research/analytics-retrospective/18-webbotauth-verification.md#standards-vendor-claims-and-local-policy) also shows native Cloudflare and later draft/reference wire formats differ. Local and native verdicts must remain independently inspectable.

## Consequences and acceptance

No nonce database or active fingerprinting is added. Replay prevention, unsupported algorithms/discovery/components, invalid-versus-unavailable summary, complete cache/SSRF handling and classifier ambiguity remain explicit follow-ups. New booleans are linked to existing pseudonymous observations; privacy disclosure must not call them anonymous or claim legal applicability is settled. Existing retention/basis/rights issues remain open.

Apply migration 0012 before code writes the new column. Tests cover actual signed mutations, key cache/rotation/expiry, protocol input limits, native unknown/false, injection separation, migration preservation, report selection/exclusions and public privacy canaries. Use native local D1 before a bounded metered production SELECT. Verify source delivery, deployment, public API/UI and future organic writes separately; do not backfill historical proof.
