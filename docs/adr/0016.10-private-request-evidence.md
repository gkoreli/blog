# ADR-0016.10: Separate audience facts from private request evidence

## Status

Prepared and locally tested — October 26, 2026 UTC. The expanded collection profile is **off by default**. Production activation and privacy-boundary acceptance are not established by this decision. Extends [ADR-0016](0016-analytics-observation-semantics.md) and the owner's [September diagnostic clarification](../../packages/blog/drafts/research/readers-vs-bots/13-two-priority-implementation-plan.md#additional-evidence-and-collection-boundaries).

## Problem and evidence

D1 retains classification outcomes but discards their UA inputs. The Exa/Ahrefs gap cannot be replayed against historical UA bytes, and the current referral investigation cannot retrieve a UA from its D1 rows. The owner wants useful future evidence without indiscriminate personal-data collection and explicitly requests both EU and US guidance.

The [primary-source and implementation review](../../packages/blog/drafts/research/analytics-retrospective/13-eu-us-collection-boundaries.md) distinguishes parsed reporting facts, linked pseudonymous diagnostics and anonymous aggregates. Plausible and GoatCounter discard routine raw UA while retaining parsed attributes; IETF's actual Matomo deployment keeps raw visitor information for five days. These are precedents with different purposes, not one mandatory configuration.

## Proposed implementation

- Add nullable `request_evidence` JSON to observations and a separate `page_observation_diagnostics` table keyed to the local observation row. No inferred backfill, added person identity or rewrite of historical classes.
- Record claimed browser family/major, OS family/major, client form, the current Fetch Metadata support result, coarse preferred language and response status. These are declarations and parser results, not verified human/device identities.
- In the private layer retain at most 1,024 UTF-8 bytes of sanitized UA evidence and 512 of Accept evidence, with redaction/truncation flags; bounded platform HTTP/TLS/colo facts; a request-operation reference, valid-shaped Ray correlation value, verifier profile and bounded outcome. No raw signature bytes, cookies, authorization, form data, complete referrer URL or query string.
- Process headers through an explicit extractor and bounded scan. Remove familiar credential, contact, address and URL-detail patterns. **This does not prove arbitrary free text contains no personal information.** Values remain private and potentially personal after redaction. A redacted or truncated value is partial replay evidence.
- The profile activates only when `ANALYTICS_DIAGNOSTICS=private-v1`. Missing/unknown values disable it. Only paths from the trusted published page index qualify. Missing index data omits optional evidence while preserving the base observation.
- Voluntarily omit the optional layer for GPC or DNT signals. This does not change the existing base counter or claim those signals universally prohibit first-party analytics. The difference must be disclosed.
- No public diagnostic endpoint or new public report dimensions. Existing authenticated Cloudflare/D1 access is the diagnostic boundary. Public report serialization is tested with private canaries.

## Retention recommendation and why

The older fourteen-day candidate addressed a two-week calibration. The latest audit happened roughly six weeks after the prior release, so copying that candidate would again erase inputs before the next comparable investigation. The prepared candidate uses **sixty days** for private diagnostics, to cover that demonstrated review interval with a margin. This is a proposed engineering window to validate, not a legal minimum, universal safe period or owner-approved activation.

Expiry is checked on private reads. Nightly cleanup deletes indexed expired rows in bounded batches and reports reaching its cap or failure. A failed cleanup can delay physical deletion; read expiry is not a claim that all storage copies were erased. Paid-plan D1 Time Travel can retain earlier database states for thirty additional days. Restores must run the cleanup before reopening diagnostic access. Exports need their own expiry and are not automatically exempt as research.

Audience observations are not deleted when diagnostics expire. The existing indefinite retention of pseudonymous audience rows remains a separate explicit policy gap; retaining counts does not require claiming those rows are anonymous. Do not silently purge historical data under this change. A future aggregate-preserving retention decision must account for public filters, daily clients, policy recalculation and evidence revisions.

## Reliability

An optional diagnostic failure cannot roll back an acknowledged page event. It emits a bounded failure signal without serializing DB errors or payloads. Attempts and acknowledged writes carry random per-operation references in operational logs; these are not stable client IDs. Sampling, retention and best-effort writes prevent a global exactly-once or zero-loss claim.

Signature verification gets a two-second ceiling; timeout preserves the eligible page and marks verification unverified. The ceiling is a local operating policy, not a Web Bot Auth requirement or full verifier-conformance repair. Collection/classifier versions become `2026-10-26.3`; verifier implementation/profile reference is `2026-10-26.1`.

## EU and US boundary

The purpose is diagnosing collection/classification defects and producing publisher statistics. No newsletter/account join, advertising profile, cross-site identity, precise location or active device probing. Linked daily-ID rows and diagnostic traces are treated as potentially personal under GDPR and US state definitions. Neither a hash nor the absence of a name establishes anonymity.

The design does not itself establish territorial applicability, a GDPR lawful basis, an ePrivacy consent exemption, a transfer assessment or a US state-law threshold. The CNIL guidance is a French conditional exemption, not an EU-wide product certification. The Cloudflare DPA provides relevant processor/transfer terms; the existing database has no verified EU-only jurisdiction constraint. These facts must be represented accurately in the operational review and disclosure rather than hidden behind a PII-free label.

## Acceptance and activation gates

1. Tests cover useful claims, unknown/absent inputs, byte caps, redaction/partial evidence, injected identifying headers, mode/privacy-signal/index exclusions, migration/history preservation, read expiry, cleanup and public serialization.
2. Execute the actual migration and collector through local Cloudflare D1, including an optional diagnostic failure and a signature timeout. Record serialized size and additional write cost.
3. Validate Worker composition, scheduled cleanup, types and isolated generated privacy/article content. Inspect the scoped source diff; no type assertions except `as const`.
4. Resolve the owner's literal no-PII boundary against the fact that private linked diagnostics remain potentially personal; settle purpose, retention and disclosure. The owner asked for authoritative prior art before choosing, so do not treat that response as activation approval.
5. Apply the additive migration before code using its column. Commit/push the checked scoped source according to repository delivery rules. Activate the profile only under the resolved boundary, then verify excluded controlled production writes, version/fidelity/expiry, and public-report isolation. Record actual activation separately.
6. Keep existing native-log recoverability, ordinary-person/browser calibration and wider legal applicability limits explicit. A local pass does not establish any of them.
