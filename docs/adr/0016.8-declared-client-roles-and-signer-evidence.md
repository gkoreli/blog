# ADR-0016.8: Keep declared client roles and signing evidence independent

## Status

Accepted — October 25, 2026 Pacific / October 26 UTC. Amends the signature-first grouping in [ADR-0016.3](0016.3-audience-composition-and-citable-articles.md); preserves [ADR-0016.4's](0016.4-owner-exclusion-and-network-evidence.md) history contract. Source, deployment and observed acceptance are recorded in the [repair evidence](../../packages/blog/drafts/research/analytics-retrospective/08-classification-repair.md).

## Problem

The October audit found that official ExaSearchBot, ExaUser, AhrefsBot and AhrefsSiteAudit declarations fell through to generic bot/null-name results. A verified signature also overrode any recognized role with `signed-agent`. Consequently a signed search or SEO crawler entered a public filter named AI agents. A signer result does not establish on-demand retrieval or a human trigger.

## Decision

Recognize the four documented client tokens, with token boundaries. ExaUser maps to `ai-assistant`, ExaSearchBot to `ai-search`, and both Ahrefs clients to the new `seo-crawler` kind. These are declared roles, not authenticated operators.

Derive the role from existing request evidence. A verified signature preserves a recognized named role; an unrecognized role retains the `signed-agent` fallback. Existing signature fields preserve verification independently. Failed verification retains the role and its failure reason. This does not change the verifier's accepted cryptographic/protocol profile or make the UA covered by every accepted signature.

Add `bySigner` to the report over exactly the included selection, sharing owner, referral, path, time, agent and kind boundaries. Show declared names and stored verified-key outcomes independently. These panels overlap the disjoint reader kinds; they must not be added to headline totals. Render signer strings as text without outbound links. A signing directory is not automatically a recognized vendor.

Rename the `agents` public filter to Assistants & signed clients and explicitly label the historical/unknown-role fallback. Add `seo-crawler` to Crawlers. Preserve all existing API filter codes and old rows. Permit known-name filters over legacy signed classifications as well as the current declared role. Bump `STATS_REPORT_VERSION` to `2026-10-26.1` so cached reports cannot conceal the semantic change.

## History and limits

No migration, delete or backfill. Original null names and signature-first classifications remain as collected. Exa's shared signing directory cannot recover ExaUser versus ExaSearchBot from historical rows without their discarded User-Agents. The frozen audit remains a dated result.

The catalogue lives in source control; this repair does not add per-observation collection/classifier versions. TASK-0119 remains open for that work, broader native/vendor evidence, supported signature-profile acceptance and actual owner-browser coverage. Unsigned declarations remain spoofable; verification alone does not establish vendor recognition, unique freshness, authorization, benign purpose or reading.

## Acceptance

Exact official declarations, lowercase variants, mobile Ahrefs, token lookalikes, absent/failed/verified outcomes, actual unsigned ingestion and locally signed Ed25519 ingestion are tested. Report fixtures preserve historical unknowns and exclude owners, referral abuse and future observations. The complete query is checked through Cloudflare-local D1 for fixed and all-time windows before production acceptance. Live scripted controls must use a verified existing exclusion and remain explicitly synthetic. Organic vendor-signed acceptance is a separate claim requiring real traffic.
