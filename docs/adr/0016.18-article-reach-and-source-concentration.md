## Decision

Provide a focused `/stats/readership` report and one canonical `/api/readership` selection: stored Browser signals over the 28 completed UTC days before today, divided into four consecutive seven-day intervals. This is request evidence for publishing decisions. It does not identify readers, search terms, attention, use or sustained following.

Resolve the article catalogue from the Worker's local `posts.json` asset. Validate current canonical paths, publication dates, titles, uniqueness and bounds; fail visibly if metadata is unavailable or malformed. Rank only those articles. Keep all-site totals and article totals distinct. Publication-date overlap is calendar context, not measured availability or exposure. Earlier removed URLs and prompt/archive pages remain outside the article ranking.

Reuse owner/client and versioned referral-policy exclusions. Keep external, internal, absent-referrer and unknown/unusable/inconsistent/earlier-merged evidence separate. An external referrer is a claim; absent is unavailable acquisition attribution. No new collection, identity, device probe, retention policy, row rewrite or source exclusion follows.

Choose the largest normalized external hostname across the entire included window, with hostname ordering breaking ties. Hold that selection fixed across its weeks and articles. Return its name only when display-approved; otherwise return a withheld name and aggregate count. Approval cannot change which cohort is selected. Always show both total events and events outside that source. This sensitivity neither authenticates the source nor estimates a corrected human count; the largest source may be legitimate.

Also select a separate largest normalized external hostname for each article over the whole window, using the same deterministic tie-break. Hold it fixed across that article's weeks. Return approved naming, total, weekly contributions and unrecognized-time contribution outside the additive site metrics. Require a separate total/weekly reconciliation so a missing weekly row cannot silently lower the result. Article-specific outside counts refer to different cohorts; they are not one source-excluded site audience or a human estimate. Show the external-event percentage and all-event remainder with their distinct denominators. [Research 101](../../packages/blog/drafts/research/analytics-retrospective/101-article-specific-source-concentration.md) records the triggering R2 case, partial-row failure and corrected boundary. Report version/cache namespace advance together. No exclusion-policy change follows.

Use a single native-tested SQL statement for the focused report instead of loading the full verification report for every article. Materialize the date-bounded window before owner filtering, preserving an observed-time index plan instead of scanning an owner-leading index across history. Group current article paths and closed source/time facts before returning them; never return raw hostnames, daily client IDs or unrecognized paths. Canonical stored timestamps require hours 00–23; unrecognized times remain explicit in totals and outside weekly rows. Stored classifier-identifier counts expose missing/mixed stamps without certifying historical implementations.

Validate counts, disjoint sources, article catalogue size, unique paths, four contiguous intervals and article/week/site reconciliation at server and client boundaries. Reject incomplete or inconsistent evidence rather than rendering zeros. Snapshot output does not authenticate the underlying requests.

Reuse the existing one-hour edge cache, capped at UTC midnight and keyed by report version and referral policy. Ignore incoming query/filter/bypass values in the canonical report request. Preserve calculation time on reuse; do not cache failures or cookies. Cache locality and isolate coalescing do not create an account-wide read cap. Meter returned calculation work separately from views and provider retries. Caller-selected dates, hosts and per-article calculations are not part of this API.

## Publication-date normalization

Research 95 finds that the installed YAML engine turns unquoted calendar dates into UTC `Date` values. Normalize those values through UTC serialization, not build-machine local getters. Preserve authored article dates and quoted strings. The timezone regression checks UTC, Los Angeles and Kiritimati; a publication date remains publisher metadata, not first-seen time or measured exposure. The accepted report already received the authored day in production.
