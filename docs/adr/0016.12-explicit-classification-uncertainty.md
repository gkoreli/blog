# ADR-0016.12: Preserve declarations and abstain on insufficient evidence

## Status

Implemented locally October 27, 2026 UTC. [Research and acceptance](../../packages/blog/drafts/research/analytics-retrospective/19-explicit-classification-uncertainty.md) record rollout separately. Extends [declared roles](0016.8-declared-client-roles-and-signer-evidence.md), [observation versions](0016.9-observation-provenance-and-referrer-boundaries.md) and [signature evidence](0016.11-signature-verification-evidence.md).

## Decision

Use exact lexical UA product matching with explicit reviewed aliases and preserve all canonical names/products. Same-category multiple names retain their common declared category without selecting an identity. Multiple categories abstain into a new Unresolved kind; signatures remain independent and do not resolve conflicting declarations.

Make missing, hosting-listed, archiver-listed and not-listed network evidence distinct. New Browser rows require a recognized browser-family claim, navigation shape and available unlisted network evidence. Missing/unrecognized Fetch Metadata, unknown browser claims and bounded context inconsistencies can abstain; absent activation is not a human/automation test. Hosting membership is a local rule, and nonmembership never establishes a normal/residential network.

Add nullable valid JSON `classification_evidence`, capped at 2,048 bytes, through migration 0013. It holds closed derived names, aliases, categories and flags, not raw UA/IP/free-text products/URLs. The legacy coarse traffic column remains compatible. Collection/classifier versions become `2026-10-27.2`; the cryptographic verifier profile remains `2026-10-27.1`. Public reports add a fifth disjoint Unresolved group, bump cache semantics and label the historical Automation & legacy rules group accurately.

Keep historical rows and their grouping unchanged. Preserve legacy Slackbot preview-kind filtering while new general Slackbot stays other-bot and explicit link/proxy tokens have distinct names. Historical navigation reasons acknowledge network unlisted/unavailable instead of normal. New role reasons no longer append local signature failures because those failures have separate retained evidence.

## Tradeoffs and evidence

The [counterexample audit](../../packages/blog/drafts/research/analytics-retrospective/17-detection-assumptions-and-experiments.md) demonstrated substring matches, order-dependent conflicts and missing-network collapse. The [new replay](../../packages/blog/drafts/research/analytics-retrospective/r1-classification-v2-replay.json) exposes 118 inconsistent retained requests without identifying their operator or rewriting them. Exact matching can miss unknown variants; explicit aliases and abstention make that limitation inspectable. Compatible multi-name categories avoid discarding useful shared evidence.

This remains a declaration/rule model, not a human classifier, vendor verifier, device authentication or full UA grammar implementation. Additional parsed facts remain linked pseudonymous data under the existing retention; this decision neither enables raw diagnostics nor settles collection basis, rights or indefinite retention. Public named tables select one stored name and do not split ambiguous requests into extra views.

## Acceptance

Check catalogue boundaries/aliases, ordering invariance, category agreement, signature independence, network states, unknown contexts, JSON size/privacy, additive migration/history and all five public partitions with exclusions. Run actual collector/verifier/persistence/report SQL through native local D1 before migration and a bounded production report. Apply migration before writes; commit/push checked source, then verify activation, live UI/API/article/cache and excluded prospective controls separately. Keep vendor-source checks, organic signed collection and independently labelled error/abstention experiments open until their own evidence exists.
