# ADR-0016.3: Audience Composition and Citable Articles

## Status

Proposed — 2026-09-03. Extends ADR-0016 and ADR-0016.1, and redirects ADR-0016.2. Research is in progress under `FLDR-0007` (`TASK-0101`, `TASK-0105`, `TASK-0106`); the decisions below are direction, and each engineering step still needs its own evidence before it ships. This document exists so the author's tenets are recorded once, in his words, before they get lost in implementation.

Distilled into tenets the engineering must obey:

1. **Composition, not exclusion.** The purpose of classification is to see who reads and how, not to filter "invalid traffic". Automation that reads the articles is audience. Nothing is blocked because of how it reads.
2. **Labels are facts, never confidence.** A public class name states something the request carried: a browser navigation from a residential network, a browser on a cloud host, an HTTP client with a browser User-Agent, an AI assistant fetching for a person, a crawler indexing. No "likely", no "-like", no "suspect".
3. **Know who is who, without knowing who.** Identify agents and services by what they declare (User-Agent rules, signatures, published keys and IP ranges) and by request facts. Never by person. The privacy contract of ADR-0016 stands: no raw IP, no raw User-Agent, no cookies, daily pseudonymous client only.
4. **Never lose history.** Method changes are dated boundaries in the public series, never deletions or silent recomputations. The repository history plus the ADR thread is the audit trail.
5. **Honest and believable beats flattering.** An independent check (a script-based counter, a citation index, a verified link) outranks an internal count. Where no independent check exists, say so on the page.
6. **Embrace agent readers and agent citations.** People will increasingly read through agents. The site should make itself easy for an agent to read correctly and to cite correctly, and should count that reading and those citations as the audience they are.
7. **Credibility comes from persistent identifiers and verification, not from formatting.** A BibTeX block is a handle; what makes it respectable is the identifier behind it and the index that can count references to it.

## Decision direction

### A. Audience composition replaces the Browsers versus Browser-like split

ADR-0016.2's evidence columns stay. The public partition changes from "browser or not" to a set of reader kinds, each defined by request facts, each with one stored reason code per row (the GoatCounter `isbot.Result` model, see research artifact `04`). Candidate kinds, names to be settled in `TASK-0105` with citable vocabulary from device-detector's bot categories and Cloudflare's verified-bot categories:

| Kind | Defining facts |
|---|---|
| Browsers | browser User-Agent, navigation-shaped request, network not on the hosting list; or legacy beacon row; or pre-evidence edge row (disclosed) |
| Cloud browsers | browser User-Agent, navigation-shaped request, network on the hosting list. Most likely an agent's browser. Counted as audience. |
| HTTP clients | browser User-Agent without the request headers every current browser sends |
| Headless browsers | self-declared (HeadlessChrome, Playwright, and similar in the User-Agent) |
| AI assistants | on-demand fetchers acting for a person (ChatGPT-User, Claude-User, Perplexity-User and similar, per vendor documentation) |
| AI crawlers | training and search-index crawlers (GPTBot, ClaudeBot, CCBot, and similar) |
| Search crawlers | Googlebot, Bingbot, and similar |
| Previews and feeds | link-preview fetchers, feed readers, monitors |

How header absence is treated is gated by `TASK-0101`: the open-source consensus is that missing Fetch Metadata is a weight, not a verdict, because WebViews omit it, and the rule must be checked against this site's referred traffic before it convicts anything.

### B. Agents identify themselves; the site verifies and names them

Investigate Web Bot Auth (HTTP Message Signatures for automated traffic) so that agents which sign requests are named exactly on the stats page. Investigate vendor-published IP ranges for the named AI fetchers. Where an agent declares itself and the declaration verifies, show the name. Where it does not, show the request facts and nothing more.

### C. Articles become citable

Each post gets a stable citation: author, title, date, canonical URL, and a persistent identifier once one exists (DOI via Zenodo or Rogue Scholar, decided in `TASK-0106`). Publish it three ways: a "Cite this" block on the page (BibTeX, APA, plain), machine-readable metadata in the page head and JSON-LD (`citation_*` meta tags, `identifier`, `rel="cite-as"`), and in the Markdown endpoint and `llms.txt` so an agent that reads the article can cite it without guessing. Consider content negotiation so a request with `Accept: application/x-bibtex` or CSL-JSON receives the citation directly, the way DOI resolvers do.

### D. References are counted only when verified

There is no citation index for blogs. Build "Referenced by", not "Cited by": a per-post count composed from sources that can be checked. Candidates: Webmention (W3C), where the citing page notifies the site and the site fetches the source and confirms the link exists before counting; distinct external referrer hosts already in D1; AI-assistant fetches and referrals from chatgpt.com and perplexity.ai per post already in D1; Search Console and Bing links reports; OpenAlex citation counts once a DOI exists. Each source is labelled on the page. The word "cited" is reserved for counts that come from a citation index.

### Currency check (added 2026-09-03 03:00 UTC)

Goga asked whether sections C and D are modern for September 2026. Honest answer: DOIs, BibTeX, Highwire tags, ORCID, and Webmention are durable scholarly-web plumbing from 2009 to 2019. They remain what citation indexes count (OpenAlex counts blog DOIs today, artifact 05), but they are not agent-native. The agent-native layer (signed agent requests, agent browsers, site-side agent interfaces, AI-preference and licensing signals, agent-era attribution) moves monthly and the assistant's knowledge ends around June 2026. A dated survey of that layer is in progress and will be saved as artifact 07; sections C and D are to be re-read against it before anything is built. Rule: durable identifiers stay as the floor, agent-native interfaces are the target, and nothing ships on the assistant's memory alone.

## Non-goals

- Blocking, challenging, or rate-limiting any reader because of how it reads.
- Any per-person identification, fingerprinting, or cross-day identity.
- Claiming that a fetch is a read, that a citation is agreement, or that a count is quality.
- Buying or importing third-party bot lists or datacenter lists wholesale; every list entry stays hand-verified.
