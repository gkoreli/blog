# ADR-0016.4: Owner Exclusion and Network Evidence After the First Public Article

## Status

Proposed — 2026-09-03. Extends ADR-0016.2 (browser evidence) and ADR-0016.3 (audience composition). Triggered by reading the first article whose audience arrived from outside: post 023, published 2026-09-03 06:00 UTC, submitted to Hacker News at 06:15 UTC.

## Context

The public stats page showed **42 views** in the Browsers class for `/which-ai-fetchers-send-which-headers`. Goga asked whether those are real readers. Reading the 42 rows one by one, against registry holders from RIPEstat, gives this:

| Group | Rows | What they are |
|---|---:|---|
| The author | 7 | AS62887 WhiteSky, one daily client id, 05:06 to 06:37 UTC, including the click on his own X link |
| Infrastructure, not readers | 14 | Internet Archive ×2; Hivelocity ×4 (two exact-duplicate timestamps, referrer `hnagg.com`); Sprious/Rayobyte ×1 (referrer `hacker-news.firebaseio.com`, which no browser sends); Byteplus ×2; HZ Hosting ×1; IT7 Networks ×1; Black Mesa ×1; Hurricane Electric ×2 |
| Plausible readers | 21 | Consumer and university networks: Charter, Comcast, Cox, Windstream, TELUS, Vodafone ×2, Free SAS, Virgin Media, RWTH Aachen, Atria Convergence, China Mobile, China Telecom ×2, SK Broadband, HGC, NETV, Hulum Almustakbal, Akamai mobile, and two small ASNs. Eleven of them carry a `news.ycombinator.com` referrer |

So the Browsers class over-counts by about half on this page, and the largest single source of error is the author's own traffic. Three defects produced that.

**1. Owner exclusion is an exact IP match against a static list.** `extractRequestMetadata(request, env.OWNER_IPS)` sets `isOwner` with `owners.includes(ip)`. The author's home address is dynamic, so the list goes stale silently and his own reading is published as audience. This was first seen on 2026-09-03 during the ADR-0016.2 deploy ("owner marking did not catch my requests from AS62887") and was not fixed; it has now inflated the first article that anyone else read.

**2. The hosting network list is missing providers that demonstrably carried automation to this site.** `HOSTING_NETWORKS` has 23 entries. Five networks in the 42 rows are hosting or proxy businesses and are absent: Hivelocity (AS29802), Sprious (AS64267, the Rayobyte proxy business), Byteplus (AS150436), HZ Hosting (AS59711) and IT7 Networks (AS25820).

**3. An archiver is stored as a browser.** Internet Archive (AS7941) fetched the page twice within four seconds of the Hacker News submission, using a browser User-Agent, so `readerkind.ts` recorded `browser`. Confirmed as the Wayback Machine: the snapshot at `web.archive.org/web/20260903061604/` carries the timestamp 2026-09-03 06:16:04 UTC, matching the second row to the second. Save Page Now is not a reader.

Two known problems recurred and are recorded here rather than fixed:

- **Cloudflare's `as_org` names the IP block's registered organisation, not the announcing network.** Two rows say `Chiron Software LLC` where the registry says Cox Communications, and one says `AviationAI` where the registry says Comcast. The stats page displays `as_org`, so the public page shows names that suggest hosting where the network is a consumer ISP. Post 023 documents the same mismatch for nine of sixteen Grok exits.
- **Duplicate requests at identical timestamps.** The Hivelocity client produced two rows at exactly 06:20:00 and two at exactly 07:25:00. Each is a real request; nothing is deduplicated.

## Decision

### A. Owner exclusion is marked by the owner, not inferred from an address

Add an authenticated endpoint that records the caller's current daily client id as the owner's for that UTC day, and exclude those ids in the read model.

- `POST /api/owner` with the existing `ADMIN_SECRET` as a bearer token. It computes the caller's `daily_client_id` exactly as ingestion does and inserts it into a new `owner_clients(daily_client_id, utc_date, marked_at)` table.
- The stats read model excludes rows whose `daily_client_id` appears in `owner_clients`, in addition to the existing `is_owner = 0` filter.
- Rows are **not** mutated. `is_owner` keeps recording what ingestion knew at write time; the exclusion is a read-model fact with its own timestamped audit row. Tenet 4 of ADR-0016.3, never lose history, is why.
- `OWNER_IPS` stays. It is still correct when the address is stable and costs nothing.

Limits, stated on the stats page: the marking covers one browser, one address and one UTC day. A changed address mid-day needs a second call. This narrows the error; it does not eliminate it.

### B. Hosting networks: five additions, three refusals

Added, each verified against Team Cymru and RIPEstat on 2026-09-03. The ADR-0016.2 test applies: a network is added only when it is a hosting or data-centre business, never when it sells consumer VPN exits that a reader might sit behind. Rayobyte sells residential proxies as a separate product; AS64267 is its data-centre ASN, which is what this rule convicts.

| ASN | Registry holder | Evidence on this site |
|---|---|---|
| 29802 | HIVELOCITY, Inc. | four requests, two pairs at identical timestamps, referrer `hnagg.com` |
| 64267 | Sprious LLC (Rayobyte data-centre proxies) | referrer `hacker-news.firebaseio.com`, a JSON API host no browser sends as a referer. Independently documented as Rayobyte proxy infrastructure by [Qurium Media Foundation](https://www.qurium.org/weaponizing-proxy-and-vpn-providers/rayobyte/); about 73,000 IPv4 addresses with no day/night variation, the shape of a data centre rather than a consumer network |
| 150436 | Byteplus Pte. Ltd. (ByteDance cloud) | two requests in the same second from two client ids |
| 59711 | HZ-EU-AS HZ Hosting Ltd | browser-shaped request, hosting-only network |
| 25820 | IT7NET, IT7 Networks Inc | browser-shaped request, dedicated-server business |

Refused, with the reason:

- **AS6939 Hurricane Electric.** Transit plus a free IPv6 tunnel broker that real people use. Convicting it would convict readers, which is the same rule that kept M247 and Datacamp out in ADR-0016.2.
- **AS7941 Internet Archive.** Not hosting. Handled in section C.
- **AS46997 Black Mesa Corporation.** One request, unclear business. Not enough evidence.

### C. Archivers are named as archivers

Introduce `ARCHIVER_NETWORKS`, initially `AS7941 → internet-archive`. A request from an archiver network that carries no vendor agent token is stored as `preview-or-feed` with reason `archiver-asn:7941`, the group that already holds link-preview fetchers, feed readers and monitors. A dedicated `archiver` reader kind is deliberately not added: the public partition should change only when the volume justifies a new column, and two requests do not.

### D. History is corrected by a dated, disclosed migration

Migration `0008` reclassifies only the rows whose ASN is in the newly added hosting or archiver sets, from the beginning of the table to the migration date. This follows the precedent of migrations 0006 and 0007: a backfill is allowed when the method changed, when it is recorded in a migration file, and when the ADR names the date boundary. The boundary is 2026-09-03. Nothing is deleted; `page_views` remains the lossless archive.

### E. Not decided here

- **Whether the stats page should show the registry holder instead of Cloudflare's `as_org`.** The registry holder is the more accurate name, but resolving it needs an external lookup and a stored mapping. Recorded as a task, not decided.
- **Whether a `verified reader` signal is worth building.** The 42-row read shows that the honest ceiling of request evidence has been reached: a consumer network plus browser headers plus a plausible referrer is as far as the edge can go. Anything stronger needs a client-side confirmation, which ADR-0016.1 rejected once. Revisit only if the Cloudflare Web Analytics calibration in TASK-0104 shows a gap larger than this correction explains.

## Consequences

- The Browsers number on every page drops. On post 023 it drops from 42 to about 21, and the article's own claim that the class is a lower bound of unknown accuracy is strengthened rather than weakened.
- The composition table gains rows in Automation and Preview or feed.
- Post 023's `08-metrics.md` is corrected with the row-level read, and its snapshot table now records both the number the stats page showed and the number the rows support.
- The next monthly re-probe (TASK-0116) and the external calibration (TASK-0104) both compare against the corrected series, and the correction date is disclosed alongside them.
