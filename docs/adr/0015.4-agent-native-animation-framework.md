# ADR-0015.4: Make `@gkoreli/animation` an agent-native framework experiment

* **Status:** Accepted
* **Date:** 2026-08-26
* **Owner:** Goga Koreli
* **Decision Type:** Package ownership, authoring contract, runtime architecture
* **Amends:** ADR-0015, ADR-0015.1, ADR-0015.2, ADR-0015.3
* **Related:** ADR-0012

---

## Context

`gkoreli.com` is a blog, a publication, and a personal museum. Selected articles may use motion as part of their preamble, but animation is not a site-wide requirement.

`@gkoreli/animation` is a separate experiment. Its architecture must not depend on articles, blog metadata, the publication layout, or `@nisli/core`. The blog is its current reference host: it provides the Animations Lab and may mount scenes behind selected article preambles. That use does not make the package a blog subsystem.

The first implementation proved several useful ideas:

* semantic scene declarations
* fields, zones, emitters, materials, timelines, and ordered effect pipes
* typed-array particle storage
* zone occupancy and coarse events
* glyph-aware text emission
* renderer-neutral text primitives
* a Pixi adapter isolated behind a package boundary

It also exposed four architectural failures.

1. Two public authoring generations coexist. One compiles `SceneDefinition`; the older article-scene builder stores effects and timelines that no executor consumes.
2. Invalid references and unsupported declarations fail silently. This is especially unsafe for agent-generated scenes.
3. Runtime semantics outran renderer semantics. DOM/CSS stage art made zones and fractures look implemented when the package did not render them.
4. The package was described as publication-specific even though the intended experiment is broader and independently owned.

The Animations Lab is therefore both a visual laboratory and a conformance surface. It must expose what the runtime can actually compile, inspect, simulate, and render.

---

## Decision

Build `@gkoreli/animation` as a narrow, agent-native TypeScript animation framework with a renderer-neutral scene contract and replaceable render backends.

The blog remains a selective consumer. Current article preambles may keep their existing Canvas 2D or CSS implementations. No migration is required until a preamble benefits from the new framework. Default pages must not load the framework or Pixi.

### Package boundary

The package owns:

* scene declarations and stable semantic IDs
* validation and structured diagnostics
* compilation and inspectable execution plans
* deterministic seeds and explicit time inputs
* simulation stores and ordered effect execution
* renderer-neutral visual primitives
* mount lifecycle, visibility, reduced motion, frame observation, and disposal
* renderer adapter contracts

The package does not own:

* article metadata or article scene registries
* blog routes, preamble selection, or DOM layout
* lab controls, explanatory copy, or promotion status
* Pixi objects outside `renderer-pixi`
* a general-purpose game engine or visual editor

Concrete lab and article scenes belong to the consuming application.

### Agent-native contract

“Agent-native” means an agent can generate, inspect, patch, validate, and verify a scene through stable machine-readable contracts. It does not mean natural-language execution, an embedded model, or an MCP server inside the runtime.

The canonical authoring artifact is a versioned, plain-data scene declaration:

```ts
interface SceneDefinition {
  version: 1;
  id: string;
  seed: number;
  textSources: readonly TextSourceDefinition[];
  polylines: readonly PolylineDefinition[];
  fields: readonly FieldDefinition[];
  zones: readonly ZoneDefinition[];
  emitters: readonly EmitterDefinition[];
  materials: readonly MaterialDefinition[];
  systems: readonly ParticleSystemDefinition[];
  timelines: readonly TimelineDefinition[];
}
```

The TypeScript builder is authoring syntax over that data. It is not a second source of truth.

Every declaration must support:

* a schema version
* a stable scene ID and explicit seed
* stable semantic IDs for every referenced object
* deterministic array order where execution order matters
* full pre-allocation validation
* diagnostics with a code, path, severity, and precise message
* a JSON-compatible manifest that lists systems and ordered stages

Compilation must reject duplicate IDs, dangling references, unsupported timeline sources, invalid ranges and capacities, renderer-layer collisions, unsupported coordinate combinations, and illegal operator/channel combinations. It must not silently skip a system or stage.

### Execution model

The canonical frame order remains explicit:

1. sample time and external modulation inputs
2. consume scheduled bursts and coarse triggers
3. spawn particles
4. apply field influence
5. integrate motion
6. compute zone occupancy
7. emit coarse semantic transitions
8. execute transition stages
9. execute continuous stages
10. decay and retire state
11. prepare renderer-facing primitives and batches
12. render through the adapter

A pipe may contain stages from more than one execution phase. Compilation classifies stages, not the entire pipe, while preserving authored pipe and stage order in the inspection manifest.

Time and randomness are inputs. `requestAnimationFrame` belongs to `mountScene`; scene execution must not read wall-clock time or unseeded randomness directly. A later increment will add fixed-frame seeking, `renderFrame`, state snapshots, and checkpoint hashes. The v1 declaration and manifest must leave that path open now.

### Renderer boundary

Pixi remains the first renderer backend. It is useful plumbing, not the scene language.

The renderer-neutral vocabulary starts with:

* text primitives
* visible zone primitives
* particle batches and velocity trails
* polyline primitives for fractures, arcs, and connectors

Material channels must either produce visible renderer behavior or fail validation as unsupported. DOM overlays may frame a lab stage, but they cannot stand in for a runtime primitive.

### Inspection protocol

`analyzeScene()` is the first inspection surface. It returns:

* schema version, scene ID, and seed
* substrate counts
* systems, capacities, emitter/material references
* pipe IDs and stage IDs
* authored order
* execution phase, condition, and operation
* structured diagnostics

Future inspection may add resolved dependency graphs, live frame statistics, bounded event traces, state snapshots, and renderer-neutral frame hashes. These are runtime outputs, not lab-only inventions.

### Lab policy

The Animations Lab owns scene selection, controls, copy, metrics presentation, and visual judgment. It consumes the same public package APIs that another application would consume.

A lab experiment is real only when:

* its visible semantics come from runtime primitives
* its controls change actual declarations or runtime inputs
* its metrics come from runtime frames and live state
* pause survives viewport changes
* reduced motion produces a meaningful static result
* reset restores declared defaults
* its scene manifest compiles without diagnostics

The lab may show fewer experiments rather than preserve a convincing fake.

### Blog integration policy

Animation remains optional and article-local.

* Existing preamble animations stay in place until a concrete migration earns the cost.
* A future framework-backed preamble gets its own page-specific client entry or scene key.
* The shared immersive bundle must not import Pixi for every immersive article.
* Article HTML and text remain complete without JavaScript.
* No animation is added to archive or default pages merely to increase framework usage.

## Immediate implementation increment

The first accepted increment is **Scene Contract and Truthful Lab v1**:

1. remove the unused article-scene grammar, legacy effect descriptors, and legacy timeline exports from the package surface
2. add scene version, seed, structured analysis, diagnostics, and an inspectable manifest
3. split mixed pipes at stage granularity
4. make emitter burst one-shot rather than per-frame
5. clear stale zone occupancy when particle slots are reused
6. render material emissive and blend hints
7. compile visible rectangle zones into renderer-neutral primitives
8. add renderer-neutral polylines and use them instead of CSS fracture art
9. make explicit pause survive visibility transitions and expose real frame callbacks
10. derive lab controls, snapshots, and metrics from declared/runtime state

Stop after these invariants hold. Do not add a state-machine dependency, editor, shader graph, general ECS, or more lab experiments in this increment.

## Considered systems

No surveyed project becomes a dependency. Each contributes one tested idea.

| System | Keep | Reject |
| --- | --- | --- |
| [Motion Canvas](https://github.com/motion-canvas/motion-canvas) | code-first composition, seeded replay, editor/runtime separation | arbitrary generator control flow as the only inspectable representation |
| [Theatre.js](https://github.com/theatre-js/theatre) | renderer-neutral animated values, explicit playhead, custom clock | opaque track IDs and an editor export as a second source of truth |
| [Rive](https://github.com/rive-app/rive-wasm) | structural inspection and semantic editing capabilities | binary `.riv` as canonical source and editor-required agent access |
| [Lottie](https://github.com/lottie/lottie-spec) / [dotLottie](https://github.com/LottieFiles/dotlottie-web) | schema versions, explicit frame domain, markers, seeded state machines | abbreviated After Effects schema and packaged ZIP as authoring source |
| [Remotion](https://github.com/remotion-dev/remotion) | frame-as-input, seeded randomness, single-frame verification | React as the runtime or component code as the whole intermediate representation |
| [XState](https://github.com/statelyai/xstate) | declarative coarse states, pure transitions, simulated clock, inspection | actor machinery or per-particle event traffic |

The shared lesson: editable source, compiled plan, injected time, explicit seed, structural inspection, and deterministic verification are separate concerns. Keep them separate in this framework.

## Relationship to earlier decisions

* **ADR-0012** remains the historical decision behind the current blog-local Canvas 2D preamble runner. It is not the architecture for `@gkoreli/animation`.
* **ADR-0015** remains authoritative for Pixi as an isolated backend, but its publication-specific package scope is superseded.
* **ADR-0015.1** remains authoritative for the five substrates, data-oriented hot paths, coarse events, and ordered pipelines. This ADR adds the versioned agent contract and mandatory diagnostics.
* **ADR-0015.2** remains the lab experience direction. Its experiment count is no longer an acceptance criterion; truthful runtime semantics are.
* **ADR-0015.3** remains authoritative for renderer-neutral text, zone, trail, and polyline primitives. This ADR removes article semantics from the package and makes those primitives part of the independent framework contract.

## Consequences

### Positive

* Agents and humans share stable IDs, diagnostics, and inspection vocabulary.
* The package can evolve independently from the blog.
* The lab becomes technically honest.
* Renderer replacement remains possible.
* The blog can use the framework without paying for it everywhere.
* Deterministic frame verification has a clean architectural path.

### Negative

* Validation and manifest design add work before more effects appear.
* Existing proposed ADR language and package guidance require correction.
* The lab may temporarily look smaller while fake visual layers are removed.
* Current article preambles and the new framework remain two stacks until a real migration is justified.

### Risks

* A manifest can become a second scene model. Mitigation: it is derived from `SceneDefinition` and never authored independently.
* “Agent-native” can become feature inflation. Mitigation: require every capability to improve structural editing, inspection, or deterministic verification.
* Renderer-neutral APIs can merely wrap Pixi. Mitigation: no Pixi imports or Pixi types outside `renderer-pixi`.
* Declarative syntax can hide runtime cost. Mitigation: manifests expose capacity and stage order; runtime plans remain explicit and data-oriented.

---

## Decision summary

`@gkoreli/animation` is an independent agent-native framework experiment. `gkoreli.com` is its current laboratory and museum, not its architectural owner.

The framework speaks versioned scene data, stable semantic IDs, structured diagnostics, explicit time and seed, ordered pipelines, inspectable plans, and renderer-neutral primitives. The blog uses it only where motion earns its place.
