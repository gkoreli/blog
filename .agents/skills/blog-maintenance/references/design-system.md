# Design System

Use [shared tokens](../../../../packages/design/tokens.css), [layout CSS](../../../../packages/blog/src/styles/layout.css), and the [page shell](../../../../packages/blog/src/templates/page.ts). Decision rationale is in [ADR-0007](../../../../docs/adr/0007-navigation-and-layout.md), [ADR-0009](../../../../docs/adr/0009-layout-system.md), [ADR-0013.1](../../../../docs/adr/0013.1-publication-visual-layer.md), and [the reading/design contracts](../../../../docs/adr/0024-publication-reading-and-design-contracts.md).

## Layout

- Keep sidebar navigation visible on articles and other pages using the shared shell. Pass `currentSection` so articles highlight their section.
- Use the centered grid `1fr minmax(0, var(--content-max)) 1fr`. The sidebar sizes to content and aligns right inside `.sidebar-wrapper`; the opposite column balances it.
- Dense analytical pages can use the shared `layout-report` variant: the same sidebar and mobile shell, a wider comparison area and a small right gutter, capped at 1440px. Keep the default editorial grid for prose pages. Use the extra width for data, while constraining method paragraphs to a comfortable line length.
- The sticky sidebar uses section spacing. Preserve its header, navigation, follow links, and social controls. Keep a compact labeled Search link beside Contents on desktop, and the search icon beside the phone menu. Keep search with the primary navigation; the right rail belongs to article contents.
- Keep project links on About, with Design Language and Animations Lab under its site-exploration section. Preserve the Nisli footer credit. [ADR-0018](../../../../docs/adr/0018-nisli-ssg-and-publication-navigation.md) records the placement decision.
- At 768px the shell becomes one column with a mobile header and burger menu. Components may have additional breakpoints. Prefer intrinsic sizing where possible.
- The burger menu must support Escape, scroll locking, and `aria-expanded`.
- The homepage shows a featured article followed by a chronological stream. `/about` holds the biography, projects, and contact links.
- Preserve the sidebar tagline: “Where excitement ends, depth begins.”

## Typography and color

- Tool interfaces use the publication’s Lora for editorial text and monospace for controls, numbers and metadata. Scope sizing and spacing to `.tool-app`; do not inherit article spacing through `.post-content`. Prefer typographic hierarchy, open rows and neutral horizontal rules over nested cards. Do not add colored left-border callouts. Quota exhaustion is a neutral state with a reset time and useful next actions.
- Use Lora with a Georgia fallback for article body text. Use monospace for code and compact UI metadata. Keep body line height at least 1.7 and headings tighter.
- Use the same typography in both themes. Honor saved theme preference, then system preference; light is the base CSS palette.
- Light background: `#faf8f5`; dark background: `#1a1a1a`. Light-theme primary text is `#2d2a24`; secondary/metadata ink is `#625d53` in light and `#aaa496` in dark. Use the semantic text, section-ink, on-action and on-header roles on their tested surfaces. Decorative accent colors remain separate. Do not fade text-bearing containers with opacity; quiet metadata through scale, spacing and hierarchy. The [foundation test](../../../../packages/blog/test/design-foundations.test.ts) checks normal text at 4.5:1 and control boundaries at 3:1 on the supported neutral surfaces.
- Link accent: `#1a6b4e` in light mode and `#6ec9a8` in dark mode.
- Brand gradient: `#1a6b4e` → `#6ec9a8` at 60% → `#93c5fd` at 100%. Reserve the sky-blue color for the gradient; use named section tokens for other accents.
- Section accents are warm gold for Essays, blueprint blue for Engineering, and rust for OSS Radar.

## Code and controls

- Highlight code at build time with Shiki's `github-light` and `github-dark` themes and `defaultColor: false`. CSS selects the inline theme variables from `data-theme`; do not add client-side highlighting or re-render code to switch themes.
- Give code blocks enough width and padding to read comfortably within the content column.
- Use SVG icons from `public/icons/`, not emoji. Frequent controls use the shared 44px target while their glyphs stay 16px or 20px. Sidebar social links and the single appearance button share the quiet [icon-control](../../../../packages/blog/src/styles/utility-icon.css) treatment: equal targets and glyphs, neutral ink, a flat hover surface and visible keyboard focus. The appearance button names the mode it will switch to; avoid a separate raised container or redundant native hover titles. [Theme presentation](../../../../packages/blog/src/styles/theme-toggle.css) consumes that shared control. Form boundaries use the control-border role. This target scale is an ergonomic design choice; do not present it as an accessibility certification.
- Utility icons use the shared [template](../../../../packages/blog/src/templates/utility-icon.ts): a 24-unit grid, 1.5-unit round strokes and inherited single color. Use 16px beside text or 20px in controls, with an accessible name on the control. Keep gradients for identity marks; keep technical illustrations separate from utility glyphs.
- Use the sparkle separator between appropriate publication areas. Tags render as `#hashtags`, with the gradient on the hash, rather than badges.
- Add motion only when it helps comprehension. Preserve readable content before interactive components load.

## Interactive navigation

- A single-destination invitation or navigation choice uses one native link with a concise name. Its hit area includes the artwork and padding, with one tab stop and visible focus across the surface. Preserve native keyboard activation.
- Keep forms and secondary controls outside that link’s overlay. Use a separate interactive region when a surface contains multiple actual actions.
- Use the shared [navigation choice template](../../../../packages/blog/src/templates/navigation-choice.ts) and [styles](../../../../packages/blog/src/styles/navigation-choice.css) for compact tiles or illustrated rows. Use the illustrated homepage invitation for one featured destination. Design Language renders the same components as their callers.
- Linked headings and full-surface states provide the navigation cue. Do not append decorative direction arrows or add a second action to a single-destination choice. Use icons only when they convey an action or object.
- The [compact navigation study](../../../../packages/blog/prototypes/tools/design-language-study.md#accepted-implementation--november-11) records the selection, rationale and earlier alternatives. Compact tiles, readable 14px descriptions, 12px metadata, 16px tile padding and 10px corners are the accepted tools-directory pattern.

## Reading and discovery

- The [reading document module](../../../../packages/blog/src/lib/reading-document.ts) owns stable section IDs, outline preparation and table framing before search indexing. Preserve existing IDs, reject duplicates in final documents, and keep preparation repeatable. The native inline contents and wide reading rail consume one outline; do not maintain another manually copied article index.
- The [table frame](../../../../packages/blog/src/lib/reading-display.ts) owns a focusable scrolling region, overflow cue and retained first-column identity for rectangular comparisons. Preserve every cell, caption, link and merged relationship. The [browser enhancement](../../../../packages/blog/src/client/reading.ts) hides a cue when the content fits. Do not use truncation or hidden detail rows to make data fit.
- Page assembly owns exactly one research footprint. A custom article can export `researchNotes()` for its measured explanation; the shared renderer owns the frame, totals, native times and common provenance limits. Preserve the explanation in HTML and Markdown, and check representative real articles when changing that contract.
- Archives reuse [the shipped search](../../../../docs/adr/0023-publication-passage-search.md), with explicit section scope and independent topic links. Keep the complete chronology and native GET fallback. Reading navigation and overflow hints are excluded from the search corpus.
- Privacy retains every technical disclosure below a linked overview. About uses the shared navigation rows with distinct project drawings. The lab's title and introduction use the interface scale so the actual experiment enters view promptly. Design Language renders the same components as their page callers.

## Time presentation

Use the [shared time core](../../../../packages/time/README.md) for every displayed instant, calendar date and timezone operation. Server-rendered instants use the [UTC fallback adapter](../../../../packages/blog/src/lib/local-time.ts) and native `time` elements marked `data-local-time`; [browser enhancement](../../../../packages/blog/src/client/local-time.ts) localizes them. Dynamic report/feedback renderers use that same adapter. Keep UTC instants structured until the presentation boundary. In Nisli templates use native elements rather than interpolating a raw-markup object into a text binding.

Publication dates and version identifiers are calendar metadata. Do not shift them, localize raw JSON/HTTP evidence or derive a timestamp from a date-only value for ordinary UI display. Database UTC defaults, epoch expiries, signature clocks, fixed source calendars and release/admission policy retain their domain meaning; localize the instant shown to the viewer. Do not add separate Intl/Date locale formatters in application modules.

## Reports and results

- Keep check results, their evidence and actionable next steps visible while scrolling. Use section headings and native jump links for longer reports. Reserve disclosures for method explanations and raw data, rather than hiding passed, failed, optional or unassessed results.
- Group related checks with a compact points summary. State each outcome in words; color is a secondary cue. Keep unknown points separate from failed points and preserve the observation date and scope near the overview.
- The enhanced and server-rendered access reports use the same escaped [report template](../../../../packages/blog/src/lib/site-audit-report.ts). Design Language renders its check-group component with explicitly illustrative inputs.

## Analytical reports

- Put the principal metrics and trend chart before detailed evidence. Use visible, named sections and native jump links for longer reports. Keep report results in the page; disclosures can hold alternate chart data or operational method details.
- Independent reports use [context headers and scope facts](../../../../packages/blog/src/templates/report-context.ts), with separate calendars/windows/control ownership. Use the [shared section index](../../../../packages/blog/src/templates/section-navigation.ts) and its [enhancement](../../../../packages/blog/src/client/section-navigation.ts); narrow strips scroll with full labels instead of squeezing targets or wrapping a lone choice. A total with several related source categories uses the shared responsive metric-summary layout, as on Article reach.
- Keep the metric label, number and definition together. Client identifiers rotate daily in UTC and are not people; request categories describe signals and declared roles. Put the selected scope, reporting period, partial-bucket boundary and calculation time near the data they qualify. Use the [shared time kernel](../../../../packages/time/README.md) for localized timestamps and calendar dates. Daily and hourly reports must select and group actual viewer-local intervals; do not relabel UTC aggregates. Keep chart, table, period and update labels in the same selected timezone, with explicit zone context. Distinguish the report calculation time from the current clock.
- Use the shared [data-display templates](../../../../packages/blog/src/lib/data-display.ts) and [styles](../../../../packages/blog/src/styles/data-display.css) for metric tiles and comparison rows. Print the value above a short meter in a fixed measurement column; compare against the largest visible row. Never paint data fills behind titles or paths. Use quiet title styling, with a link underline on hover or keyboard focus. The title filters the report; a separate Visit control opens the page. Use the shared page glyph under a Visit column heading on desktop and a text label on phones, with visible focus and at least 44px targets.
- Label independent filter groups explicitly. Keep a short set of report choices visible using the shared native [radio-group template](../../../../packages/blog/src/templates/report-filters.ts) and [control styles](../../../../packages/blog/src/styles/report-controls.css). Use a compact selected surface inside a target at least 44px tall, with native arrow-key navigation and visible focus. Let short labels wrap as a group; at phone widths keep the six traffic choices in two aligned rows. Preserve full category names and evidence boundaries in the results and accessible descriptions. Reserve a native select for longer option sets. Distinguish chart series with line style as well as color, retain an accessible data table, and show missing evidence without treating it as zero or false.
- Lead each detail section with its results. Put coverage counts in a labeled definition list using the shared data-facts renderer; preserve zero values and state whether facts overlap. Follow with a visible [reading note](../../../../packages/blog/src/templates/data-note.ts), in short paragraphs at a readable size. Do not scatter dense method text between a heading and its data or squeeze long paths into narrow comparison columns. Organize long methodology into named, directly linked topics without removing its evidence boundaries.
- Use consistent section gaps and matching label/value headers. Pair related short comparisons on wide screens; constrain standalone short lists rather than stretching a few words across the report. Let fact lists and reading notes respond to their container width. Keep notes with their data in the reading order, including on phones.
- Distinguish ranked comparisons, disjoint distributions and overlapping diagnostic facts. Do not draw a ranking bar behind every coverage indicator. Use contextual reading-note titles. A readable page title and its exact path share one filter link, with Visit kept separate. Headers and row columns share the same layout; align titles and counts at the start of phone rows.
- The shared grouped-evidence renderer puts common classification context in native row-group headers, retains every evidence record and prints totals only for disjoint observations. Do not truncate evidence labels or verifier versions to make a table fit; keep recorded date-version identifiers together. In smaller report containers, show the identity and pinned request count, wrap captions and keep extra columns keyboard-scrollable with a visible scroll cue. Wide report tables keep column and current-group headings below the sticky section index. The [visual QA study](../../../../packages/blog/prototypes/stats/visual-qa-study.md) records the pattern and preservation comparison.
- Long reports keep a compact sticky section index, with a current-location cue and enough anchor offset to leave headings visible. Loading, empty and error states retain a useful place in the layout. Verify these states and both themes with real component markup and a labeled saved report before delivery.
