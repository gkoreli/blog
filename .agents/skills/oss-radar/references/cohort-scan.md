# Cohort scan

## Record the source

Record the source, author, date, cutoff, inclusion rule, and total project count.

Check the full set. If full review is not practical, define a repeatable sample and state its size and limits.

## Build the inventory

Collect each project and repository before choosing projects to feature. Keep the full inventory in research notes.

Give projects unequal space. Leave a project out of the prose when it adds no new fact.

For a full entry, cover:

- **Solves:** the exact problem;
- **For:** the likely user;
- **Why care:** what changes if it succeeds;
- **Our take:** one clear verdict;
- **Hard question:** one unanswered risk;
- **From the code:** one fact beyond the README.

Use an outside source only when it changes the verdict.

## Find patterns

Derive patterns from the full inventory or stated sample, not only from selected standouts.

For each pattern:

- give the denominator;
- name the projects that support it;
- add one checkable fact;
- test the source's likely explanation against one sound rival when the evidence supports it;
- state what would prove the claim wrong.

Do not restate the project entries.

## Close once

End with one thesis and, when useful, up to two follow-up topics. Do not force a `try now` table or release gates onto a cohort scan.

Verdict labels such as `BOLD BET` or `META PATTERN` are optional. Use one only when named evidence supports it.

## Review

- [ ] Source, cutoff, inclusion rule, and total count recorded
- [ ] Full inventory or repeatable sample checked before selection
- [ ] Unequal projects receive unequal space
- [ ] Pattern claims include a denominator
- [ ] Patterns add facts beyond the entries
- [ ] Main pattern tests a sound rival explanation
- [ ] Source bias or sample limits appear once
- [ ] Final thesis can be proved wrong
- [ ] Follow-up topics support later research
