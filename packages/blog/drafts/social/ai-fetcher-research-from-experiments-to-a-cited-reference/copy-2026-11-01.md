## r/CloudFlare technical discussion

Title: One Grok prompt produced 11 browser-style requests to my Cloudflare Worker

Flair: Discussion.

All 11 were unsigned, had no agent declaration, and were stored as Browser by my own collector. Ten omitted `Sec-Fetch-User`; one sent `?1`.

This was a controlled Nov 1 test: signed-in Grok on X, Auto, with Codex operating the interface. I assigned an article URL only to that chat and asked for its H1 plus a sentence from a named section. It quoted the sentence correctly, but used the document title as the H1.

At the Worker, all 11 requests returned HTTP 200. They declared Chrome 142/143/156 or Safari 26.2. Codex traced each invocation to its acknowledged insert, then read back the exact D1 rows. The full stored receipt projections matched all 11 acknowledgements.

Browser is my collector's label. My receipts record Cloudflare's native verified-bot/signed-agent values as unavailable here.

The useful check is:

1. Start the log stream before submitting, and use a unique URL per trial. Don't open that assigned URL directly yourself.
2. Save the assistant's answer separately from the received request. A page fetch and a correct answer are separate outcomes.
3. Join the request to the stored result by its operation/returned-row reference. A query by article pathname alone won't identify the trial.

This is one controlled run, so it gives a counterexample to treating browser headers as proof of a person. It doesn't establish a Grok-wide detection rate. These deliberate tests stay separate from the audience analysis.
