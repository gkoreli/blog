# Dagger Dockerfile COPY

Dagger v0.21.12 shipped November 17 at `6ccf00943c1b4f065dea791b6d6ee956573fdabe`. A CI user reported slower Dockerfile builds after restoring the runner's disk snapshot. They had upgraded Dagger and changed a Dockerfile cache mount, so their report leaves the effects of those changes open. The maintainers isolated a copy-related cost and backported a fix to the 0.21 release line. [Release](https://github.com/dagger/dagger/releases/tag/v0.21.12) · [CI user's report](https://github.com/dagger/dagger/issues/14749) · [Backport and maintainer measurements](https://github.com/dagger/dagger/pull/15040) · [Apache-2.0 license](https://github.com/dagger/dagger/blob/6ccf00943c1b4f065dea791b6d6ee956573fdabe/LICENSE).

The Dockerfile-compatible copy implementation loads and evaluates the source directory, then resolves the selected paths for an unfiltered `COPY`. It combines their paths and content hashes with the destination parent's identity and arguments such as ownership and permissions. The digest becomes the result's cache identity. The filtered path used for `COPY --exclude` still performs the copy and hashes the result. The shipped change also narrows the checksum of a single source file. [Copy identity](https://github.com/dagger/dagger/blob/6ccf00943c1b4f065dea791b6d6ee956573fdabe/core/schema/directory.go#L594-L686) · [Source checksum](https://github.com/dagger/dagger/blob/6ccf00943c1b4f065dea791b6d6ee956573fdabe/core/contenthash.go) · [Engine checksum](https://github.com/dagger/dagger/blob/6ccf00943c1b4f065dea791b6d6ee956573fdabe/engine/contenthash/checksum.go).

## Planned release trial

Build a scratch-based Dockerfile in the v0.21.12 engine. A source stage holds two small files, and the final stage uses `COPY --from` to copy one. Keep the Dockerfile, destination parent and engine fixed. Compare an unchanged run, a change to the file the final stage leaves behind, and a change to the selected file. Read the final bytes and retain the cache trace. If the trace exposes only a whole-build result, use the output comparison as correctness evidence and keep step reuse as a source observation. The first trial is about this one code path. The maintainer's timing and memory measurements used different workloads.
