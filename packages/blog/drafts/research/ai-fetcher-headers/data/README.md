# Data files for "Which AI Fetchers Send Which Headers, Measured on a Live Site"

Captured 2026-09-03 at the Cloudflare Worker in front of gkoreli.com with `wrangler tail --format json`. Generated by `../scripts/export-captures.ts` from the private tail stream; the private stream is not committed.

| File | What it is |
|---|---|
| `captures.jsonl` | One record per request for a probe URL assigned to a specific assistant or baseline during the study (the allowlist is in `../scripts/export-captures.ts`), ordered by time. Fields below. |
| `side-requests.jsonl` | Attributed requests that are not probe URLs: subresources whose `Referer` is a probe URL (headless renders), and requests from `ChatGPT-User`, `PerplexityBot`, `DuckAssistBot` or `GPTBot` during the capture windows (homepage and post follow-ups, the PerplexityBot burst, robots.txt fetches). |
| `stray-probe-requests.jsonl` | Probe-shaped URLs nobody assigned: the article's literal `<name>` template fetched by GPTBot, and URLs assembled from columns of the published CSV by whatever read it. Kept because they show the dataset itself being crawled. |
| `captures.csv` | The same records flattened: one row per request, the most-used headers as columns, remaining header names listed in `header_names`. |
| `asn-holders.json` | ASN → registry holder from RIPEstat `as-overview`, fetched at export time. |
| `firewall-events-2026-09-03.json` | Every Cloudflare edge security event for the zone across the capture window (GraphQL `firewallEventsAdaptive`). Used to rule out edge blocking of probes that produced no origin request. |
| `vendor-ip-lists/` | The vendor-published IP range files as fetched on 2026-09-03: OpenAI `chatgpt-user.json`; Anthropic `bots.json`; Perplexity `perplexity-user.json`, `perplexitybot.json`; Mistral `mistralai-user-ips.json`; DuckDuckGo `duckassistbot.json`; Google `googlebot.json`, `special-crawlers.json`, `user-triggered-fetchers.json`, `user-triggered-fetchers-google.json`, `user-triggered-agents.json`. |

## `captures.jsonl` fields

| Field | Meaning |
|---|---|
| `observed_at` | ISO 8601 UTC, from the Worker event timestamp |
| `probe` | The probe name from the URL (`?probe=<name>` or `/probe/<name>`); attribution key |
| `url`, `method` | As received |
| `headers` | Request headers as received by the Worker, lower-cased, sorted by name. Cloudflare-added headers (`cf-*`, `x-real-ip`, `x-forwarded-proto`, `host`, `connection`) removed. Order is not preserved. |
| `asn` | Autonomous system of the client IP, from Cloudflare `request.cf.asn` |
| `asn_registry_holder` | Registry holder of that ASN (RIPEstat) |
| `cloudflare_as_organization` | Cloudflare's `request.cf.asOrganization` string. Names the organisation registered for the IP block, which differs from the ASN holder wherever address space is resold. Kept as a second fact. |
| `cloudflare_country`, `cloudflare_colo` | Cloudflare geolocation of the client IP and the edge location that served the request |
| `http_protocol`, `tls_version`, `tls_client_hello_length`, `tls_ciphers_sha1`, `tls_extensions_sha1` | Transport facts from `request.cf`; the two digests fingerprint a client stack |
| `client_ip_vendor_lists` | Names of the vendor IP list files the client IP falls inside (empty when none) |
| `client_ip` | Present only when `client_ip_vendor_lists` is non-empty; otherwise `null` |
| `owner_network` | `true` for requests from the site owner's own network (baselines, local tools) |

The files are exports of the requests the article relies on, redacted as described below. They are not a complete log of the site's traffic during the windows.

## Redaction rule

A client address identifies a vendor when it is inside that vendor's published list, and possibly a person when it is not. Addresses are therefore kept only in the first case. Proxy-exit addresses (the Grok runs) are never included; the ASN, its registry holder, and the Cloudflare country stand in. TLS client randoms and exported authenticators are dropped.

## Source and reproduction

These files were generated by `../scripts/export-captures.ts` from the raw `wrangler tail --format json` stream, which is not committed because it contains client addresses for every request, including the proxy exits and ordinary readers. The raw stream is retained privately by the author outside the repository, with these commitments so a later export can be shown to come from the same bytes:

| Private file | Bytes | SHA-256 |
|---|---:|---|
| `tail-live.json` (runs 1–5) | 11,332,772 | `38c262a5b617a04ed5bd83760acffe76d2a0acd6d41dbb0701159f4bdbf54b05` |
| `tail-probe.json` (initial curl check) | 4,110 | `b43fd653591a245d2a31b1b2d8161aba3ec6562d018b176d26d7751435578aa2` |

Recorded 2026-09-03. The vendor IP-list snapshots in `vendor-ip-lists/` and the open-source detector files used in `../04-open-source-validation.md` were archived alongside the raw stream, so the IP matches and detector verdicts can be recomputed against the same inputs even after those upstream files change.

To reproduce from your own site instead: run the Worker tail while sending the prompts in `../03-probe-log.md`, then run the export script with a directory holding the `tail-*.json` stream and the `ip-*.json` vendor lists.

## Attribution

Each assigned probe URL was given to one assistant in a fresh chat and existed nowhere else at the time, with one deliberate exception: `/probe/grok-mobile` was reused for the signed-in phone and desktop Grok runs. A request carrying an assigned URL is attributed to that assistant by the URL and by arrival time. The prompts, times and assistant replies are in `../03-probe-log.md`.
