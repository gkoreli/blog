# Controlled local ingestion experiment

Executed September 6, 2026 UTC. Twelve hand-selected Accept headers passed through the actual `observePageResponse` entry point, its metadata parser/classifier, and its SQL INSERT into an in-memory SQLite database. All requests were generated by a script with the same synthetic browser declaration, navigation headers, test IP, and non-hosting test ASN. These are constructed requests, not real browser visits or a representative traffic sample. No network call, RUM beacon, production D1 write, or historical reclassification occurs.

| Measure | Before | After |
|---|---:|---:|
| Cases executed | 12 | 12 |
| Accept results disagreeing with the case's expected HTML acceptance | 7 | 0 |
| Rows missing ASN provenance despite a supplied ASN | 12 | 0 |
| Selected requests classified as Browsers | 8 | 5 |

Five selected cases move from Browsers to `http-client`; two move in the opposite direction. Explicit zero quality, wildcard specificity, exact media-type matching, and representation parameters explain those changes. The after count is smaller here, but the acceptance criterion is correct interpretation of each input, not a smaller count. Missing Accept remains null evidence; it is not treated as a positive browser signal even though HTTP permits any representation when Accept is absent.

The HTML target is `text/html; charset=utf-8`. Unknown representation parameters do not match it. Invalid quality values provide no positive acceptance evidence; exact valid media ranges take precedence over wider wildcards. This is an analytics evidence parser, not a replacement for the Worker's content negotiation. [RFC 9110, Accept](https://www.rfc-editor.org/rfc/rfc9110.html#section-12.5.1), checked September 6.

Every case reaches the recording path in both runs. Correcting the marker writes `asn_source = 'request'` when the request supplies an ASN and leaves it null when no ASN is present. Separate integration assertions cover both situations. Historical null provenance remains null; the migration and repaired INSERT are different operations.

## Reproduce

From the checkout under test:

```bash
pnpm -C packages/analytics exec tsc -p tsconfig.test.json
node packages/analytics/scripts/calibration-probe.mjs
pnpm -C packages/analytics test
```

The probe emits JSON to stdout. Save each new run under a new filename; do not replace the baseline. The [before](01-local-baseline.json) and [after](02-local-repair.json) artifacts include the base Git revision and hashes of the compiled code actually executed. The after run was measured with uncommitted repair bytes, so the Git revision alone does not identify that implementation; its source hashes do. The harness and exact inputs are committed with this experiment. No private visitor identifiers are included in the output.

Validation: 39 analytics tests pass. Two additional test groups cover 35 input cases in the parser and metadata integration; existing database tests now check present and absent network provenance. The twelve-case probe deliberately overlaps known failure cases: 7/12 is not an estimated production error rate.

These findings establish defects and a local repair. The historical count impact remains unknown because D1 retained derived Accept flags rather than the original headers. The 95-versus-14 comparison is unchanged. Browser, cache, script, delivery, and RUM ingestion experiments remain open in the [worklist](00-worklist-index.md).
