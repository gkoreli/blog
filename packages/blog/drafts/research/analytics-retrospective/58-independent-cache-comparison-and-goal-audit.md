On the same thirteen cases, our policy accepts **four** and the library's selection result matches **six**. Decisions agree on **eleven**, with two deliberate scope differences:

| Case | Application | Library `matches` | Why retain the distinction |
|---|---|---|---|
| Stored weak tag; returned strong tag with the same opaque value | Unavailable | true | Our narrower policy requires a stored strong validator before strong-tag renewal. |
| Neither stored nor returned validators; supplied 304 | Unavailable | true | Our application requires a conditional request. The library selects a single validator-free stored representation; that does not establish whether the supplied server response was valid. |

No application policy changed because of that harness correction.
