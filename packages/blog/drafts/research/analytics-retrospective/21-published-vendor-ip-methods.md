## What the source inspection changed

Moving-main documentation was insufficient for dependency adoption. `ipaddr.js` main declared 3.0.0, but the official npm endpoint returned **version not found**. The published latest endpoint supplied **2.5.0**. Its SHA-512 integrity passes; shipped JavaScript, declarations and MIT license match upstream commit [`dc55282780d8702bac31ef012ca52e4a77fbca1f`](https://github.com/whitequark/ipaddr.js/tree/dc55282780d8702bac31ef012ca52e4a77fbca1f) byte for byte. The runtime dependency and lockfile pin that published version, with installation scripts disabled. The earlier main-branch inspection in research 20 remains historical, not silently recast as a pinned release review.

The [pinned parser](https://github.com/whitequark/ipaddr.js/blob/dc55282780d8702bac31ef012ca52e4a77fbca1f/lib/ipaddr.js) intentionally accepts numeric/octal/hex IPv4 and scoped IPv6. We use its strict four-part decimal helper for IPv4, reject address lists, port/bracket/scope forms and normalize mapped IPv4 explicitly. Its parser and CIDR matcher do the address arithmetic; our wrapper defines the collection boundary. A dependency that accepts a string does not decide whether that string is an appropriate edge address or a valid vendor feed entry. A non-default parser range is retained as special-range, not declared universally non-public; this is a conservative local eligibility policy, not an IANA routing authority.

Actual feed responses matter too. OpenAI's ChatGPT-User feed serves `application/octet-stream`; its other inspected feeds serve JSON. The registry narrowly permits that observed type for that one official source. Google's common-crawler feed requests no-cache, while three OpenAI feeds have zero max-age. We preserve revalidation semantics and rate-limit refreshes, returning not-assessed during cooldown instead of silently reusing stale results. Perplexity's documented .com links redirect to .ai; the fixed registry uses the observed official .ai endpoints and rejects runtime redirects.

## What runs and what is retained

`vendor-ip.ts` uses only fixed registry URLs. Each eligible observation can assess at most four distinct applicable feeds in parallel, coalesced by source. Every fetch has a 1.5-second deadline, a 256 KiB body cap and a 4,096-prefix limit. Whole-feed validation rejects bad family keys, invalid CIDRs, host-bit prefixes and non-default parser-range bases; it never silently discards bad entries and presents the remainder as a complete list. Source-cache keys are fixed IDs, never reader addresses.

Reuse follows max-age/Age/no-cache/no-store, with a five-minute default and one-hour maximum. Conditional revalidation preserves the original body fetch time and digest while recording its latest validation time separately. A failed refresh cannot yield a stale listed/nonlisted verdict. A 30-second source cooldown and the four-source request budget produce explicit not-assessed results; source/body/network failures produce unavailable. These bounds are per isolate. No global vendor-fetch cap or complete original-client attribution is claimed.

Additive migration 0014 introduces `vendor_ip_evidence` at 4,096 bytes. Routine evidence holds method/profile, normalized address source/family/availability, declaration coverage, per-source result, digest, publisher version and fetch/validation/freshness times. No raw address, raw UA, matched prefix, arbitrary URL or validator text is retained there. Reader addresses are not transmitted to vendors. Publisher version strings are validated but preserve the source's timezone notation rather than inventing a UTC suffix. Raw diagnostic capture remains off; derived records remain linked pseudonymous data under the existing lifecycle and privacy limitations.

The report adds overlapping view-level flags under the existing owner/referral/time/path selection and the same single statement. It does not expand source arrays per observation or create additional page events. Old rows remain unrecorded. Classification/collection/report versions become `2026-10-27.4`; adding OAI-AdsBot is a prospective catalogue change. The earlier classifier evidence shape remains `.2`, while its profile identifies the new rules. Signature verification/evidence stay `.3`; the IP method has its independent `.1` profile.

The privacy page now describes this processing and its retained facts. No universal anonymity, legal compliance, vendor identity, residential-network, benignness or human-readership claim follows. A published-range nonmatch can reflect forwarding, vendor changes or an incomplete source, not necessarily impersonation. A match may support a shared vendor network while leaving the exact product, initiator and purpose unresolved.
