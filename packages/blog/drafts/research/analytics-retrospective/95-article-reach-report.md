# Put article decisions in the report

October 29, 2026 UTC. Continues [Research 94](94-reader-growth-and-editorial-decisions.md): raw page ranks hid source concentration, internal navigation and unequal publication ages. The new `/stats/readership` page puts those distinctions together, linked from `/stats`. This implements the next reporting step; it does not complete the wider identity/measurement goal.

## What changes

The focused library [query](../../../../analytics/src/article-reach.ts) selects stored Browser signals over 28 completed UTC days. Four seven-day intervals omit today's partial day. Site and article totals remain separate. The validated current `posts.json` catalogue supplies canonical article paths, titles and dates; home, hubs, prompt pages and removed historical URLs are outside the ranking. Dates show calendar overlap, not actual exposure. Missing metadata fails before D1; it cannot quietly produce an empty leaderboard.

Each article shows total, external, internal, absent-referrer and unknown-source events, plus events outside the largest external source. That source is selected once across the whole window and kept fixed across articles/weeks. Public naming remains conditional on the existing display policy. A legitimate source can be largest; this is a sensitivity check, not an exclusion or human correction. Sorting uses the already received report and creates no additional calculation.

The [contract](../../../../analytics/src/article-reach-contract.ts) validates the catalogue count, unique/bounded paths, dates, closed keys, safe counts, source partitions, four contiguous weeks and article/site reconciliation. Client and server share it. Unusable/inconsistent/earlier merged source evidence stays unknown. Unrecognized timestamps stay in totals with an explicit count, outside weekly rows. Distinct stored classifier identifiers and missing stamps expose changing measurement conditions without claiming reviewed historical code.

The single statement reuses current owner/client/referral exclusions and the existing metered calculation adapter. A separate report/cache namespace reuses one-hour/midnight expiry, preserved calculation time, coalescing and failure handling. The Worker canonicalizes requests, so arbitrary source/path/date/bypass parameters create no new report state. The metadata fetch uses the local asset binding; no third-party lookup or new collection is added. Existing `/stats/` and `/api/` eligibility rules exclude the new page/API from observations.

## Checks and discoveries

The 24-case native D1 corpus covers dates, source normalization, absent versus merged history, owner/client/referral precedence, non-articles and zero-event articles. Display approval changes naming without reselecting the source. Twenty-five contract negatives reject incomplete or contradictory outputs. SQL uses six bindings and stays below the documented statement limit. Shared unit checks include malformed native rows, cookie/query isolation, cache expiry and metadata failure/recovery.

Two implementation findings mattered. SQLite accepts hour 24, while the collector's canonical timestamps use 00–23; an explicit bound prevents silently assigning that value to a week. The planner initially selected an owner-leading index across history. Materializing the date window first gives the intended observed-time index range; this adds work on the all-in-window fixture but avoids making older history part of that selection scan. These are measured local findings, not production prevalence claims.

On 32,768 synthetic selected rows and the maximum 256-article catalogue, the focused report costs **441,772 native reads / zero writes**, producing **210,794 bytes**. The full stats report costs **1,547,477 reads** on the same input, whose events lie inside both windows. This comparison is fixture evidence, not a measured production saving or an enforced quota cap. Primary [SQLite date](https://www.sqlite.org/lang_datefunc.html), [CTE](https://www.sqlite.org/lang_with.html) and [D1 return-object](https://developers.cloudflare.com/d1/worker-api/return-object/) docs frame the interpretation.

The hash-verified private Research 94 capture supplies all 1,463 retained Browser rows. Native local reconstruction reproduces **1,429 included events**, all four weekly site/article totals, source metrics and all **32 article cohorts with traffic**. The catalogue also retains the thirty-third zero-event article. No new production export is needed. The reconstruction creates each owner-client relationship once; an initial duplicate-link insertion failed locally before assessment, then was corrected. It preserves selected scalar facts and defaults unselected required columns; it is not a complete production snapshot. The resulting report contains 931 article events, 388 reporting the largest source. Sorting outside that cohort puts the fetcher reference first. Raw hosts and daily IDs never enter the public response.

Checks: **306 analytics / 119 site tests**, workspace types, Markdown validation and isolated 33-post build pass. Initial isolated build missed the required publication image metadata; it was repaired before acceptance. Desktop 1280px and mobile 390px checks keep overflow within focusable table regions. Native selection changes sort order; no extra API request occurs. Missing weeks, inconsistent totals and HTTP failure each hide the report and show a retry. The final desktop table fits the normal content column. These are synthetic browser checks, not human/device accuracy measurements.

[Native receipts](article-reach-native.json), [frozen comparison](article-reach-frozen.json) and [checks](article-reach-checks.json) preserve the result. The [ADR](../../../../../docs/adr/0016.18-article-reach-and-source-concentration.md) owns the current decision. Private captures and screenshots remain outside Git. Article 030 stays unchanged at 1,450 words / 31 prompts. Human trials remain deferred; search terms, sustained readership, native managed-verifier agreement, R1 operator/trigger and historical cryptographic completeness remain unproven.

At this checkpoint source delivery, exact activation and a bounded live cache/asset/meter check remain acceptance work. No production request, diagnostic SELECT or new human label has occurred in this iteration. October 31 is a private-evidence review date, not automatic deletion.


## Live acceptance and a publication-date defect

[Release receipt](article-reach-release.json): source `d43863c` links through the native deployment row’s full Git SHA, Ready build `791e0f8d` and Worker prefix to the uniquely matching full CLI version `f3e3f5f1` at 100% allocation. The full build log was not inspected: deep navigation returned Page not found or rate limiting. One backed-off native deployment retry supplied the source/Ready/version row; later build-detail attempts did not strengthen it. Actual response/log joins use the full Worker UUID.

The first 200/MISS reproduces every traffic/source metric: 1,429 site events, 931 article events and 388 article events reporting the largest source. Its complete matched D1 receipt reports **33,868 reads / zero writes / one attempt**, a last-attempt meter, not unique observations. The controller stops because one catalogue date differs from the local fixture. The retained response is subsequently accepted after the metadata review; it is never requested again to recover a receipt.

The macOS article declares unquoted `date: 2026-10-28`. Installed gray-matter 4.0.3 delegates to js-yaml 3.14.2, whose timestamp constructor returns a UTC `Date`. Our parser then used local calendar getters, producing October 27 in Los Angeles. Production returned October 28; its actual build timezone was not independently inspected. The parser now takes the UTC calendar day. [Three-timezone evidence](article-reach-date-checks.json), including quoted/unquoted/leap-day regression cases, preserves the distinction. The isolated build changes exactly [one metadata field](article-reach-date-build.json), without editing any article date or prose; the [Worker JavaScript remains byte-identical](article-reach-date-worker.json). Site tests rise to 120 and workspace types pass.

This follows the installed [js-yaml timestamp implementation](https://github.com/nodeca/js-yaml/blob/3.14.2/lib/js-yaml/type/timestamp.js), the [YAML 1.1 timestamp draft](https://yaml.org/type/timestamp.html) used to interpret that engine, and [ECMAScript’s UTC ISO serialization](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-date.prototype.toisostring). It does not claim that every YAML schema coerces dates or that publication dates measure actual exposure.

The next nominal warm request returns MISS with a **SJC** Ray suffix, while the first was **DFW**. Its meter is unavailable: the filtered tail returns no event before stopping. Its cost is not treated as zero, and differing locations do not establish every possible reason for a MISS. [Cloudflare documents cache locality](https://developers.cloudflare.com/workers/runtime-apis/cache/). A new [local connection control](article-reach-connection-native.json) verifies curl’s [sequential connection reuse](https://curl.se/docs/manpage.html#-:). A separately frozen experiment then sends two immediate HTTP/1.1 transfers in one curl process: the second opens no connection; both return DFW/HIT with identical body, calculation time and expiry, and neither has a calculation log. Matched request metadata also reports DFW for that pair. Worker execution placement was not independently measured; the HIT/body/time/expiry result establishes reuse for those responses, not global cache coverage.

The four previously unsent asset checks then pass: report article fragment, stats link, JavaScript and CSS. All six responses in this connection/asset phase join exact marker/Ray/full-version events. Across the whole release there are eight one-attempt controlled GETs, seven exact joins and one unmatched response; no collection-eligible request, direct diagnostic SELECT or human label. Two MISS responses indicate calculations, but only one has a complete matched meter. Therefore total read cost across both fills is unavailable. All three owned tail groups terminate with no remaining group members; provider-side deletion is not independently inspected. No original request is replayed to recover missing evidence.

The feature is accepted on the recorded source/Worker. The build-time date repair is delivered separately with this acceptance record; it does not claim a fresh activation of that later commit. Browser layout checks remain local/synthetic. Article 030 remains unchanged. Search queries, sustained readership, human/device accuracy, native managed agreement, R1 operator/trigger and whole-history cryptographic correctness remain open; human trials stay deferred.

[Research 100](100-readership-delta-and-source-concentration.md) independently reconstructs the shifted October 2–29 window through this library. A second source dominates one article’s new-day requests while R1 remains largest overall.
