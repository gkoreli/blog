# Detection lessons from pinned OSS source

November 6, 2026 UTC / November 5 Pacific. This source review follows [the fresh uncertainty baseline](127-current-unidentified-and-unsigned-traffic.md) and supports the new detection investigation. It does not measure a deployed improvement. [Source ledger and exact offline cases](2026-11-06-oss-detection-source-ledger.json) preserve commits, file hashes, sizes and results. Sources were checked on November 6 UTC; upstream HEAD is pinned at acquisition, not treated as a permanent release.

## Findings that change the implementation priorities

The useful improvement is to preserve more explainable evidence and remove false lexical conclusions. A much larger bot regular expression alone cannot identify the operator behind a browser request. The current baseline contains 620 generic-token events, but an offline catalogue match does not show how many of those events a change would resolve.

Two correctness repairs are immediately actionable:

- The current generic `bot` suffix matches the Android model text `CUBOT MAX`, `CUBOT C11` and `CUBOT DINOSAUR`. [isbot's browser fixtures](https://github.com/omrilotan/isbot/blob/3f9c982acd95b1be033fa3c14b2a7ece565ba10a/fixtures/browsers.yml#L149-L153) and [uap-core's explicit CUBOT exception](https://github.com/ua-parser/uap-core/blob/73e7340c3ed8055051607b296bf46ead7aa5f19e/regexes.yaml#L191-L194) expose this collision. A CUBOT model must not veto an independent `GPTBot` or generic bot product elsewhere in the header.
- The current generic `phantom` substring matches Phantom's mobile app tokens `Phantom/ios/...` and `Phantom/android/...`. The [two upstream browser fixtures](https://github.com/omrilotan/isbot/blob/3f9c982acd95b1be033fa3c14b2a7ece565ba10a/fixtures/browsers.yml#L483-L485) differ from [PhantomJS](https://github.com/matomo-org/device-detector/blob/0ca48a37aa7a4388e9ec5897f033aaef9155ed90/regexes/client/libraries.yml#L8-L11). Phantom's [own documentation](https://help.phantom.com/articles/connect-phantom-to-an-app-29995498642195) confirms that its mobile app has an in-app browser. This supports narrowing the automation token, not authenticating the app or a person from the UA.

The baseline replay reads `analyzeTraffic()` from repository source at `18606bd538c3899ea8786abd71517519df5834cd` through Node 24.14.1's native TypeScript stripping; the ledger records the source hash and execution time. It includes 17 explicit cases and a separate pass over 551 unquoted single-line entries in isbot's browser fixture file. Eight entries produce a non-browser coarse class: four CUBOT cases, two Phantom cases, Yahoo Slurp and Amzn-User. The final two show why upstream fixture labels are not ground truth for this site's declared-role contract: a named Amzn-User declaration should remain an on-demand fetcher. This is a fixture disagreement count, not an estimated false-positive rate in production.

## What the other implementations actually do

### Matomo device-detector

Pinned [Bot parser](https://github.com/matomo-org/device-detector/blob/0ca48a37aa7a4388e9ec5897f033aaef9155ed90/Parser/Bot.php#L68-L95) first performs a combined-regex precheck, then returns the first matching detailed record. Its [general parser](https://github.com/matomo-org/device-detector/blob/0ca48a37aa7a4388e9ec5897f033aaef9155ed90/Parser/AbstractParser.php#L388-L407) adds a left boundary and caches parsed/combined regexes. The pinned bot file has 847 top-level rules and occupies 152,283 bytes; records carry names, categories, producer names and source URLs. [Semrush](https://github.com/matomo-org/device-detector/blob/0ca48a37aa7a4388e9ec5897f033aaef9155ed90/regexes/bots.yml#L1680-L1686), [MJ12](https://github.com/matomo-org/device-detector/blob/0ca48a37aa7a4388e9ec5897f033aaef9155ed90/regexes/bots.yml#L1324-L1330), and [DotBot](https://github.com/matomo-org/device-detector/blob/0ca48a37aa7a4388e9ec5897f033aaef9155ed90/regexes/bots.yml#L587-L593) are useful discovery leads. Its [Ai2 variants](https://github.com/matomo-org/device-detector/blob/0ca48a37aa7a4388e9ec5897f033aaef9155ed90/regexes/bots.yml#L5623-L5645) have different categories, so collapsing every prefix to a single training role would lose information.

Lesson: keep typed per-client facts and sources; precompute lookup structures. Preserve this site's all-candidate/conflicting-role behavior rather than adopting first-match identity selection. A PHP/PCRE parser and its LGPL-3.0-or-later source are not a drop-in TypeScript Worker dependency. No Matomo parser execution or performance acceptance is claimed.

### JavaScript isbot

Pinned [runtime code](https://github.com/omrilotan/isbot/blob/3f9c982acd95b1be033fa3c14b2a7ece565ba10a/src/index.ts#L7-L42) caches one combined expression and falls back to a less precise expression if construction fails. Its 207 patterns occupy 3,342 JSON bytes. [Patterns](https://github.com/omrilotan/isbot/blob/3f9c982acd95b1be033fa3c14b2a7ece565ba10a/src/patterns.json#L2-L28) include broad URL, email, short-UA, generic word and shape heuristics; [other entries](https://github.com/omrilotan/isbot/blob/3f9c982acd95b1be033fa3c14b2a7ece565ba10a/src/patterns.json#L147-L168) cover Manus-User, node and PhantomJS. It produces a boolean or matched fragments, not authenticated names or roles. Its [fixture downloader](https://github.com/omrilotan/isbot/blob/3f9c982acd95b1be033fa3c14b2a7ece565ba10a/scripts/prepare/externals/index.js#L7-L29) consumes several upstream sources, including Matomo and crawler-user-agents; agreement among these projects is therefore not independent corroboration.

Lesson: borrow adversarial fixture discipline and a cached matcher where useful, not its boolean as a reporting identity. A browser-looking header with a publisher URL can match broad patterns. Its Unlicense declaration is recorded separately from upstream fixture provenance. No dependency is introduced.

### crawler-user-agents

The pinned JSON has 1,505 records and occupies 545,335 bytes. Its [typed Go record](https://github.com/monperrus/crawler-user-agents/blob/db662d2787f984ed4fe3043744a12eb067b89218/validate.go#L20-L45) retains example UAs, discovery dates, URLs and optional role tags. Its [Python matcher](https://github.com/monperrus/crawler-user-agents/blob/db662d2787f984ed4fe3043744a12eb067b89218/__init__.py#L10-L38) caches compiled chunks; `is_crawler` can stop on the first hit, while the detailed path collects all matching patterns. Plain substring patterns can match a name inside a URL or another product: the explicit `NotGPTBot/1.0` control matches its `GPTBot` pattern, whereas our named matcher correctly selects no GPTBot declaration.

Lesson: use the MIT-licensed dataset as an offline candidate/fixture feed, with first-party review and exact-product acceptance. Version imported data and preserve notices if data is copied. Do not ship half a megabyte of unreviewed patterns merely to make the unnamed remainder smaller. The replay instantiates the pinned regex strings in JavaScript; it does not claim Python/Go parser parity.

### GoatCounter and its Go isbot dependency

GoatCounter [pins `zgo.at/isbot` v1.1.0](https://github.com/arp242/goatcounter/blob/c031008a8d28c85b36708824f23b28957e7ed262/go.mod#L27), independently of the JavaScript project above. Its dependency's [request classifier](https://github.com/arp242/isbot/blob/305a021896f64c75ccbd18f5ba89183e8bdcdb07/isbot.go#L106-L134) checks prefetch, UA, then network ranges, returning typed reasons. Its [UA implementation](https://github.com/arp242/isbot/blob/305a021896f64c75ccbd18f5ba89183e8bdcdb07/user_agent.go#L13-L56) uses short/shape, URL, library, known-token and generic-word rules, with early known-browser exceptions. Its [CUBOT exceptions](https://github.com/arp242/isbot/blob/305a021896f64c75ccbd18f5ba89183e8bdcdb07/user_agent.go#L76-L80) solve the immediate suffix collision but an unconditional whole-UA allowlist can suppress unrelated signals.

Lesson: expose detection reasons and cache bounded reusable work. This site's audience includes agents, so GoatCounter's filtering objective and “not a regular user-initiated browser” definition do not transfer wholesale. GoatCounter declares modified EUPL-1.2; the separately reviewed isbot dependency declares MIT. No Go implementation is executed here.

Plausible [drops Headless Chrome and parsed bot results](https://github.com/plausible/analytics/blob/a93b615b3af980399123eb9112f6c88255f8f943/lib/plausible/ingestion/event.ex#L263-L282). Its [runtime dependency](https://github.com/plausible/analytics/blob/a93b615b3af980399123eb9112f6c88255f8f943/mix.lock#L163) and [UA data release `6.5.2`](https://github.com/plausible/analytics/blob/a93b615b3af980399123eb9112f6c88255f8f943/config/config.exs#L44-L46) are separate pins. That distinction is useful for reproducibility. The exact UAInspector 3.12.0 Git tag could not be resolved from the attempted repositories; no claim about that dependency's internal matching implementation follows. Plausible's application source declares AGPL-3.0.

[uap-core](https://github.com/ua-parser/uap-core/blob/73e7340c3ed8055051607b296bf46ead7aa5f19e/README.md#L4-L6) supplies data, not an executable parser. Its 222,536-byte YAML spans browser, OS and device parsing, with [ordering exceptions](https://github.com/ua-parser/uap-core/blob/73e7340c3ed8055051607b296bf46ead7aa5f19e/regexes.yaml#L158-L194), [Phantom app rules](https://github.com/ua-parser/uap-core/blob/73e7340c3ed8055051607b296bf46ead7aa5f19e/regexes.yaml#L244-L246), and separate [PhantomJS handling](https://github.com/ua-parser/uap-core/blob/73e7340c3ed8055051607b296bf46ead7aa5f19e/regexes.yaml#L1201-L1203). ## One declarative client registry

The current named rules, role sets, network assignments, signing-origin mappings and directory-publisher mappings are maintained in separate files. A unified registry should own each canonical client name, exact product aliases, coarse traffic class, declared reader kind, source references/review date, and explicit lists of applicable method IDs. Derive matcher rules, role lookups, known-name types and current declaration counts from those rows. Derive reverse method-to-declaration associations rather than maintaining a second list by hand.

Keep method definitions distinct: an IP feed has a URL/parser/budget contract; a documented signing origin has a different basis from a reviewed public directory endpoint. Ahrefs' directory publication is not a documented promise to sign every request. A missing method ID means no configured method, never a negative identity result. Store leaf types/IDs in an import-independent module to avoid cycles. Use `as const` plus checked shapes and narrowing, without assertions or `any`.

Preserve all-candidate matching. Explicitly distinguish one declared role with several compatible names from conflicting roles; do not let registry order choose an identity. Exact aliases should be reviewed independently, including hyphenated crawler variants. Product tokens in URLs and `NotGPTBot` must not acquire the GPTBot name. A name field should remain a lexical declaration, independently joined to IP, signatures and provider-category evidence.

Current collection/classifier/registry profiles must change when behavior or catalogue scope changes. Append frozen historical catalogue/method profiles rather than regenerating them from today's registry. Keep historical filter exceptions such as Slackbot explicit. Stored historical names and reasons are not rewritten by a new source release. Plausible's independent library/data pin and Matomo's versioned cache keys are useful precedents; neither certifies a deployed service's current state.

Registry invariants should cover duplicate canonical IDs/aliases, every alias's role, all referenced method IDs, exact reverse mapping, missing-method states, signature-covered versus uncovered names, compatible/conflicting multi-name headers, and representative false-positive controls. Snapshot or generate current public catalogue documentation from the same rows. Candidate-source refresh should produce a reviewable diff with additions/removals, provenance and new fixtures; it should not silently pull new classification rules into production.

## Benchmark and acceptance design

Compare equivalent work at three levels: declaration extraction, complete classification, and native Worker collection. Separate cold module/regex initialization from warmed request processing. Comparing this site's structured multi-candidate result against one competitor boolean is informative about cost only when the semantic mismatch is explicit.

Use a fixed, hashed corpus with named declarations, generic bots, CUBOT/Phantom false-positive controls, standard browser claims, known HTTP libraries, multiple/conflicting products, URL/name injections, malformed tokens and long adversarial inputs. Repeat each family with a browser-looking prefix, a vendor URL comment, varied case and unrelated punctuation. Test near the documented UA budget and beyond it; do not call a truncated prefix a complete identity assessment. Include official examples and hand-written negative controls; do not use overlapping upstream datasets as an independent held-out validation set.

Report corpus size/composition, exact runtime/CPU, cold compilation time, warmed per-family latency distribution, total CPU time, bundle delta and peak allocations where measurable. Randomize order and repeat bounded runs. Keep fixtures and import/configuration outside the timed hot path; cache reusable matchers, never unbounded raw-UA keys. Run matched and nonmatched long strings because regular-expression worst cases can differ. A local microbenchmark does not establish Worker billing, production latency, or classifier accuracy. Production acceptance additionally requires deployed version confirmation, bounded controlled requests and read-cost accounting.

Acceptance should show supported identity/role evidence becoming more specific while adversarial controls remain unclaimed. It must also retain the large ordinary-browser uncertainty boundary. A false-positive repair can reduce generic-bot counts without “finding humans”; a catalogue addition can reduce unnamed declarations without authenticating operators. Provider categories should remain a separate measured facet, with explicit agreement/disagreement/missing states rather than silently replacing the stored local kind.

## Independent adversarial review of the integrated work

An additional isolated compilation into `/tmp/analytics-adversarial-review-20261106` passes. Source review and direct calls find two remaining parser-coherence cases beyond the separately discovered semicolon-in-URL product bypass:

- `Chrome/75.0 AppleWebKit/605.1 (+https://example.test/iPhone OS 17_0)` reports Fetch Metadata support, although the same browser products without the URL do not. The opposite change occurs for Chrome 150 with a URL containing `iPhone OS 16_3`. The iOS capability branch still scans the raw header, independently of product parsing. This changes the support explanation; it does not establish a human or automated operator.
- An optional diagnostic for `https://example.test/Chrome/150.0` reports Chromium 150 and browser form, while the main declaration parser reports an unrecognized browser family. Its independent browser regex still reads the URL. Root assigned shared masked-claim handling and optional-extractor coherence to the lexical implementation track; acceptance of that subsequent repair belongs with its tests.

The retained-products review also reproduces a narrower API issue: a JavaScript sparse historical array, such as `Array(1)` or `[, 'GPTBot']`, passes an `Array.every` guard and returns an array containing `undefined`. The old category-array decoder has the same issue. Parsed JSON cannot contain sparse arrays, so this is an unknown-input library-contract gap, not evidence of corrupt production JSON. A dense-array guard and direct sparse-array controls are the bounded repair.

The new joint report keeps selected-name presence separate from declaration cardinality and validates its signature/provider-category margins and named-table total. Extra unknown cohort keys are discarded by projection; no new free-text field reaches its output. Its consistency checks establish arithmetic and shared selection, not independent authentication of the underlying stored evidence. The review finds no additional report/codec release blocker in that scope. Current native fixture read costs and local timings do not establish future production cost; historical provider and signature assessments retain their original evidence boundaries.
