## Borrow the platform's visibility before adding machinery

[Cloudflare's tracing guide](https://developers.cloudflare.com/workers/observability/traces/) documents built-in outbound-fetch and binding spans. Its [attribute reference](https://developers.cloudflare.com/workers/observability/traces/spans-and-attributes/) provides the operation fields, while [known limitations](https://developers.cloudflare.com/workers/observability/traces/known-limitations/) caution about incomplete attributes, evolving names and non-I/O timing. The request-reference query returns one root span; the exact trace-reference query also returns child operations. That difference in this selection does not prove complete logging across other requests.

[Custom spans](https://developers.cloudflare.com/workers/observability/traces/custom-spans/) can expose application work such as parsing or key selection if those remain a demonstrated gap. No new runtime instrumentation or tracing configuration is needed to locate this particular Exa wait. [Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/) still impose retention, sampling and truncation limits; we have recovered retained provider representations, not independent wire captures.

The pinned [pyauth verifier](https://github.com/pyauth/http-message-signatures/blob/1de433d9a49fd608475c6054ab14a1652c088844/http_message_signatures/signatures.py) keeps key resolution, freshness, signature verification and required components explicit. Its [component resolver](https://github.com/pyauth/http-message-signatures/blob/1de433d9a49fd608475c6054ab14a1652c088844/http_message_signatures/resolvers.py) derives authority/method/path and maps an empty ordinary path to `/`. Eighteen source files are hash-checked before comparison. The fresh pinned GitHub web reads fail with cache misses; the authoritative saved source mirror is read locally. Agreement on these six contexts does not prove general interoperability or managed-provider agreement.

[RFC 9421](https://www.rfc-editor.org/rfc/rfc9421.html#section-1.3) explains why changes to covered message components can break a proof. Its [application requirements](https://www.rfc-editor.org/rfc/rfc9421.html#section-3.2.1) remain separate from cryptographic success. [Exa's signing and automatic-edge-validation claims](https://crawler.exa.ai/) do not establish the outcome of this particular local key-directory lookup. Both native verification booleans remain unavailable in the stored evidence. The successful Exa replay still binds no User-Agent, method or resource and establishes no human trigger or readership.
