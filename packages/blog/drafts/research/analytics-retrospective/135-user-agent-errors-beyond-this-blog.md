## Question and acceptance

Can we substantiate an externally relevant analytics failure without inventing how many sites or people are affected? Find independent firsthand reports and concrete repairs; distinguish a direct lexical mistake from adjacent bot heuristics. Improve the draft around the field read, the incorrect derived value and its consequence. Provide a small reproducible extraction check readers can adapt. Preserve all nine complete November 10 shaping messages in the paired prompt record, following its three historical messages.

## Method

Use web search for discovery, then GitHub's connected read tools for complete issue bodies/comments, linked PRs, fix commits and pinned files. The returned hits are a purposive lead set, not an exhaustive issue census, representative sample or count of affected sites. A zero-result search establishes only that query's returned pool. Public web search sometimes returned unrelated projects; those hits were rejected.

Record actual dates from issue metadata, not relative search labels. Fetch Matomo issue 5484's timeline to identify its fix; inspect that exact commit. Check current isbot source separately so historical reports cannot imply an unresolved defect. Preserve failed accesses. External public captures stay outside Git alongside local command outputs; this record contains only derived evidence and public links.

The bounded headline is **two externally documented historical lexical failures in two library projects, plus our independently reproduced case**. The Rybbit item is a separately labelled adjacent report. This supports recurrence and practical relevance. It does not support “most analytics is wrong,” an affected-person count, an affected-site count, or a current industry-wide error rate. The libraries' existing fixes are counterevidence against implying all current versions still make these mistakes.

## Numbers accepted and rejected

- **Accepted:** four supplied UA examples in isbot's original CUBOT issue; at least two reporting accounts in that thread; 2016 and 2018 historical reports with inspected remediation; the blog's dated 2,810/3,960 unnamed declaration baseline; 16 selected companion controls; six previously accepted live controls. These have different units and must not be summed into a prevalence metric.
- **Rejected:** interpreting the blog's roughly 71% without a recognized catalogue name as a 71% error rate, as affected readers, or as misclassified AI traffic. Browser families and other evidence can still be recognizable.
- **Rejected:** treating package downloads, dependency declarations or repository stars as affected people or deployments. Web access to npm's download API failed; a sandboxed direct read also failed DNS. No download total is obtained or used, and no alternate credential/access change is attempted.
- **Further prevalence evidence:** a defined sample of deployed product versions, operator-confirmed applicable configurations and a privacy-appropriate observed request selection with defensible labels. Controlled counterexamples establish possibility/mechanism, not the frequency of that condition on real sites. This study does not start that experiment or contact operators.

## Reader-facing engineering

The [User-Agent check pack](../../../tools/user-agent-check/README.md) supplies sixteen simplified public controls, a standalone Node runner and a current-blog adapter. The contract concerns software declarations in a supplied string, not a binary human/bot truth label. It tests phone/app lookalikes, URI spans, positive appended declarations, unknown bare bot names, canonical-name lookalikes, competing candidates and order invariance. No URLs in fixtures are fetched. Readers explicitly execute their own adapter; it is not a sandbox for untrusted code.

A broader boolean detector or first-match API can intentionally have a different policy; the pack must not rank it as inaccurate simply for failing a contract it does not implement. The JSON result includes every selected case and fixture SHA-256. Demo failures demonstrate a deliberately weak local implementation, not the blog's full old classifier or an upstream product. Existing collector/classifier/verifier/schema sources are unchanged.
