## A normal browser can preserve the external referrer

The [HTML navigation standard](https://html.spec.whatwg.org/multipage/browsing-the-web.html#document-state) stores a session-history entry's request referrer. Its [fetching algorithm](https://html.spec.whatwg.org/multipage/browsing-the-web.html#create-navigation-params-by-fetching) supplies that stored referrer when fetching the entry. Referrer policy controls what is transmitted, including origin-only minimization; it does not turn a destination request into a counted search click. [RFC 9110, section 10.1.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.1.3).

A local agent-operated browser control follows one link between two loopback hostnames, then reloads the destination without another source-page click. Both destination requests carry **the same external-origin `Referer`, `Sec-Fetch-Site: cross-site`, navigation/document values and `Sec-Fetch-User: ?1`**. The reload additionally sends `Cache-Control: max-age=0`. This is a concrete counterexample to treating every referrer-bearing request, including one with activation, as a new source click. It does not measure how many of the historical 79 were reloads, or independently reproduce the `none` combination. An initial single-threaded test-server attempt stalled on a second connection; only the corrected threaded run supplies the two observations. The server is stopped and no lab request reaches the publication.

The [Fetch Metadata draft](https://www.w3.org/TR/fetch-metadata/#sec-fetch-site-header) defines context relationships and [user-agent-initiated navigation](https://www.w3.org/TR/fetch-metadata/#directly-user-initiated-requests); `none` is not a bot label. Its browser JavaScript restrictions do not prevent an independent HTTP client from choosing headers. The official [curl `--referer` documentation](https://curl.se/docs/manpage.html#-e) explicitly allows supplying a referrer, separately from User-Agent and other headers. Thus compatible browser headers are useful signals, not a cryptographic origin proof.

## Where the discrepancy belongs

Google's [report definition](https://support.google.com/webmasters/answer/7576553?hl=en) counts Google Search clicks and scopes Web (text) to text-query traffic. Other search types are separate. Its [aggregation contract](https://support.google.com/webmasters/answer/17011364) can combine repeat property clicks within a search interaction. Our report counts page observations, including repeated destination requests. Its UI already says **Reported referrers — by views** and **Browser signals**; neither label promises organic-search acquisitions or verified people.

The [Search Console discrepancy guide](https://support.google.com/webmasters/answer/17010575?hl=en) says rare/anonymized query rows can be absent while their data remains in an unfiltered chart total. Hidden query rows therefore do not justify turning the observed zero-click chart dates into invented clicks. The dates are already aligned in Pacific time, and this historical interval is beyond the normal recent-data delay. Alternate Google surfaces, reloads/history, supplied headers, collection differences and unrecorded tests remain possible contributors; this investigation does not assign their individual shares.

The supported conclusion is **correct reporting within a limited attribution contract**, with no demonstrated need for a runtime patch or retrospective exclusion. Interpreting Google-referrer views as new Google Search clicks would be an interpretation error. The lack of retrospective test/source provenance is an observability limit, not proof that all traffic is genuine. Do not rewrite 79 to zero, mark all 79 as bots, tighten a network rule to force agreement with 11 clicks, or enable broad raw tracking on this evidence.
