## Diagnosis

At 16:18:47 UTC, the public endpoint returns the application's generic JSON 503 with `Cache-Control: no-store` and `Retry-After: 60`. A header-filtered tail joins a later request to Worker `caccaba0-f37a-4df1-b5ae-52d7d80febdb`: the D1 batch throws before any report decoding, and its meters are unavailable. This is not evidence of zero reads or quota exhaustion.

The binding names the expected existing analytics database. CLI D1 metadata returns authentication error 10000; an authenticated remote-development preview cannot start. Neither failure identifies the production SQL cause. After Goga signs into the in-app dashboard, the database inventory is present and a constant `SELECT 1 AS query_access_control` succeeds. Dashboard authorization remains separate from the failing CLI route.

An authenticated query-plan check produces **`VIEWs and/or subqueries nested too deep: SQLITE_ERROR`**. It uses the original report structure with literal dates and an empty referral-rule array, under `EXPLAIN QUERY PLAN`; it does not execute an observation report or reproduce the public referral selection. The public query is 78,225 SQL bytes. Its trace separately warns that SQL text exceeds the span attribute limit; that instrumentation warning alone does not establish the database error.

The pinned local runtime accepts the original report. A separately installed Workerd `1.20261108.1` rejects the same local query-plan fixture with the exact production message. [Upstream issue 16786](https://github.com/cloudflare/workers-sdk/issues/16786), opened November 8, reports flat CTE references being counted cumulatively as nesting; its reporter and automated triage preserve their own reproduction limits. Our matching runtime reproduction supports an engine regression explanation. The exact engine build serving production and the outage's start/duration remain unmeasured.
