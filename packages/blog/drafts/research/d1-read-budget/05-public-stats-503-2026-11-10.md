# Public stats rejected by the D1 engine

November 10, 2026 Pacific / UTC. Goga reports HTTP 503 from `/api/stats?range=7d&traffic=all`. This is a new availability investigation, separate from the completed [September read-budget repair](03-handoff.md). The governing cost decision is [ADR-0016.7](../../../../../docs/adr/0016.7-budget-d1-reads-and-cache-public-reports.md).

## Diagnosis

At 16:18:47 UTC, the public endpoint returns the application's generic JSON 503 with `Cache-Control: no-store` and `Retry-After: 60`. A header-filtered tail joins a later request to Worker `caccaba0-f37a-4df1-b5ae-52d7d80febdb`: the D1 batch throws before any report decoding, and its meters are unavailable. This is not evidence of zero reads or quota exhaustion.

The binding names the expected existing analytics database. CLI D1 metadata returns authentication error 10000; an authenticated remote-development preview cannot start. Neither failure identifies the production SQL cause. After Goga signs into the in-app dashboard, the database inventory is present and a constant `SELECT 1 AS query_access_control` succeeds. Dashboard authorization remains separate from the failing CLI route.

An authenticated query-plan check produces **`VIEWs and/or subqueries nested too deep: SQLITE_ERROR`**. It uses the original report structure with literal dates and an empty referral-rule array, under `EXPLAIN QUERY PLAN`; it does not execute an observation report or reproduce the public referral selection. The public query is 78,225 SQL bytes. Its trace separately warns that SQL text exceeds the span attribute limit; that instrumentation warning alone does not establish the database error.

The pinned local runtime accepts the original report. A separately installed Workerd `1.20261108.1` rejects the same local query-plan fixture with the exact production message. [Upstream issue 16786](https://github.com/cloudflare/workers-sdk/issues/16786), opened November 8, reports flat CTE references being counted cumulatively as nesting; its reporter and automated triage preserve their own reproduction limits. Our matching runtime reproduction supports an engine regression explanation. The exact engine build serving production and the outage's start/duration remain unmeasured.

## Repair and local acceptance

Diagnostic source `00c1af84` adds closed failure categories without retaining raw provider messages, SQL, parameters or reader values. Source-linked dashboard metadata shows build `c3ba020f-3ec3-4175-a52b-e9277449a21a` Ready/100%, and one diagnostic request executes Worker `f06aa5f2-d498-4f58-8c75-61d3d53425d0`, emitting `failure: sql`. The exact nesting message is subsequently established through the dashboard and local regression runtime.

Simpler single-statement shapes remain rejected by the regression runtime; a compound projection also hits D1's compound-SELECT limit. The implemented workaround partitions the unchanged section projections into six prepared statements in one transactional batch. They use the same clock, filters, owner exclusion and referral policy. Decoding still requires all complete, unique and reconciled sections. The all-time boundary appears exactly once. No schema, collection or historical row is changed. The cache namespace and calculation-log contract advance to `2026-11-10.1`.

The [native parity checker](../../../../analytics/scripts/check-stats-runtime.mjs) compares **33 selectors over 47 synthetic rows** with a bundled pre-repair implementation: all reports match exactly on the affected runtime. It covers four ranges, six traffic selections, path/agent/kind scopes, empty results, owners, referral exclusions and valid/unrecognized vendor evidence. The repaired native report emits six per-statement meters and zero writes. The first 47-row fixture costs **33,442 reads**. An earlier five-included-event fixture costs **7,435 before / 28,937 after**; this is a local cost increase, not a production forecast or saving.

The isolated release checkout passes **435 analytics tests, 432 site tests, workspace typechecks, a 44-post production build and Worker upload dry-run**. A separate concurrent primary-checkout run has 441 analytics tests; that includes another session's work and is not the isolated release count. Initial primary-checkout checks lacked site-audit dependency links; restored dependencies in the isolated checkout pass. Native negative controls verify closed failure labels. Malformed signer/count/partition tests now inject faults across every batch result rather than only the first statement.
