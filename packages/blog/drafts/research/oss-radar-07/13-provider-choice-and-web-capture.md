## What the options establish

| Route | Useful evidence | Limit |
|---|---|---|
| Perplexity web app under the existing membership | Exact question, visible answer, citation links, available mode/model label, capture time, source-support review, and subsequent Promptfoo import/export retention | Does not expose or verify the original API response, provider-side usage, billing, or retrieval trace |
| Another available AI service or local model | A real answer and whatever source evidence that interface supplies, with a tested provider/import path | A model naming URLs from memory is not evidence that it retrieved them; supplied-source evaluation is distinct from web discovery |
| Perplexity or another provider through an API | Request/response fields, exposed usage/status identifiers, automated collection, and live adapter/export behavior | Requires that provider's API access; fields and billing differ by route |
| OpenRouter | An optional gateway to a selected model provider; its adapter is the one exercised by the original fixture | The fixture finding belongs to that adapter/version and cannot be generalized to a different provider |

Perplexity's current [plan comparison](https://www.perplexity.ai/help-center/en/articles/11187416-which-perplexity-subscription-plan-is-right-for-you), updated September 2, describes web/app subscriptions and separately billed API access, with no complimentary API credits. Its [API billing page](https://www.perplexity.ai/help-center/en/articles/10354847-api-payment-and-billing), modified September 8, states that API access is a separate service and does not require Pro. These general documents do not establish this account's promotional entitlements or remaining allowance.

Promptfoo's [provider catalog](https://www.promptfoo.dev/docs/providers/) lists multiple hosted providers, local runtimes, custom scripts, and manual input. Its [Echo provider](https://www.promptfoo.dev/docs/providers/echo/) supports evaluation without generating a new answer. Current documentation explains the alternatives; it is not a claim that every listed current integration was tested in our pinned 0.122.2 experiment. Our already tested custom-provider interface supplies the narrow import mechanism we need.
