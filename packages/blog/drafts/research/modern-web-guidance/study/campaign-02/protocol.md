# Campaign 02: corrected execution, 54 new attempts

November 13, 2026, America/Los_Angeles. This replaces the first campaign as the primary controlled comparison. It adds 54 generation attempts, with the original 54 preserved as a diagnostic campaign. No original attempt is relabeled, silently replaced or deleted.

## Why a second campaign is necessary

The first campaign advertised the skill in all 18 skill-arm sessions, but only four runs had successful locally logged search/retrieve use. Inspecting failed command outputs showed real npm `ENOTCACHED` errors: login-shell startup bypassed the process-level pinned PATH. The custom wrapper also did not accept valid `--no` and `--no-install` runner options. A read-only skill-discovery preflight had not exercised command execution and missed these integration faults.

These are defects in this study's harness, not evidence that the product cannot retrieve its guides. That batch cannot cleanly answer the intended code-quality question with a working installed skill. Its original and corrected behavior scores, raw operational logs and generated artifacts remain preserved. The directly supplied arm's reproduced WebKit focus misses remain diagnostic evidence, but do not substitute for the complete repeated comparison.

## Changes frozen before the new attempts

- Preserve the original six task texts, fixture bytes, common project agreements, predetermined supplied guide text, model (`gpt-6.1-sol`), medium reasoning, five-minute cap and three-worker maximum.
- Run all three conditions again, three times per task: **54 new attempts**, rather than selecting replacements only for failures. The primary result is this complete second batch. No retries within this batch.
- Use a new fixed shuffle seed, `2026111302`, and new opaque IDs. All three conditions run under the same repaired execution environment in the same new observation window.
- Isolate zsh startup with a per-campaign `ZDOTDIR`, retain the actual user home for authentication, disable CLI shell snapshots, and explicitly inherit the controlled environment. Startup files restore the pinned tools and Node PATH for both login and non-login commands. These settings apply to all conditions.
- Resolve the exact frozen package in the offline launcher after accepting runner options before its package name. Log every invocation and its exit code, including failures. The launcher never downloads a package and never allows another package.
- Verify actual `node`, search and retrieval execution through an isolated Codex agent's normal command tool before freezing the batch. Successful skill advertisement alone is insufficient. Exercise both `--no-install` and `--no` forms.
- Use the already documented [v3 grader](../grade-v3.mjs) for the whole batch: corrected T06 checks from [amendment 01](../amendment-01-reveal-grading.md), corrected T01 close-event settling from [amendment 02](../amendment-02-dialog-settling.md), and unchanged checks elsewhere. Its positive/broken calibration must pass before generation. No outcome-driven grader changes are planned for this batch.

The parent [original protocol](../protocol.md) still supplies the task, condition, metric, privacy and evidence boundaries except where explicitly superseded here. Its no-regeneration rule remains true within each campaign. Repeating a full batch after identifying a harness failure is disclosed here rather than rewriting the original evidence.
