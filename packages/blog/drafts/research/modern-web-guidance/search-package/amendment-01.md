# Development amendment: native Pagefind and candidate reranking

November 14, 2026. The initial 33-case development run completed without failure. Its eight conditions remain unchanged. Reserved validation has not been opened. This amendment adds development conditions rather than replacing the initial matrix.

Observed development limits: record-level Pagefind returned no result for any of the ten full-sentence recollections; its native whole-page product has not yet been measured. MiniSearch exact and tolerant each selected the article for 9/10 recollections. Tolerance changed one selected-block hit to a miss. E5 plus tolerant MiniSearch demoted the correct OpenClaw article beyond third even though tolerant lexical retrieval placed it first. The original E5/BM25 hybrid found all ten selected recollection articles, while losing article hits on typos. None of these aggregate counts proves reader accuracy or complete labels.

Add the following, keeping queries and selected answer blocks fixed:

1. **Native whole-page Pagefind 1.6.0**, using the saved isolated HTML build of the same 46 source articles. Index `.post-content`, retain native headings/sections and default ranking, and run raw/prepared queries. Record article outcomes and native section/snippet identities separately. Do not invent the controlled source-block metric for its different snippet budget. Save every HTML hash. Current source files have changed for two unrelated articles since the old snapshot; use the retained build, not those current files.
2. **E5 plus exact MiniSearch**, with the existing fixed boosts and k=60 fusion. This isolates the tolerant lexical list's contribution to the observed hybrid regression.
3. **Retrieve and rerank**, using `Xenova/ms-marco-MiniLM-L-6-v2` at `a09144355adeed5f58c8ed011d209bf8ee5a1fec`, q8 CPU, Transformers.js 3.8.1, two intra-op/one inter-op threads. For each original passage/block index, take the union of the first 20 exact MiniSearch and first 20 E5 units, ordered lexical first with duplicate IDs removed. Rerank at most 40 query/unit pairs by raw single relevance logits. Use whole questions and each unit's existing title/heading/body text. Batch eight; cap paired input at 512 model tokens, explicitly recording truncation rather than claiming uncropped input. Group the resulting passage candidates and block excerpts with the existing common grouping. Record whether the known answer was in the candidate pool; the reranker cannot recover a discarded unit.

The reranker is a representative local cross-encoder pipeline, not a claim about the newest or best model. Its raw logits are not calibrated confidence. [Primary implementation recipe](https://huggingface.co/Xenova/ms-marco-MiniLM-L-6-v2), [retrieve/rerank architecture](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html). Model asset hashes, source/configuration and this amendment must be committed before new blog rankings. Non-blog fixture checks may validate the loader before that freeze. No public redistribution of this reranker's weights is part of this experiment.

Product selection will be documented before reserved runs. Expanded native/paired conditions are prompted by development evidence and are not described as initial predeclared baselines. Preserve both development receipts, preparation failures and all regressions. Do not tune per-case rewrites, labels or score cutoffs to make the table cleaner.
