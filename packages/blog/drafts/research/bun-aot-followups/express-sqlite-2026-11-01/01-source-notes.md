A bounded code search for both `node:sqlite` and bearer auth in Bun returned no result. A broader `node:sqlite` search found bindings and a microbenchmark, without identifying the chart's application. Absence from these searches does not establish that the benchmark source is unpublished.

[Bun's compatibility guide at the executable revision](https://github.com/oven-sh/bun/blob/3f3a9ff87cdccf3d32d7ec6b648c664eddaae840/docs/compiler/compatibility.mdx#code-from-strings) specifically names Fastify's serializer compiler replacement and standalone validators. This fixture uses a response schema without an input validation schema; the proposed control isolates serialization. The installed serializer implementation constructs a function from generated source. Package versions and the source hash will be retained with the experiment inputs. The generated serializer's schema behavior must not be silently treated as equivalent to unrestricted JSON output.

Pinned first-party checks: [Fastify 5.12.7 validation/serialization guide](https://github.com/fastify/fastify/blob/v5.12.7/docs/Reference/Validation-and-Serialization.md) identifies `fast-json-stringify` for response serialization; [version 7.2.0's constructor](https://github.com/fastify/fast-json-stringify/blob/v7.2.0/index.js#L585) uses `new Function`. These match the installed package versions. An earlier lookup at version 6.1.1 was superseded by the exact installed version and is not evidence for this fixture.

The [three-case serializer check](results/serializer-contract.json) passed under Node 24.14.1: fixture bytes match; extra root/nested fields appear only with plain JSON; a numeric string is a number under generated serialization and a string under JSON. This is a functional result, excluded from timings. Two setup attempts preceded it: a scratch-directory runtime resolved Node 20 without `node:sqlite`, then an explicit Node 24 invocation ran from the wrong database working directory. Copying the repository runtime pin into scratch and using the fixture's working directory resolved setup. Neither failure is a Bun/compiler result.

[fast-json-stringify 7.2.0 standalone documentation](https://github.com/fastify/fast-json-stringify/blob/v7.2.0/README.md#standalone) supports emitting a source module before deployment. The runtime package still supplies serializer helpers. Schemas using conditional validation may require `inlineValidators` to avoid regenerating Ajv functions; our simple fixture has no `anyOf`, `oneOf` or `if/then/else`. The prepared control must not be generalized to those schemas without testing their generation and runtime dependencies.
